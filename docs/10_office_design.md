> **11-10 바뀜 — 방 모눈**: 위 9구역 + ㅗ자 복도 그림은 처음 구상이다. 지금은 방 열한 개(구역 열 + 출하장)를 칸 한 벌(`themes/_shared/grid.json`)에 놓고 세 테마가 같은 자리를 쓴다 — 위 줄 소장실 · 자재창고 · 공구실 · 검사대 · 셔터(웹검색, 위 · 오른쪽 벽 모서리), 가운데 함바 · 작업대 · 서류실 · 도면실, 아래 출하 접수대 → 출하장 ① ② ③. 복도는 방이 아닌 칸(가로 두 줄 + 세로 한 줄). 한 칸 = 캐릭터 한 명, 이름표는 방 왼쪽 위 칸 고정. 배치 생각 · 잰 숫자는 [log:designer_grid_20261110.md]

> **11-17 출하 라인 고침**: ① Harbor 칸은 따로 알림을 받지 않고 Jenkins 행에서 미루어 그린다(`js/shipstate.js` `harborStatus`, 시험 `tests/js/shipstate.test.mjs`). 기준은 「그 빌드의 이미지가 실제로 올라갔는가」다. 「빌드·push」에서 실패하면 ✗, push 뒤 단계(매니페스트 태그 등)에서 실패하면 이미 올라갔으니 ✓, push 앞 단계(태그 · 시험)이거나 모르는 단계에서 실패하면 칸은 「기록 없음」이다(전에는 push 앞에서 실패해도 ✓였다). ② 이미지를 만들지 않는 현장(인프라, FOREMAN)은 `office.js` `NO_SHIP`에 까닭과 함께 둔다. FOREMAN 방은 전에 세 칸이 늘 「기록 없음」이었고 지금은 인프라 방처럼 「… 없음」 이름표만 있다. ③ 현황판의 🔥 · ✕ 표시(`siteState`)는 단계 실패뿐 아니라 웹훅 끊김 의심과 빌드 알림 없음도 켠다. 조용한 고장을 알리려는 뜻이라 그대로 둔다 [log:foreman-6_designer_code_oddities_20261117.md]

세션의 Claude Code 창에 결정 창(권한 · 계획 승인 · 안내 · 고르기 창)이 떠 있으면 FOREMAN에서 볼 수 없어, 11-14 사용자가 VNC로 들어가 Esc로 닫았다. 패널은 글만 넣을 수 있었다.

- **세션 패널 탭은 셋 — 「대화」 · 「활동」 · 「세션 정리」**(`opanel.js` `TABS`), 그 오른쪽 끝에 **[세션 화면 ↗] 단추**. 「세션 정리」는 전 「세션」 탭(정보 · 넘기기 · 합치기 카드 · 끝내기 · 승인 기록). 화면 글 · 알림 글의 「세션」 탭 · [세션] 탭도 모두 바꿨다
- **「세션 정리」 탭 평소 모습(11-14 사용자 「평소에 너무 길다」)** [log:coder_sesstab_short_20261114.md] — 보이는 것만 줄였다(누르면 하는 일은 그대로)
  - 맨 위 「프로젝트 · 서버 경로」 줄은 없다(사람이 서버 경로를 볼 일이 없다). 작업 중이면 「▶ 작업 중 · N분째」 줄만
  - [더보기]는 버튼 줄 옆으로 펼쳐지므로 **접힘 「더보기 ▶」, 펼침 「접기 ◀」**(위아래로 펼치는 접는 칸 · 활동 줄 ▸▾ · 모델 고르기 ▾ · 셸 ▲▼은 그대로). 호버는 실제로 펼쳐지는 버튼만 적는다 — 「새 세션으로 옮기기」 쪽은 「요약 관련 기능입니다(지금 요약, 새 세션만 띄우기[, 끝난 세션이면 압축 요약으로 만들기])」, 「세션」 쪽은 「세션 조작입니다(작업 중단, 일시정지, 다시 시작)」
  - 「넘겨받은 글: 세션 N에서 · 4시간 전」(보낸 세션 제목은 빼고 번호만)
  - 「읽을 곳」의 「(자동: …)」는 같은 이름을 하나로 줄인다. 서버(`bridge/pointers.py` `reads`)는 맨 위 CLAUDE.md를 가리키는 읽을 곳마다(절이 달라도) 경로를 하나씩 주므로 화면(`handoff.js` `autoNote`)에서 줄이고, 서로 다른 것이 셋을 넘으면 「첫 것 외 N개」(전부는 호버). 자동으로 세는 것은 이 저장소 맨 위 CLAUDE.md 하나뿐이라(원본 · worktree는 같은 열쇠) 경로로 가를 일이 없다
  - **「옮기기 전 정리」는 평소 두 줄**: `[압축으로 잊은 것 찾기]  아직 없습니다` · `[대화에서만 정한 것 문서에 적기]  아직 없습니다  같이 넣을 것(N개) ▾`. 소제목은 「옮기기 전 정리」만 남기고 옆 설명문(「잊은 것 · 대화 결정을 문서에」)은 뺐다(11-14 사용자 — 펼친 두 버튼 이름이 같은 말을 해 겹쳤다). 설명은 각 버튼 호버(「이름 — 설명」)에 있다. 「세션 정보 · 토큰」의 모델 줄은 「모델 [Opus 5.5]」 배지만 보인다(「· 고른 것 opus」는 화면에서 뺐다. 배지가 실제로 도는 모델이고 고른 값은 세션을 만들 때 적은 것이라 같은 것을 두 번 보였다. 값 `model_req`는 서버에 그대로 있다). 두 버튼 폭을 맞춰 상태가 같은 세로줄에 선다(`panel.css` `.docs-run`). 찾기 결과(사라짐 · 약해짐 · 잃은 것 목록) · 문서 후보 목록 · 진행 표시는 결과가 생기면 그 줄 밑에 전처럼 펼쳐진다. 두 번째 버튼이 하는 일은 전 [문서 후보 묻기]와 같다(세션이 후보만 내고 파일은 고치지 않음)
  - **(11-14 밤) 「옮기기 전 정리」는 늘 접은 채로 시작한다** [log:foreman-3_docs_fold_20261114.md] — 위 ③ 고르기에서 고른 것이 그대로 들어가고, 여기는 글을 고칠 때만 쓰는 곳이라서다(사용자). 전에는 목록 승인 · 쓰기 확인 · 도는 점검이 있으면 저절로 펼쳤다. 사람이 펼치거나 닫으면 그대로(`handoff.js` `docsOpen`). 보이는 것만 바꿨고 누르면 하는 일 · API는 그대로다
    - 머리 줄: `▶ 옮기기 전 정리   승인 N개  고칠 수 있음`(승인 수는 지금 고른 상태 그대로 센다. 「고칠 수 있음」은 목록을 받았거나 확인에 실패해 아직 고칠 수 있을 때만). 확인 실패 · 도는 중 · 잊은 것 찾기 실패 · 일부만 끝 · 잃은 것 N은 그 옆에 노랑으로 남는다. 가운뎃점 대신 칸 사이를 띄운다
    - 펼치면 맨 위 설명 한 줄 「고치고 싶은 곳을 고쳐주세요. 고치지 않아도 위에서 고른 대로 들어갑니다.」(`promote.js` `DOCS_GUIDE`). 줄 가운데 있던 「고치고 승인해 주세요」는 여기로 올라갔다
    - 잊은 것 찾기 줄: `[압축으로 잊은 것 찾기]  찾을 것 없음  1분 전  [Sonnet 5.5]` — 설명 줄 「이 세션은 압축된 적이 없어 …」은 「찾을 것 없음」 호버로, 모델은 날 이름(`claude-sonnet-5-5`) 대신 패널 모델 칩과 같은 배지(`render.js` `pickedLabel` · `pickedFamily`)
    - 문서 적기 줄: `[대화에서만 정한 것 문서에 적기]  18초 전  [같이 넣을 것(N개) ▾]` — 무엇을 같이 넣었는지는 시각 호버로. 「목록 기다리는 중…」 · 「실패」 · 「썼습니다」 같은 상태는 그대로 보인다
    - **문서 후보 항목은 한 줄로 접는다**: `[승인 ▾] #1 기준  docs/style_guide.md  「4-1. 화면 글」 ▶`. 번호부터 끝까지가 접기 단추라 누르면 펼쳐(▼) 어디로 · 절 입력 칸, 글 칸, 원문, 왜 거기가 나온다. 상태 고르기는 접기 단추 밖이라 펼치지 않고 바꾼다. 틀린 목적지(✗)는 접힌 줄에도 보인다. 펼친 항목은 `handoff.js` `promOpen`이 들고 있어 15초 다시 그리기에도 풀리지 않는다. 화살표는 사용자 예시대로 ▶ · ▼(style_guide의 위아래 ▲▼ 약속과 다르다, log에 적음)
    - 옮기기 흐름 쪽: 볼 것 없음 줄은 「잊은 것 없음」, ③ 고르기 안내는 「문서에 넣을 것을 골라주세요. 사용자가 고르는 곳은 여기 하나입니다.」 「고른 것만 세션이 문서에 쓰고 커밋한 뒤 이어서 옮깁니다.」, 다 옮긴 뒤 초록 글은 「새 세션으로 옮겼습니다. 새 캐릭터를 확인해주세요.」
  - **(11-14 저녁) 작업방(worktree)이 있는 세션은 「새 세션으로 옮기기」 묶음이 없다** — 제목 · 버튼 · [더보기] · 「작업 중이라 지금은 못 합니다」 · 「아직 요약이 없습니다」 · 요약 카드 · 지난 요약을 함께 뺐다(코더 세션에서 한 번도 쓴 적 없음, 사용자). 가르는 기준은 역할이 아니라 `controls.worktree`가 있는가(`handoff.js` `showMove`) — 디자이너 · 서기 worktree 세션도 같다. 넘겨받은 글 · 읽을 곳 · 누른 뒤 결과 글은 머리 없는 칸으로 남긴다. 이미 도는 옮기기 흐름이 있으면 보인다. 관리자(worktree 없음)는 그대로. 서버 기능 · 패널 머리 · 대화 탭의 [새 세션으로 옮기기]는 그대로다 [log:designer_sesstab_end_20261114.md]

  - **크기 맞추기**(보기 스크립트): 붙을 때 그 창을 `window-size manual`로 묶고(표시 `@foreman_ccview`) 자기 그룹 세션에 `client-resized` 훅 `run-shell -C 'resize-window -t <창> -x #{client_width} -y #{client_height}'`을 건다 — 붙을 때 · 띄운 창 크기를 바꿀 때 Claude Code 창이 손님(xterm) 크기를 따른다. 그룹 세션은 상태줄을 꺼 손님 크기 = 창 크기. `resize-window` 혼자는 `#{…}`를 풀지 않아 `run-shell -C`로 감쌌다. 묶었으니 보는 동안 VNC 등 다른 손님이 붙어도 크기가 흔들리지 않는다
  - **머리줄 「Claude Code 창 WxH」는 iframe 안 xterm의 열 · 줄 수를 바로 읽는다**(11-14 사용자 — 열면 80×24가 5초쯤 가다 바뀌었다) [log:coder_ccsize_20261114.md]. 서버 확인(`GET /api/terminal/cc`)은 5초마다라 느렸다. 상태줄을 꺼 손님 크기 = Claude Code 창 크기라 xterm 열 · 줄 = 창 크기(서버 값과 같음을 대조). 붙기 전에는 숫자를 비우고(옛 80×24가 안 보이게), 붙은 뒤 xterm `onResize`로 바뀔 때마다 · 모서리를 놓은 뒤 바로 그리고, 1.2초 뒤 서버 값으로 한 번 확인해 다르면 서버 값이 이긴다(`ccscreen.js` `sizeSoon`). 5초 확인은 죽음 · 까닭용으로 그대로
  - **둘이 같은 세션을 띄우면 나중에 붙은 쪽 크기**(사용자 결정 — 혼자 써서 거의 없음). 나중 것이 먼저 나가면 남은 보기 크기로 다시 맞춘다. **마지막 보기가 나가면 80×24로 되돌리고** `window-size` · 표시를 푼다. 80×24는 `bridge/terminal.py` `CC_REST_SIZE` 한 곳 — ttyd 고정 인자로 스크립트에 넘긴다. 죽어서 못 되돌린 것은 브리지 `release_cc_windows`가 같게 한다(브리지 시작 · 세션 화면 연결마다)
  - 창에 사람이 정한 `window-size`(표시 없음)가 있으면 크기를 맞추지도 되돌리지도 않고 보기만 한다(`attach -f ignore-size` — 크기 계산에도 끼지 않음)
  - 멈춰 둔(Ctrl+Z) 세션 · 끝난 세션 · tmux 밖 세션 · 다른 tmux 서버는 열지 않고 창 안에 까닭을 띄운다. 열려 있는 동안 5초마다 `GET /api/terminal/cc/{sid}`로 다시 물어 끝남 · 세션 화면 ttyd 꺼짐을 까닭으로 띄운다(조용히 빈 화면이 되지 않게). [다시 붙기]
  - 기록은 열고 닫은 것만 `session_action` `ccview-open` · `ccview-close`(그 세션, 어느 tmux 창 · 크기 · 탭 · 본 초). 키 하나하나는 남기지 않는다. 사람이 세션 화면에서 친 글은 붙여넣기 전 검사를 거치지 않는다(사용자가 괜찮다고 함)
  - **브리지가 글을 넣을 때 입력 칸에 사람이 치던 글이 있으면 넣지 않는다**(`inject.typed_in_box` — 11-14 전에는 거르지 않았다). 까닭 「입력 칸에 사람이 치던 글이 있어 넣지 않았습니다. 그 세션 대화창(세션 화면)을 확인해 주세요」. 빈 칸의 흐린 안내 · 제안 글(SGR 2 · 회색)과 커서 칸은 친 글로 보지 않는다
- **화면 아래 것은 「셸」**(전 「터미널」) — 여닫는 단추 「▲ 셸」, 고르는 메뉴 「FOREMAN 셸」 · 「런슈즈 셸」…, iframe 이름 · ttyd 제목도. 「대화창」 약속(`docs/style_guide.md` 4-1)은 그대로
- **[셸 비우기]**(전 [새 셸]) — 셸을 새로 띄우지 않고 지금 셸의 화면 · 스크롤백을 비운다(`POST /api/terminal/clear`, `TerminalManager.clear`). 셸이 입력을 기다리면 readline 화면 지우기(C-l, 기록에 `clear`가 남지 않음) + tmux `clear-history`, 친 글이 있으면 먼저 묻고 지운다, 명령이 돌고 있으면 먼저 묻고 그 명령에는 아무것도 넣지 않고 tmux 쪽 화면(`send-keys -R`)과 스크롤백만 지운다. 셸 설정이 바뀐 옛 셸 알림은 「셸에서 exit를 친 뒤 셸을 다시 열면 새 설정을 읽습니다」로 바꿨다(새 셸을 여는 단추는 없다 — `POST /api/terminal/respawn`은 남겨 두었다)

### 타일 크기 · 화풍

- **16×16으로 간다.** 거의 모든 CC0 후보가 16이다. 32(DCSS · 일부 OGA)는 섞지 않는다 — 2배로 키운 16 옆에 32가 서면 픽셀 크기가 달라 바로 티가 난다
- **화풍은 세 무리로 갈린다**: ① Kenney Roguelike(테두리 약함, 음영) ② Kenney Tiny(테두리 없는 단색) ③ Ninja Adventure · Puny · MetroCity(굵은 외곽선 치비). **한 테마 안에서 무리를 섞지 않는다**. OGA factory tileset은 ①에 맞춰 그렸다고 한다
- 빠진 것을 직접 그릴 때는 그 테마의 팔레트(theme.json `palette`)로 — 지금 도형 렌더러가 이미 그 방식이라 이어진다

### 고를 것(사용자 결정) — ⚠ 아래 "기준을 넓혀 다시"가 이 절을 대신한다

1. **캐릭터**: (가) Kenney Roguelike 조립식 — 역할 색은 쉽고, 걷기 · 앉기는 엔진 흉내 / (나) Ninja Adventure — 진짜 4방향 걷기, 대신 역할 색은 팔레트 바꾸기, 치비 외곽선 화풍 / (다) 현대 느낌이 꼭 필요하면 MetroCity(달리기만)
2. **오피스 테마의 구멍**: (가) 직접 그리기(랙 · 모니터 벽 · 유리벽 · 커피머신 — 단순한 것 위주) / (나) 유료 CC0 팩 구입(확인 후) / (다) 오피스를 뒤로 미루고 덮임이 높은 테마부터
3. **동작**: 앉기 · 눕기 · 들고 있기는 엔진 흉내로 시작하고, 눈에 띄게 어색한 것만 몇 장 직접 그린다(CC0라 덧그림 가능)
