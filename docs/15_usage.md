> 상태: 11-08 사용자 승인(설계 그대로). ✓ 1. `claude -p` 사용량 기록. ✓ 2. 집계 · 환산 · 창 + `/usage` 주기 읽기 · `/api/usage`(관찰 수집은 5절 고친 대로). ✓ 4. 페이지 · 머리 칩 · 캐릭터 열기 · 경고등 · 알림(11-08). ✓ 칩 소진 예상 · What's contributing 호버 · 추가 사용 판정 · 막힘 90% 알림(11-09, 6 · 6-2절). ✗ 사람 입력 · 가중치 맞추기

세션 · 모델 · 프로젝트 · 시간대별 토큰을 보이고, 구독 한도(5시간 · 주간)를 "지금 몇 %"로 추정한다. Anthropic은 한도를 토큰으로 공개하지 않으므로, 사람이나 화면이 본 %와 그 구간에 FOREMAN이 본 사용량으로 거꾸로 구한다 — **한도가 아니라 하한**이다.

## 1. 재료

| 무엇 | 어디 | 빠진 것 |
|---|---|---|
| CC 세션 응답마다 모델 · 입력 · 출력 · 캐시 읽기 · 캐시 쓰기 · 시각 | `message` 표(트랜스크립트 적재) | 서브에이전트 출력은 응답 시작 때 값(`output_tokens_reliable`) |
| 인계 요약(`claude -p --resume`) | 그 세션 트랜스크립트에 이어 써져 `message`에 들어온다 | — |
| **디스패처 · 압축 손실 점검(`claude -p --no-session-persistence`)** | **없었다** → `usage_extra`(0026). `--output-format json`의 `modelUsage`(모델별 토큰 + CC가 정가로 계산한 `costUSD`)를 그대로 | — |
| 웹 · 앱 · 다른 PC · CC 안쪽 호출(제목 짓기 등) | 볼 수 없다 | 역산 값이 하한인 까닭 |

## 2. 환산 — API 정가 비율(사용자 동의, 관찰이 쌓이면 고친다)

한도가 토큰 종류 · 모델을 어떻게 치는지는 모른다. 계산이 많이 드는 만큼 친다고 보고 API 정가로 환산해 한 줄로 더한다(`config/usage.toml`).

| 100만 토큰당 | 입력 | 출력 | 캐시 읽기 | 캐시 쓰기(1시간) |
|---|---|---|---|---|
| Opus 5.5 | $4 | $20 | $0.20 | $8 |
| Sonnet 5.5 | $2 | $10 | $0.20 | $4 |
| Haiku 5.5 | $0.10 | $0.50 | $0.01 | $0.20 |

- 캐시 쓰기는 1시간짜리다 — CC가 `ephemeral_1h`로 쓴다(`claude -p` JSON에서 확인, Haiku 정가 계산이 `costUSD`와 맞는다). 5분짜리(1.25배)가 아니다
- 11-01 22:00 ~ 11-08 08:10(KST, 주간 88% 관찰) FOREMAN이 본 양 ≈ $838 — 캐시 읽기가 약 57%(23.9억 토큰), 거의 전부 Opus → 주간 한도 ≥ 약 $950

## 3. 한도 · 창

| 한도 | 창 | 리셋 |
|---|---|---|
| 5시간 | 창의 첫 메시지부터 5시간(공식 설명). FOREMAN이 자기 메시지 시각으로 창을 이어 붙여 계산 | 화면 · 사람이 본 리셋 시각으로 바로잡는다 — FOREMAN 밖 사용이 창을 먼저 열 수 있다(10-23 사례: 20:16 첫 입력 + 5시간 = 01:16, 화면 "1:20am", 실제 01:21:30에 풀림) |
| 주간(종류는 사용자가 CC에서 확인해 알려 줌) | 리셋 시각부터 7일 | 사람이 알려 준 요일 · 시각 |

## 4. 역산

- 관찰 하나 = (한도, %, 시각, 리셋 시각?, 출처 사람 · 화면). 그 시각의 창에서 FOREMAN이 본 환산액 U → **하한 L ≥ U / %**
- 여러 관찰 — 높은 %에 무게(정수 % 반올림 오차가 작다). 역산 하한끼리 10% 안으로 모이면 "추정 안정"
- 지금 % = 지금 창의 U / L, 범위(관찰 하한들의 최소 · 최대)와 근거 관찰 수를 함께. "이 속도면 언제 100%"(최근 1시간 속도)
- 관찰 5번 이상, 캐시 비중이 다른 구간이 있으면 캐시 읽기 가중치를 맞춘다(모이지 않는 것이 그 신호)

## 6-2. 추가 사용(크레딧) — 막힘 · 이어 씀 · 모름 (11-09)

한도(5시간 · 주간)에 닿은 뒤 크레딧으로 이어 쓸 수 있는지. 막혀 있으면 한도 100%가 곧 세션 멈춤이다 — 조용한 고장. [log:tips_and_credit_signal_20261109.md]

- **읽을 길이 없다**: `claude -p "/usage"`에도, 대화형 /usage에도 잔액 · 월 한도 칸이 없다(대화형은 "Usage credits are off"). 값은 claude.ai 설정 > 사용량(공개 API 없음)에만 [log:screen_argocd_read_20261109.md] [log:credits_and_middle_number_20261109.md]
- **판정은 CC가 남긴 한도 글로**(`usage.credit_signal`). CC는 한도에 닿으면 모델 응답 대신 오류 글을 남긴다(트랜스크립트 `isApiErrorMessage`, `error: rate_limit`, 모델 `<synthetic>` — 적재기는 event type `error`). 이번 달(KST) **마지막 한도 글 하나**로:

  | 글 | 판정 | 칩 |
  |---|---|---|
  | "You've hit your monthly spend limit · …" | **막힘**(why `spend`) | "⛔ 추가 사용 막힘 · 오늘 13:55"(빨강) |
  | "You've hit your 5-hour limit · resets …" 뒤, 그 리셋 전에 실제 응답(`<synthetic>` 아님)이 1분 뒤로 이어짐 | **이어 씀** | "추가 사용으로 이어 씀 · 시각"(노랑) |
  | 그냥 한도 글 뒤 리셋까지 실제 응답 없음 | **막힘**(why `limit`) | "⛔ 추가 사용 막힘 · 시각" |
  | 이번 달 한도 글 없음 | **모름** | "추가 사용 확인 필요" |

  - 같은 때 StopFailure 훅 이벤트(글 없음)도 `error`로 30ms 뒤에 들어온다 — **글 있는 행만** 본다(처음엔 훅 행을 골라 16:36 ~ 16:39 화면에 "이어 씀"이 잘못 떴다)
  - 금액(잔액 · 월 한도 · 쓴 돈)은 CC 글에 없다. 칩에 근거 시각, 호버에 CC 글 원문. "한도를 올렸다면 다음에 한도에 닿을 때 다시 판정합니다"
  - 11-09 실제: 13:10 5시간 한도 → 13:13 ~ 13:32 응답 이어짐 → 13:32 · 13:55 monthly spend limit
- **사람이 넣은 값 `config/usage.toml [credits]`**(`balance_usd` · `monthly_cap_usd` · `monthly_used_usd` · `auto_reload` · `as_of`)은 **판정에 쓰지 않는다** — 이번 달 CC 한도 글이 없을 때(모름)만 막힘 판정에 쓰고("⛔ 추가 사용 막힘(넣은 값)"), 그 밖에는 호버의 금액 참고로만(`usage.credit_view`). ~~값으로 막힘 · 갱신 필요를 판정~~(11-09 바뀜 — 사용자: 직접 넣은 값은 조용히 틀린다)
  - **넣은 지 3일(`MANUAL_DAYS`)이 지나거나 달이 바뀌면 숫자를 감춘다**(`credit_status` `stale`) — 월 사용액은 쓰는 날마다 늘고 충전 · 한도는 아무 때나 바뀐다. 감추면 막힘도 믿지 않는다. 고치면 브리지를 다시 띄운다

## 6-1. 인계 요약은 언제 비용을 아끼나 (11-08)

맥락 크기 알림(300k · 500k, `bridge/compactwatch.py`)을 보고 [인계 요약 받기]를 누르기 전에 본다.

- live 요약은 **그 세션의 한 턴**이다 — 지금 맥락 전체를 그 세션 모델로 한 번 더 읽는다
- **일하는 중인 세션**(캐시가 따뜻함): 캐시 읽기 값으로 읽혀 싸다 → 요약해 넘기는 편이 이후 응답마다 아낀다
- **쉬어서 캐시가 식은 세션**: 맥락 전체를 캐시 쓰기로 다시 올린다(170 펫퍼민트 350k Opus면 약 $2.8). 비용을 아끼려면 **끝내기만** 하고, 그 일을 다시 할 때 새 세션에서 정한다
- 11-08 170은 이 이유로 요약 없이 끝냈다(사용자 결정, 주간 93%)
