# 13 시연 사진 · 녹화 — 포트폴리오에 "움직이는 화면"을 (설계, 2026-11-06)

> 상태: 13a ~ 13e 만듦(같은 날) — 결과 `log/stage13_demo_capture_result.md`. 사용자 결정: 연출 표시 캡션 한 줄 + 00 한 줄, 실제 기록 재생 우선, **웬만하면 GIF**(PPT에 옮김 — 실측 결과 7개 모두 GIF, 128색 · 원래 크기)

> 이 문서의 글 번호(00 ~ 09)는 옛 10편 기준이다. 지금 포트폴리오 편 목록은 `portfolio/` 폴더 파일이 정한다(`docs/12_scribe.md` 7절). 서기 일감 지시문이 이 방식을 그대로 쓰라고 한다(편마다 사진 한 장 이상, 움직임은 영상)

## 1. 왜

- 포트폴리오 10편 중 사진이 있는 글은 00 · 01 둘(사진 3장)뿐이다. 다른 프로젝트는 시연을 보이는데 이건 글만 있다(사용자, 11-06)
- 이 프로젝트의 핵심은 **캐릭터가 움직여 상태를 말하는 것**인데 정지 사진으로는 안 보인다

## 2. 확인한 사실 (11-06)

| 항목 | 결과 |
|---|---|
| 연속 캡처 | `tools/screen.py`의 CDP로 `Page.captureScreenshot`(JPEG, clip)를 초당 10장 — 1366×768 방 부분 6초 = 60장 실제로 찍힘. 캔버스 애니메이션은 헤드리스에서도 돈다 |
| WebM | Playwright가 받아 둔 ffmpeg(`~/.cache/ms-playwright/ffmpeg-1013`) — **VP9 · WebM만**, 입력은 JPEG를 `image2pipe -c:v mjpeg -i pipe:0`로만(파일 묶음 · PNG 입력 · H.264 · mp4 · GIF 없음) |
| GIF | 시스템 `python3`의 PIL 12.3(`.venv`에는 없다) — 128색 · 디더 없음 |
| 크기(움직임 적은 6초, 890×570) | WebM(crf 36) **63KB** · GIF 890px **369KB** · 640px **249KB** |
| Notion | 시험 페이지에 GIF → 그림 블록, WebM → 동영상 블록 **둘 다 올라감**(확인 뒤 휴지통) |
| Notion 파일 한도 | `GET /v1/users/me`의 `bot.workspace_limits.max_file_upload_size_in_bytes` = **5,242,880(5MB)** — 무료 요금제 한도와 같다. 파일 하나가 5MB를 넘으면 안 된다 |
| mp4 | ffmpeg를 새로 깔지 않는다(사용자 결정) → mp4는 쓰지 않는다 |

## 3. 연출 표시 — 밝힌다 (권함)

**의견:** 밝히는 게 맞다. 다만 크게가 아니라 **캡션 한 줄**로.
- 사용자 말대로 영상이 보이는 것은 "화면이 이렇게 움직인다"이고, 제품 데모는 대개 따로 밝히지 않는다
- 그래도 이 포트폴리오는 사정이 다르다
  - 글 전체가 **근거 표시 · 기계 확인 · 실제 숫자**로 서 있다(근거 틀림 0이 자랑거리). 그 옆에 대본 영상이 아무 말 없이 놓이면, 읽는 사람이 영상 속 세션 이름 · 시각 · 숫자까지 실제 기록으로 읽는다
  - 이 프로젝트의 주제가 "조용히 틀어진 화면을 없애는 것"이다. 화면이 실제와 다른데 표시가 없으면 그 반대가 된다
  - 채용 담당 · 엔지니어는 "연출이었다"를 나중에 알게 되는 쪽을 가장 나쁘게 본다. 미리 한 줄 쓰면 손해가 없다
- 밝히는 방법
  - 영상 캡션 끝에 **〔시연 재생〕**(대본) 또는 **〔실제 기록 재생 · ×8〕**(DB 이벤트를 빠르게 재생) — 정지 사진은 **〔실제 화면 · 11-06〕**
  - 00 「한눈에」 맨 아래 한 줄: "움직이는 화면은 실제 화면 코드에 시연용 이벤트를 흘려 녹화했다. 세션 이름 · 숫자는 시연용이다(실제 기록 재생은 그렇게 표시)"
  - 영상 안 화면에는 아무것도 덧씌우지 않는다(화면 자체가 보여야 할 것)
- 더 나은 길(권함): 가능한 장면은 **실제 기록을 재생**한다 — DB `event`에 실제 세션의 도구 순서가 있다. 이름만 시연용으로 바꾸고 순서 · 간격(빠르게)은 실제 그대로 흘리면 "이렇게 움직였다"가 사실이 된다. 승인도 실제 `approval` 행이 있다. 대본은 실제 기록으로 안 되는 장면(테마 전환 같은 것은 연출이 아니라 실제 조작, 서브에이전트 소환 · 사라짐은 기록 재생 가능)에만

## 4. 구조

### 4-1. 시연 모드(화면 쪽)

- `/?theme=office&demo=<대본 이름>` — 이때 화면은 **WS · 스냅샷을 열지 않고**(실제 데이터가 섞이지 않게, 몇 초마다 오는 스냅샷이 꾸민 상태를 덮어쓰지 않게) `static/demo/<이름>.json`을 읽는다
- 대본 형식
  ```json
  {"snapshot": {"projects": [...], "approvals": [], "pipeline": {...}},   // /api/dashboard와 같은 모양 — 시연용 이름
   "steps": [{"at": 0, "msg": {"type": "event", "event": {...}}},        // store.apply()에 그대로 넣는 WS 메시지
             {"at": 1500, "js": "window.office.go('foreman')"},          // 화면 조작(테마 링크 · 패널 열기 · 버튼 누르기)
             {"at": 9000, "end": true}]}
  ```
- 화면에는 진입점 하나만 연다: `window.office.demo.run(name)` — `store.loadSnapshotFrom(json)` + 시각에 맞춰 `store.apply(msg)`. 새 그리기 코드는 없다(실제 화면 코드 그대로)
- `tools/demo_from_db.py` — 실제 기록 재생 대본 만들기: 세션 id · 시각 구간 → 그 사이 `event`(tool_use · subagent_start/stop · approval_req …)를 메시지로, 간격을 ×N으로 줄이고, 세션 이름 · 프롬프트 · 경로는 시연용으로 바꾼다(실제 글은 대본에 남기지 않는다)

### 4-2. 녹화(`tools/screen.py --record`)

```
.venv/bin/python tools/screen.py --record wander --themes magic --sizes 1366x768 \
    --clip 60,135,890,570 --fps 10 --secs 10 --as webm,gif --gif-width 640
```
- 시연 모드 주소로 띄우고 → 대본 시작 → `Page.captureScreenshot`(JPEG 85, clip)를 fps에 맞춰 → 프레임 폴더
- WebM: Playwright ffmpeg로 `image2pipe`(crf 36, VP9). GIF: 시스템 `python3 -I`로 PIL 변환 스크립트(`tools/frames_to_gif.py` — 128색, 디더 없음, 폭 줄이기 NEAREST, 같은 프레임 묶기)
- **GIF 바뀐 곳만 담기(11-19)**: `--delta`(`screen.py --record`도 같은 이름으로 받는다)를 주면 보이는 화면과 거의 같은 점(R, G, B 차의 합이 문턱 아래)을 투명으로 두고 바뀐 곳만 담는다. 보이는 화면은 색을 줄인 그림이 아니라 원본 RGB로 들고 견준다(줄인 색으로 견주면 색 오차가 문턱에 더해져 투명이 줄고 GIF가 커진다, `tests/test_frames_to_gif.py`가 지킨다). 마법학교 돌바닥 무늬는 JPEG 잡음이 점마다 달라 같은 설정에서 오피스보다 GIF가 두 배쯤 크기 때문이다(디자이너 573이 임시 스크립트로 쓰던 것을 저장소 도구로 옮겼다 [log:foreman-5_gif_delta_20261119.md]). `--delta-threshold N`은 기본 120이고, 글씨가 바뀌는 장면은 잔상이 남아 24쯤으로 낮춘다. 투명 칸 하나를 쓰므로 색은 최대 255, 문턱은 255 안에서만 뜻이 있다. 옵션이 없으면 전과 같다
- 끝에 크기를 재서 **5MB를 넘으면 실패**(종료 코드 1, 무엇을 줄이라는 안내) — 게시에서 처음 알면 늦다
- 결과는 `portfolio/img/<글>_<무엇>.webm|gif`(사진과 같은 자리)

### 4-3. 게시(Notion)

- 마크다운: 사진과 같은 `![설명](img/x.gif)` — `.gif`는 그림 블록, `.webm`은 **동영상 블록**(`md_to_blocks`가 확장자로 가른다)
- `git_bytes`가 받는 확장자에 `.webm` 추가, 지문(`content_digest`)에 그대로 포함
- 올리기 전에 `workspace_limits`로 크기를 본다 — 넘으면 Notion에 보내지 않고 거부 사유(`~습니다`)로 알린다(조용히 빠지지 않게)

## 5. GIF와 WebM 가르기

| | GIF | WebM |
|---|---|---|
| Notion에서 | 그림 블록 — **글 안에서 저절로 돈다**(반복) | 동영상 블록 — **눌러야 재생** |
| 크기 | 크다(6초 250 ~ 370KB, 움직임 많으면 몇 배) | 작다(6초 63KB) |
| 화질 | 128색 — 픽셀 그림이라 거의 손실 없음 | 좋음 |
| 쓰는 곳 | **8초 이하 · 한 가지 동작 · 부분 확대** | **8초 넘는 이야기 · 패널까지 같이** |

## 9. 위험 · 정할 것

- **정할 것:** 연출 표시(3장 — 권함은 캡션 한 줄 + 00 한 줄), 실제 기록 재생을 쓸지(권함), 영상 목록 중 뺄 것
- 움직임이 많은 GIF는 크기를 미리 알 수 없다 — 녹화가 5MB · 예산을 넘으면 실패시키고 폭 · fps를 줄여 다시
- 시연 모드가 실제 화면 코드를 그대로 쓰므로, 화면을 고치면 영상도 다시 찍어야 할 수 있다(대본 · 명령이 남으니 다시 찍기는 한 줄)
- Notion WebM은 눌러야 재생된다 — 첫인상은 GIF가 맡는다(00 맨 위 V4 GIF)
