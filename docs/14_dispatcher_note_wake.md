# 14 — 감독실 캐릭터 · 디스패처 노트 · 자동 기상 2단계 (설계, 2026-11-08)

> 상태: 11-08 ✓ 이름 바꾸기 · 노트 · 2단계(실패 → 계획 → [시작]?) · 캐릭터 클릭. △ 노트는 실제 디스패치에서 아직 한 줄도 쌓이지 않았다. ✗ 3단계(묻지 않고 띄우기)는 2단계를 써 본 뒤 정한다(사용자)

디스패처는 여전히 부를 때만 `claude -p` 한 번이다. 화면의 감독실 캐릭터는 그 디스패처의 얼굴이고, 프로젝트마다 크기를 정한 노트를 들고 있으며, 실패가 오면 스스로 계획을 세워 사람에게 [시작]?을 묻는다.

## 1. 이름

| 무엇 | 이름 |
|---|---|
| 프로젝트 | **FOREMAN**(영문). 한글 "포먼"은 화면에 쓰지 않는다. 텔레그램 접두어 `[FOREMAN]` |
| 감독실 캐릭터 | 테마마다 — 오피스 **팀장** · 마법학교 **교장** · 현장 **소장** · 기본 **디스패처**(`theme.json`의 `foreman.name`). 현장의 감독실은 "소장실" |
| 기능(문서 · 기록 · 코드) | **디스패처**. 역할 키는 `foreman` 그대로(DB · 승인 규칙이 쓴다) |

- 프로젝트별 이름("런슈즈 팀장")은 고르지 않았다 — 디스패처는 하나다. 방마다 서 있는 팀장은 같은 디스패처의 그 프로젝트 창구이고, 패널 제목이 "팀장 · 런슈즈 건"이다
- 테마마다 이름을 바꾸는 틀은 이미 있었다(배송 담당: 오피스 "배포 담당" · 현장 "출하 반장")
- 디스패처 상황 묶음은 "포먼"이라고 쓴 요청도 FOREMAN으로 알아본다(`ALIASES`)

## 2. 감독실 캐릭터는 무엇인가

| | 세션 캐릭터 | 감독실 캐릭터 |
|---|---|---|
| 실체 | CC 세션(tmux · 트랜스크립트) | 디스패처. 부를 때마다 `claude -p` 한 번 |
| 하는 일 | 파일 · 명령 | 계획만. 띄우기 · 보내기 · 노트 고치기는 사람이 [시작]을 눌러야 |
| 기억 | 대화 컨텍스트(압축된다) | 노트(크기를 정한 기록) |
| 이력 | 트랜스크립트 | `dispatch` 표 |

화면에 보이는 것: 계획을 세우는 동안 책상에서 일하는 동작(`running` — `claude -p`가 도는 동안), [시작]을 기다리는 자동 제안이 있으면 머리 위 "제안 N", 누르면 가운데에 말하기 창(그 방이면 그 프로젝트로, 제안이 있으면 그 계획) · 패널에 노트 · 지난 디스패치 · 제안.

## 3. 노트

상주 세션은 압축된다 — 압축 요약에 무엇이 남을지 고를 수 없다(11-05 압축 손실 점검). 노트는 **무엇이 남을지 사람이 고르는 압축 요약**이다. 호출은 매번 새로 하고 노트만 함께 넣는다.

| 쌓는 것 | 어디 |
|---|---|
| 진행 중인 일 줄기(thread) — 무엇을 · 어느 세션들 · 어디까지 · 남은 것 | `foreman_note` |
| 사람이 정한 판단(decision) — 사람의 말 · log에 근거가 있는 것만 | `foreman_note` |
| 지난 디스패치와 사람이 고친 칸 | `dispatch` 표에서 바로(새로 저장하지 않는다) — 최근 5건 |

- **쌓지 않는 것: 구조 · 자주 쓰는 명령.** CC 메모리 · CLAUDE.md · docs에 있고 새 세션이 스스로 읽는다. 사본은 원본이 바뀌면 조용히 낡는다
- **줄마다 출처와 확인 시각.** 출처는 `세션 N` · `log/….md` · `docs/….md` · `dispatch #N` · `커밋 <sha>` 중 하나. 묶음에 넣을 때 확인 뒤 바뀐 것을 기계로 붙인다: 그 줄의 세션에 뒤 활동 · HEAD가 움직인 커밋 수 · 출처 파일이 없어짐 → `⚠`
- **상한 약 2000토큰**(프로젝트마다, 한글 1자 ≈ 1토큰으로 넉넉히). 진행 중인 일 먼저 · 최근 확인한 것부터 넣고 넘친 줄은 **지우지 않고 접는다** — 묶음에 안 들어가고 패널에 "접힘"으로 보인다
- **고치기는 디스패처가 제안 · 사람이 [시작] 때 승인.** 계획의 `note_updates`(add · update · retire · touch)가 계획 카드에 체크 칸으로 뜨고, 켠 것만 [시작]과 같은 트랜잭션으로 반영한다. 바꾸면 옛 줄은 `retired_at` · `replaced_by`로 남는다. 진행 중인 일 줄에는 이번에 띄운 세션을 붙인다. 사람은 패널에서 [내리기]만 바로 한다

## 4. 자동 기상 2단계

README 3.5 "자동 기상"을 한 번에 자동으로 가지 않는다(`docs/11_foreman_dispatch.md` 7절).

```mermaid
flowchart LR
  F["실패 이벤트<br/>파이프라인 실패 · 빌드 알림 없음 · 웹훅 끊김<br/>인프라 무응답 · 적재 막힘"] -->|"알림과 같은 때 on_failure"| W["Waker<br/>같은 실패 12시간 안 한 번 · 하루 5번 · 한 번에 하나"]
  W -->|"origin=wake"| D["디스패처 claude -p<br/>점검 · 읽기 전용으로"]
  D --> P["dispatch 표 planned"]
  P --> TG["텔레그램 🧭 제안 + 링크 /?dispatch=N"]
  P --> SC["화면 — 감독실 캐릭터 '제안 N'"]
  TG --> H["사람이 계획 보고 [이대로 시작] · [버리기]"]
  SC --> H
```

- 설정 `config/wake.toml`: 켜기 · 하루 상한 5 · 같은 실패 12시간 · 공개 주소 · 종류
- 조용한 고장이 되지 않게: 계획을 못 세우면 그것도 텔레그램으로("디스패처가 살펴볼 계획을 세우지 못했습니다"), 하루 상한에 닿으면 그날 한 번. 알림을 보내는 쪽은 콜백이 바로 돌아와 영향이 없다
- 적재 막힘 중 DB 끊김 · 시간 초과(`transient`)는 계획하지 않는다 — 기다리면 돌아온다
- 밤에도 계획은 만든다(시작은 사람이 누르니). 3단계로 가면 밤 · 동시 1개 · 20분 규칙을 그때 정한다
- 시험: `POST /api/foreman/wake-test`(토큰) — 알림 글 하나로 실제 경로를 끝까지, 글 앞에 〔시험〕

## 5. 왜 이렇게

- 노트를 DB에 둔 것 — 화면 패널 · [시작] 트랜잭션 · 낡음 비교(세션 활동 · 커밋)가 모두 DB에 있다. 파일이면 사람이 고치기 쉽지만 반영과 계획 승인을 한 번에 묶을 수 없다
- 노트 상한을 토큰으로 — 디스패처 묶음이 10~20k 토큰이라, 프로젝트 셋 × 2k가 넘치지 않는 크기
- 2단계 제안을 텔레그램 버튼이 아니라 링크로 — 브리지는 텔레그램을 보내기만 한다(받는 길이 없다). 화면은 Cloudflare 로그인 뒤라 링크가 곧 사람 확인이다

## 6. 시도한 것 · 찾은 것

- 디스패처를 다시 부르자 `claude를 띄우지 못했습니다: [Errno 2]` — systemd 서비스(11-06)의 PATH에 `~/.npm-global/bin`이 없었다. 이틀 동안 디스패처 · 인계 요약이 같은 상태였는데 그 사이 부른 사람이 없어 몰랐다. PATH를 고치고, 기동 때 `claude`를 못 찾으면 텔레그램으로 알린다
- 실제 디스패처로 "발볼 검증 이어서"(런슈즈 방) → 16.7초, `ask`(이어 갈 검증이 기록에 없다며 되물음), 노트 제안 0 — 사람이 정한 판단이 이미 CC 메모리에 있어 겹쳐 쌓지 않았다
- 2단계 시험(11-06 Jenkins 무응답 상황) → 펫퍼민트 · 점검 · 읽기 전용 · 새 세션, 확신도 0.7, "〔시험〕이고 마지막 빌드가 모두 성공이니 지금도 죽어 있는지부터" — 텔레그램 · 화면 제안까지 나갔다

## 7. 남은 것

- 노트가 실제로 쌓이는 모습은 아직 없다 — 디스패처를 몇 번 쓰고 `foreman_note`를 본다
- 3단계(묻지 않고 띄우기)는 2단계 제안이 몇 주 동안 맞는지 보고 정한다
- 텔레그램에서 바로 [시작]은 없다(링크로 화면)
