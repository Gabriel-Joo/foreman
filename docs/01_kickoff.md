# BRIEF 01 — 킥오프: 설계 검토

FOREMAN 프로젝트를 시작한다. 이 지시서의 목적은 **구현이 아니라 검토**다. 코드를 쓰지 말고, 아래 순서대로 읽고 판단한 결과만 보고할 것.

---

## 1 / 읽을 것

`README.md`를 처음부터 끝까지 읽는다.

→ **원하는 동작**: 전체 설계를 파악한다. 특히 아래 네 개념의 관계를 정확히 이해할 것.

- 캐릭터(영속)와 세션(임시)의 분리
- 캐릭터가 인프라의 거울이라는 규칙 — 등장은 이벤트, 생존은 폴링
- 입력(send-keys)과 출력(JSONL)의 경로 분리 이유
- 커밋 SHA를 축으로 한 CI/CD 인과 체인

**확인 체크리스트**

- [ ] 세션을 턴마다 끄지 않는 이유를 설명할 수 있다
- [ ] IDLE과 DORMANT의 차이와 각각의 비용을 설명할 수 있다
- [ ] headless 세션을 쓰지 않는 이유를 설명할 수 있다
- [ ] 서버 다운을 브리지가 아니라 브라우저가 판단하는 이유를 설명할 수 있다

---

## 2 / 환경 조사

현재 서버 PC 상태를 조사한다. **추측하지 말고 실제로 확인할 것.**

→ **원하는 동작**: 아래 항목을 실제 명령으로 확인하고 결과를 표로 보고한다.

- tmux 설치 여부 및 버전
- 현재 실행 중인 CC 프로세스와 그 실행 방식 (tmux 안인지 아닌지)
- `~/.claude/` 구조 — settings 파일 위치, 기존 hook 설정 유무
- `~/.claude/projects/` 아래 트랜스크립트 JSONL의 실제 경로 규칙과 파일 1개의 스키마
- 현재 텔레그램 연동이 어떤 방식으로 붙어 있는지 (스크립트 위치, 호출 지점)
- MySQL 파드 접근 경로 및 접속 가능 여부
- Python / Node 버전, ttyd 설치 여부

**확인 체크리스트**

- [ ] 모든 항목을 추측이 아니라 명령 실행 결과로 채웠다
- [ ] JSONL 한 건의 실제 필드 구조를 샘플로 제시했다
- [ ] 접근이 안 되는 항목은 "불명"으로 남기고 이유를 적었다

---

## 3 / 설계 검토

README의 설계에서 실제로 막힐 지점을 찾는다. **동의하는 부분은 쓰지 말고, 문제가 될 부분만 적는다.**

→ **원하는 동작**: 아래 관점에서 각각 검토하고, 근거와 함께 지적한다.

| 관점 | 확인할 것 |
|---|---|
| 턴 경계 판정 | Stop hook이 실제로 주는 정보로 충분한가. 누락 케이스는 |
| 입력 주입 | send-keys가 CC TUI에서 실제로 동작하는가. 멀티라인·특수문자는 |
| 트랜스크립트 | JSONL 폴링 지연이 실용적인 수준인가. 더 나은 방법이 있는가 |
| 승인 정책 | PreToolUse hook으로 자동 승인이 실제로 가능한가. 현재 CC 버전 기준 |
| 스키마 | 누락된 테이블·컬럼, 과한 설계, 인덱스가 필요한 지점 |
| 인과 체인 | 커밋 SHA만으로 연결이 끊기지 않는가. 여러 커밋이 한 빌드에 묶이면 |
| 수명 정책 | DORMANT 부활 시 요약 주입만으로 충분한가 |

**확인 체크리스트**

- [ ] 각 지적에 "왜 문제인지"와 "대안"을 함께 적었다
- [ ] CC 공식 문서나 실제 동작 확인으로 근거를 댔다 (추측이면 추측이라고 명시)
- [ ] 동의하는 부분은 적지 않았다

---

## 4 / 기존 구현 조사

README "참고할 기존 프로젝트" 항목의 레포들을 조사한다.

→ **원하는 동작**: 각 레포에서 가져다 쓸 수 있는 부분과 직접 만들어야 하는 부분을 가른다.

- 라이선스 확인 (차용 가능 여부)
- tmux 제어 로직이 어떻게 구현돼 있는지
- hook 설정 방식
- 우리 설계와 충돌하는 가정이 있는지

**확인 체크리스트**

- [ ] 레포별로 차용 가능 여부를 라이선스 근거와 함께 판정했다
- [ ] "통째로 쓸 것 / 로직만 참고할 것 / 쓰지 않을 것"으로 분류했다
- [ ] 우리 설계와 다른 전제를 쓰는 곳을 짚었다

---

## 5 / 단계 0 실행 계획

로드맵 0단계(CC를 tmux로 이전)만 **계획**한다. 실행은 아직 하지 않는다.

→ **원하는 동작**: 현재 돌고 있는 두 세션을 중단 없이 tmux로 옮기는 절차를 제시한다.

- 세션 이름 규칙
- 기존 대화 컨텍스트를 잃지 않는 방법 (또는 잃는다면 그 사실을 명시)
- 되돌리는 방법

**확인 체크리스트**

- [ ] 현재 작업 중인 내용이 날아가는지 여부를 분명히 했다
- [ ] 각 명령이 무엇을 하는지 한 줄씩 설명했다
- [ ] 실패 시 복구 방법을 적었다
