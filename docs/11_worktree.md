## 1. 만든 것(사용자 승인 11-05)

| 무엇 | 어떻게 |
|---|---|
| 언제 worktree인가 | 그 프로젝트에 살아 있는 세션이 있을 때 [+ 세션] · 포먼 디스패처 · [새로 띄우기]가 기본으로. 포먼 계획 카드의 「작업방」 칸([자세히] 안)으로 끄고 켠다 |
| 자리 | `<repo>/.worktrees/<이름>`, 브랜치 `cc/<이름>`(이름은 tmux 이름에서 `cc-`를 뗀 것). 저장소 안이라 조립기가 같은 프로젝트로 잡고, 폴더 신뢰도 상위를 따른다(시험에서 신뢰 창 안 뜸) |
| git이 안 보게 | `.git/info/exclude`(로컬 전용, 저장소 파일 아님)에 `/.worktrees/` · `/.venv` · `/.tools` · `/.env*` · `node_modules` |
| 링크 | 저장소 맨 위 `.venv` · `.tools`(ttyd 등 — 없으면 ttyd 시험이 건너뛴다, 11-14) · `.env*`와 한 단계 아래 `*/node_modules` → 원본을 가리키는 링크 |
| CC 메모리 | `~/.claude/projects/<worktree 경로>/memory` → 원본 메모리 폴더 링크. 시험 세션이 원본 MEMORY.md 첫 줄을 그대로 말했다 |
| 합치기 | 세션을 끝낸 뒤 패널 [합치기] → 확인 창 → worktree에서 `rebase <base>` → 원본에서 `merge --ff-only` → worktree · 브랜치 지움. **push는 안 한다**(런슈즈는 push = 배포). 11-10부터 실제로는 관리자가 같은 API로 합친다 — 「6. 합치기」 |
| 충돌 | rebase가 멈추면 `rebase --abort`로 되돌리고 충돌 파일 목록을 보여 준다. worktree는 그대로 — 세션을 다시 띄워 풀고 커밋한 뒤 다시 합친다. 합치기 전에 충돌을 미리 보는 법은 「6. 합치기」 |
| 막는 것 | 세션이 살아 있으면 합치기 · 버리기 불가. 커밋 안 된 변경이 있으면 합치기 불가(끝내기 확인 창에서 미리 경고). 버리기는 이름을 그대로 적어야 한다 |
| 스키마 잠금 | `config/worktree.toml` — 프로젝트별 마이그레이션 경로 · 명령. 처음 쓴 세션이 잠금을 갖고, 다른 세션의 같은 시도는 PreToolUse에서 **거부**(승인 모드가 observe인 런슈즈도). 풀림: worktree 세션은 합치기 · 버리기 때, 원본 폴더 세션은 끝날 때, 사람이 `DELETE /api/schema-lock/<프로젝트>`(11-09부터 화면 배너에서도 — 「5.」) |
| 잠겨 있을 때(세션의 방침) | 잠금을 가진 앞 세션이 살아 있으면 스키마 변경 없이 할 수 있는 일부터 하고, 스키마가 필요한 단계를 시작할 때 잠금을 다시 본다. 잠금을 가진 세션이 이미 끝났으면(잠금 파일에 이름이 남아 있어도) 가져가 써도 된다 |

API: `POST /api/spawn`의 `worktree`(null · true · false), `POST /api/sessions/{id}/worktree` `{action: merge|discard, confirm}`, `GET /api/schema-lock`.

## 2. 미리보기 브리지

**11-05 사용자 결정**
- A(화면만 worktree, 데이터는 지금 브리지)로 한다
- 버튼을 누를 때만 띄운다
- 런슈즈 vite는 FOREMAN을 써 본 뒤에 한다

→ 만들었다(`bridge/preview.py` · `bridge/previews.py`).

설계 문서와 다른 점
- 상태는 DB 표 대신 `~/.foreman/previews.json`에 둔다(스키마 잠금과 같은 방식)
- 미리보기 서버 코드는 원본 저장소 것을 쓰고, 화면 파일만 worktree에서 읽는다

아래는 승인 전 설계 그대로다.

worktree에서 고친 화면은 지금 브리지(원본 폴더의 `bridge/static`)에 안 보인다. 합치기 전에 그 worktree의 화면을 보는 자리가 필요하다.

### 2.1 무엇을 띄우나 — 프로젝트마다 명령 하나

`config/worktree.toml`에 프로젝트별 미리보기 명령을 둔다. `{port}` · `{wt}`를 채워 tmux 창에서 띄운다.

```toml
[preview.foreman]
cmd = ".venv/bin/python -m bridge.preview --port {port} --static bridge/static --upstream http://127.0.0.1:8000"
[preview.runshoes]          # 나중에 — 런슈즈 화면(vite). 백엔드는 로컬 Spring을 그대로 쓴다
cmd = "npm --prefix frontend run dev -- --port {port} --strictPort"
```

**FOREMAN은 "화면만 worktree, 데이터는 지금 브리지" 방식(A)을 제안한다** — `bridge/preview.py`(작은 FastAPI):
- `/`, `/classic`, `/static/*`는 worktree의 파일로 준다
- `/api/*` · `/ws`는 지금 브리지(8000)로 그대로 넘긴다(토큰 헤더 포함). 그래서 실시간 데이터가 그대로 보이고,
  DB에 두 번 적재하거나 알림 · 승인 · 웹훅이 두 벌 도는 일이 없다

| | A. 화면만(제안) | B. worktree 브리지 통째(읽기 전용 모드) |
|---|---|---|
| 보이는 것 | worktree의 HTML · JS · CSS · 테마 | 위 + worktree의 백엔드(API) 변경 |
| 데이터 | 지금 브리지 그대로(실시간) | 같은 DB를 읽기만 — 적재 · 알림 · 승인 · 웹훅 · hook 끄는 `FOREMAN_PREVIEW=1` 모드를 만들어야 한다. 실시간 이벤트 없음 |
| 위험 | 거의 없다 | 끄기를 빠뜨리면 두 벌 적재 · 이중 알림. 스키마가 다른 worktree면 깨진다 |
| 만드는 양 | 파일 하나(~100줄) | 브리지 곳곳에 모드 분기 |

화면 작업이 대부분이라 A부터 만들고, 백엔드 미리보기가 필요해지면 B를 따로 정한다.

### 2.2 포트 · 프로세스

- 포트: 8200~8299에서 빈 것(소켓을 열어 본다). 바인드는 지금 브리지와 같은 `127.0.0.1`. 8100은 이미 다른 것이 쓴다
- tmux 세션 `fm-pv-<이름>`에서 돈다 → 브리지를 다시 띄워도 미리보기는 남는다. 포트 · tmux 이름은 DB(새 표 `preview`: 세션 · worktree · 포트 · 시작 시각 · 상태)
- 브리지가 뜰 때 표와 tmux를 맞춰 본다: 표에만 있으면 닫힘, worktree가 없어진 미리보기는 끈다

### 2.3 화면에서

- 패널 [세션 정리] 탭 「브랜치 이름」 칸에 **[미리보기 열기]**. 누르면 없으면 띄우고(포트 자동) 새 탭으로 연다. 돌고 있으면 「미리보기가 :8203에서 돌고 있습니다.」와 [미리보기 닫기]
- 토큰: 포트가 다르면 출처(origin)가 달라 브라우저 저장소의 토큰이 없다 → 여는 주소에 `#t=<토큰>`(조각 — 서버로 안 간다)을 붙이고,
  미리보기 페이지가 저장한 뒤 주소에서 바로 지운다(`history.replaceState`). 미리보기 머리말에 **"미리보기 · cc/<이름>"** 띠를 둘러 원본 화면과 헷갈리지 않게
- 미리보기 화면에서도 버튼(입력 · 승인 · 세션 조작)은 지금 브리지로 가서 **진짜로 동작한다**. 띠에 그 사실을 적는다

### 2.4 정리

- 세션을 **끝내면** 미리보기도 끈다(사용자 요청)
- 끝난 뒤에도 worktree가 남아 있으면 [미리보기 열기]로 다시 띄울 수 있다 — 합치기 전에 보고 싶을 때
- 합치기 · 버리기 때 끈다. 브리지가 뜰 때 주인 없는 미리보기를 끈다

### 2.5 정할 것

1. A(화면만, 데이터는 지금 브리지)로 시작해도 되나
2. 미리보기는 버튼을 눌렀을 때만 띄우나(제안), 아니면 worktree 세션을 띄울 때 바로 띄우나
3. 런슈즈 미리보기(vite)도 이번에 같이 하나, FOREMAN만 먼저 하나(제안: FOREMAN 먼저)

### 2.6. 「있음」은 미리보기가 답할 때만 (11-13, `691487e`) [log:preview_alive_20261113.md]

기록(`~/.foreman/previews.json`)과 tmux만 보고 「있음」으로 답하던 것을 실제 응답으로 바꿨다. 서버가 죽었는데 기록이 남아 「있음」으로 보이는 조용한 고장이었다.

- **확인 주소 `/__foreman_preview`** (`bridge/preview.py`): 응답 머리 `X-Foreman-Preview: 1` + `{"foreman_preview": true}`. 프록시보다 먼저 등록해 지금 브리지로 넘어가지 않는다
- **「있음」** (`bridge/previews.py` `get()`): 기록이 있어도 tmux가 살아 있고 `_probe(port)`(127.0.0.1의 그 포트에 확인 주소를 두드림)가 참일 때만. 포트만 열린 남의 서비스는 거짓이다. 아니면 기록을 치우고 남은 tmux도 끄며 까닭을 `dead[경로]`에 남긴다
- **죽었으면 치우고 다시 띄운다** (`start()`): 결과에 `restarted` · `was_dead`. 다시 띄우기도 실패하면 「미리보기가 죽어 있습니다(까닭). 다시 띄우지 못했습니다: …」로 거부한다(패널이 보여 주는 서버 거부 사유). `_ready()`도 단순 연결이 아니라 `_probe`로 본다
- **세션 상태 `preview_dead`** (`bridge/handoff.py`): 죽어서 기록을 치운 까닭, 없으면 `None`. 패널 JS는 아직 이 칸을 띄우지 않는다(후속)
- **텔레그램은 보내지 않는다** (11-13 사용자 결정 — 사람이 버튼으로 연 것이고 거부 사유가 그 자리에 바로 뜬다)
- 옛 코드로 띄운 미리보기는 확인 주소가 없어 한 번 「죽음」으로 보고 다시 띄워진다. 합친 뒤 브리지를 다시 띄워야 서버 쪽이 돈다

## 3. 같이 도는 세션의 범위

- **UI(화면)를 맡은 세션이 다른 세션과 같이 돌 때는 테마 `roles` · 역할 색 · 패널의 캐릭터 · 역할 표시(`render.js` `sessionMeta`)를 건드리지 않는다.** 역할 · 색은 역할 작업 쪽이 갖는다(사용자 합의 — "테마 `roles` · 역할 색 · 패널의 캐릭터 · 역할 표시(`render.js` `sessionMeta`)는 건드리지 마라")

## 4. 쉬게 하기 · 이어서 (11-09, 세션 233) [log:coder_resident_20261109.md]

worktree 세션을 **끝내지 않고 잠깐 내려놓는** 길. 끝내면 합치거나 버리는 것밖에 없어서, 하다 만 일이 "합치기 기다림"으로 남을 곳이 필요했다.

**[쉬게 하기]** — 패널 「세션」, worktree 세션만. `POST /api/sessions/{sid}/rest`. **(11-14 바뀜) 화면 이름은 [끝내기 ▾]의 「커밋만 하고 끝내기」**(아래 「패널 「세션」 버튼」) — 하는 일 · 확인 창은 같다

**패널 「세션」 버튼(11-14 사용자, `handoff.js` `END_ITEMS` · `endMenu`)** [log:designer_sesstab_end_20261114.md] — 살아 있는 worktree 세션은 `[끝내기 ▾] [더보기 ▶]` 둘이다. [끝내기 ▾]를 누르면 버튼 줄 바로 아래로 셋이 펼쳐지고, 각 줄 아래에 설명이 있다(전엔 호버). 고르면 전 버튼과 같은 `data-act` · 확인 창 · API로 간다

| 메뉴 항목 | 줄 아래 설명 | 전 버튼 | API |
|---|---|---|---|
| 합치고 끝내기 | 고친 것을 main에 합치고 끝냅니다 | (전 이름 [끝내고 합치기]) | `POST …/worktree {"action":"merge","end":true}` |
| 커밋만 하고 끝내기 | 작업방에 커밋만 해두고 끝냅니다 | [쉬게 하기] | `POST …/rest` |
| 그냥 끝내기 | 아무것도 안 하고 세션만 끕니다 | [그냥 끝내기(나중에 정함)] | `POST …/action {"action":"exit"}` |

- **[끝내고 버리기]는 화면에서 뺐다** — 저장한 커밋까지 되돌릴 수 없이 사라져 위험하고, 「그냥 끝내기」 뒤 끝난 세션의 [버리기]나 관리자 · 셸로 대신한다. **API(`{"action":"discard","end":true}`)는 그대로다.** 서버 거부 글은 11-15에 지금 메뉴 이름으로 고쳤다(전 글 「…[끝내고 합치기] · [끝내고 버리기]로 함께 할 수 있습니다」): 「세션이 아직 살아 있습니다. [끝내기 ▾]의 [합치고 끝내기]로 끝내면서 합칠 수 있습니다. 버리려면 세션을 끝낸 뒤 「브랜치 이름」 칸의 [버리기]를 누릅니다」(`bridge/handoff.py`)
- 할 수 없는 항목은 꺼진 버튼으로 흐리고 호버에 까닭(「커밋만 하고 끝내기 — 지금은 할 수 없습니다. 작업 중입니다.」). [끝내기 ▾] 자체는 늘 눌린다(흐린 까닭을 보게). 메뉴 밖을 누르거나 Esc면 닫힌다
- worktree가 없는 세션(관리자)은 전처럼 [세션 끝내기] 하나(고를 것이 하나라 메뉴로 모으지 않는다). 호버만 「세션 끝내기 — 세션을 완전히 끝내고 창도 닫습니다.」
- 그 아래 칸 이름 「따로 작업」 → **「브랜치 이름」**(칸에 든 `cc/<이름>`은 브랜치 이름이다). 살아 있을 때 붙던 「세션을 끝내면서 합치거나 버립니다 — …」 줄은 뺐다(11-14 `91e090a`가 `handoff.js`에서 지웠다. 지금 코드에 없는 것이 맞다)
1. 작업 중이거나 뒤에서 도는 일(백그라운드 Bash · Monitor · 서브에이전트 — 대시보드와 같은 기준)이 있으면 **먼저 막고 까닭을 띄운다.** 커밋도 하지 않는다. 그대로 끝내면 CC가 끝내기 확인 창에서 멈춘다 [log:old_session_exit_bg_20261109.md]
2. 없으면 `git add -A` → 넣으면 안 되는 것을 내린다: `.env*`(견본 빼고) · `.venv` · `.tools` · `node_modules` · worktree 밖을 가리키는 링크. 거부가 아니라 **빼고 진행하고, 뺀 것은 결과 글에 적는다**(링크 하나 때문에 진행 중 저장 전체를 못 하는 것보다 낫고, 조용히 빼지 않는다)
3. 커밋 "쉬게 하기: 진행 중 저장 — <제목>". 커밋이 실패하면(pre-commit 등) 거부하고 올린 것을 내린다
4. `/exit`. 안 내려가면 tmux 화면에서 CC 끝내기 확인 창을 찾아 "CC 끝내기 확인 창에 걸렸습니다"로 알린다
- `session_action` `rest`에 남긴다(실패는 ok=0). worktree · 브랜치는 그대로

**[이어서]** — 「브랜치 이름」 칸, 끝난 worktree 세션. `POST /api/sessions/{sid}/rest-resume`
- 새 tmux 창에서 `claude --resume <cc> [--model]`. 대화 기록 파일이 없거나 45초 안에 안 붙으면 까닭을 띄운다. 이미 살아 있는 세션이면 거부한다

## 6. 합치기 — 누가 어떻게 (11-10, 코드 확인) [log:merge_237_242_20261110.md]

합치기의 몸(`bridge/worktree.py` `merge`)은 「1.」 그대로다 — worktree에서 `rebase`, 원본에서 `merge --ff-only`, worktree · 브랜치 지움, push 없음. 달라진 것은 **누가 부르는가**다.

- **관리자(원본 폴더 세션)가 `POST /api/sessions/{sid}/worktree` `{"action":"merge"}`로 합친다.** 사용자가 패널 [합치기]를 누르던 때와 같은 API다
- **사용자가 패널로 하는 길도 남아 있다**(`bridge/static/js/handoff.js`): 끝난 세션의 「브랜치 이름」 칸 [합치기], 살아 있는 세션의 「세션」 [끝내기 ▾] → 「합치고 끝내기」(`end: true`, 11-14 전 이름 [끝내고 합치기])
- **합치기 전에 충돌을 따로 본다.** 예: `git merge-tree --write-tree <base> cc/<이름>`의 결과를 읽는다. 충돌이 없다고 나온 것을 **본 뒤에** 합치기 API를 부른다. 확인과 합치기를 한 명령에 묶지 않는다
- **충돌이면 `end: true`로 부르지 않는다.** `end: true`는 세션을 먼저 끝낸 뒤 합치므로(`HandoffManager.worktree_act`) 충돌이 나면 풀 세션이 이미 없다. 화면 확인 창도 "충돌이 나면 되돌리고 멈춥니다(세션은 이미 끝난 뒤입니다)"라고 적는다
- **살아 있는 세션의 충돌은 그 세션이 푼다**(main을 가져와 rebase하고 커밋한 뒤 다시 합친다). 세션이 이미 끝났으면 관리자가 푼다 — 예: README 표(11-15 전의 「나중에 할 일」 표가 그랬다)처럼 줄만 합치면 되는 충돌을 `git rebase main` 뒤 두 쪽을 다 남기고 `--continue`(CLAUDE.md 「작업 규칙」 관리자 기준 2)
- 합친 뒤 시험 · push · 브리지 다시 띄우기 · 화면 점검은 관리자 몫이다. 커밋 안 된 변경이 있으면 합칠 수 없다 — 세션이 끝내기 전에 커밋을 마친다
- **규칙 파일이 바뀌면 알린다**(11-15, 조사 B 고치기 [log:foreman-7_silent_delete_fix_20261115.md]): `merge`가 ff 전에 `git diff --name-only <base>...<브랜치>`를 지금 도는 규칙(원본 폴더 `config/approval.toml` `[sensitive] protect`)과 맞댄다(`worktree.rule_changes` → `approval.rule_files`). 걸리면 결과에 `rule_files`, `note` 끝에 「🛡 규칙 파일이 바뀝니다(…). 브리지를 다시 띄우면 반영됩니다.」, 합친 뒤 `HandoffManager.worktree_act`가 텔레그램 🛡 한 번(kind `rulefile`). **합치기를 막지는 않는다.** 작업방 편집은 그 자리에서 효과가 없고 합친 뒤 브리지를 다시 띄울 때 살아나므로 이 순간을 본다. 작업방 안에서 규칙 파일을 고치는 순간에도 원본 경로와 같이 묻지 않고 🛡 알림이 간다(11-15 `7ccb55f`, `config/approval.toml [sensitive]`의 `protect`와 편집 허용 목록에 작업방 경로 꼴을 더함). 확인을 못 했으면 `note`에 「규칙 파일이 바뀌는지 확인하지 못했습니다(까닭)」
- **세션을 살려 둔 채 합칠 때**(API가 「세션이 아직 살아 있습니다」로 거절, 11-11): `merge-tree` 확인을 먼저 따로 한 뒤 원본 폴더에서 손으로 합친다. 브랜치가 main 끝 위에 있으면 `git merge --ff-only cc/<이름>`, main이 그 사이 앞섰으면 `git merge --no-ff cc/<이름>`(11-11 `52ba341` — 디자이너 273). 세션 · worktree는 그대로 남는다

  - **「자세히」의 사람에게 올린 까닭(11-15 사용자 — 위 「승인해야 할 파일 N개」와 같은 말이 또 보였다)** [log:foreman-4_confirm_merged_20261115.md, log:foreman-4_more_overlap_20261115.md]: 늘 사람 경로 파일은 위 줄과 같아 「자세히」에서 뺐다. 위에 안 보이는 것만 남긴다 — 늘 사람 경로가 아닌 까닭(지우기 · 자원 크기 등)은 그 까닭 글(서버 글)을 머리로 파일 이름을 줄마다, 파일이 없는 까닭은 위에서 60자로 잘렸을 때만 전부. 서버 `note` 「사람 승인 카드입니다 …」 · 「관리자가 승인합니다 …」는 위 줄과 같은 뜻이라 안 그린다. **관리자 세션에 못 알린 것(`manager_told === false`)은 조용한 고장이라 경고로 남긴다**(알렸다는 말은 안 그린다)
  - **합친 뒤 안내**: 「main에 커밋 N개를 하나로 합쳤습니다. push는 아직입니다.」(squash가 아니면 「하나로」 없이) + 「해시 「제목」」 두 줄. 「자세히」 안에는 squash 설명과 원래 커밋 보는 `git log refs/foreman/squashed/…`만(관리자 세션에 못 알렸으면 그 한 줄도). **(11-15 사용자 — 같은 말이 세 번 떴다) 결과 `note` 원문은 그리지 않는다**: 「자세히」의 「합치기 결과 원문」을 뺐고, [합치기]를 누른 뒤 결과 글(`run` note)도 카드가 짧은 안내를 그리면 띄우지 않는다(`{ quiet: true }`). 「관리자 세션에 알렸습니다」 · 「시험, push, 브리지 다시 띄우기는 관리자가 합니다」 줄도 뺐다(뒤 줄은 [합치기] 호버에 있다). 서버가 합칠 때 카드에 갈래 `merge_result`(`count` · `commit` · `title` · `squash` · `orig_ref` · `base`, `bridge/mergeprep.py` `merge_result_of` — `bridge/worktree.py` `merge` 결과에 새 원본 끝 해시 `into`와 제목을 더함)를 남긴다. 갈래가 없는 옛 카드는 전처럼 `note` 원문을 그린다. 관리자 입력 칸에 가는 「[FOREMAN 합치기] …」 글과 `note`는 그대로다
  - **push 여부**(`pushed`): 합친 커밋이 원격 추적 ref `refs/remotes/origin/<base>`에 들어갔나(`git merge-base --is-ancestor`, `pushed_to_origin`). 관리자가 원본 폴더에서 push하면 그 ref가 갱신되므로 원격에 묻지 않고(fetch 없음) 안다. 합칠 때 한 번, 합친 카드가 남아 있는 동안 1분 훑기마다 다시 보고 True가 되면 「push까지 했습니다」. ref가 없거나 git이 실패하면 `None` — 화면은 「아직입니다」(호버에 확인하지 못했다고). 다른 곳에서 push하고 이 저장소가 fetch하지 않았으면 「아직」으로 남는다(한계)

- **브리지가 꺼져 있던 동안 지난 알림도 다시 뜰 때 한 번**(11-13 `2552526` [log:merge_remind_catchup_20261113.md]): 5 ~ 7일 사이에 다시 떴으면 첫 맞추기에서 위 5일째 알림이 나간다. 7일이 지나 사라진 물음(`esc_id`를 쥔 채 안 떠 있고 esc-off도 없음)은 `_esc_catchup`이 「⏳ 합치기 카드 물음이 7일이 지나 관리자 머리 위에서 사라졌습니다 — 카드는 남아 있습니다 · … · 브리지가 꺼져 있던 동안 지났습니다」를 바로 한 번 보낸다. **열쇠가 5일째 알림과 같아** 이미 보냈으면 다시 안 보낸다. 사람이 끈 카드 · 합쳐지거나 미뤄진 카드 · `remind_days = 0`은 알리지 않는다. 카드 자체가 치워졌거나(`keep_h`) 합쳐진 뒤면 알릴 대기가 없어 알리지 않는다
- **카드는 DB에 남는다**(11-13 321, `merge_card` 0032 [log:mergeprep_db_20261113.md]): 세션 하나에 한 줄, 카드 전부를 `card` JSON 한 칸에 둔다(`esc_id` · `esc_mgr` · `esc_error`도 거기). 브리지를 다시 띄워도 `MergePrep.restore()`가 첫 훑기 전에 카드 · 걸리는 문서 · `made_at`을 되살린다 — 합친 뒤 브리지를 다시 띄우면 카드와 정리 후보가 사라지던 조용한 손실을 막았다. 끝난 카드(합침 · 실패 · 충돌 넘김)는 `keep_h`(6시간), **걸리는 문서가 남은 합친 카드는 `keep_docs_h`(72시간)** 남긴다(기본값, `config/handoff.toml`에는 칸이 없다). 합치는 중(`merging`)에 브리지가 내려간 카드는 되살릴 때 `failed`(「결과를 모릅니다」)로 바꾼다. 같은 커밋이면 main이 앞서 카드를 다시 재도 `made_at`을 잇는다. DB 쓰기 · 읽기가 실패해도 카드는 메모리로 돌고, 처음 실패할 때 텔레그램 한 번 + 카드 목록 `store`/`health.error`에 사유가 뜬다
- **걸리는 문서를 다 봤으면**(11-17 전 「정리 후보를 다 골랐으면」) `POST /api/sessions/{sid}/merge-prep {"action": "docs_done", "by": "manager"}` — 합친(`merged`) 카드만 치운다(DB에서도). 대기 · 충돌 카드는 거부. 안 부르면 72시간 뒤 치운다. 합친 결과 글(관리자 입력 칸)에 이 부르는 법이 한 줄 들어간다
- **관리자는 늘 원본 폴더**(11-11 아홉): `spawn_new`가 관리자를 worktree로 띄우려 하면 거절하고(`bridge/handoff.py` `will_worktree(role="manager")` False), 원본 폴더에 관리자가 이미 살아 있으면 둘째를 거절한다(`manager_conflict`). 관리자 인계가 worktree로 떠서 push · 브리지 다시 띄우기를 못 했던 일의 뒤처리다 [log:handoff_misplaced_admin_20261111.md]
- 끄기: `enabled = false` + 브리지 다시 띄우기 — 카드만 사라지고 패널 [합치기] · API 합치기는 그대로
- **조사 세션 카드는 승인자 `auto`일 수 있다**(11-15, 아래 「6-2.」). 사람 화면(승인 막대, 말풍선, [합치기])에는 관리자 카드처럼 띄우지 않고 「브리지가 스스로 합치고 조사 세션을 끝냅니다. 사람이 누를 것은 없습니다.」만 보인다(`handoff.js` `managerCard`, `dashboard.py` `manager_card`)

### 6-2. 조사 세션 스스로 끝내기: log만 바뀐 작업방은 승인 없이 합친다 (11-15 사용자, `bridge/inspector_close.py`) [log:foreman-6_inspector_close_20261115.md]

사용자: 「조사 세션이 일을 마치면 스스로 끝나게 해라. 조사는 읽고 알려 주는 것이 전부라 끝나면 남을 까닭이 없다. 작업방도 치워라. 다른 역할은 그대로 둔다.」

- **언제**: 조사 세션 턴이 끝나고 15초(`settle_s`) 뒤. 끝내는 판정은 `docs/11_foreman_dispatch.md` 「10-2.」(일하는 중이 아니고 묻는 말이 없을 때). 턴 끝 알림(관리자에게 보고 넘기기)이 그 턴을 기록한 뒤 끝낸다. 5분마다 그물이 놓친 것(브리지를 다시 띄운 사이 끝난 턴)을 줍는다
- **log를 잃지 않는다**: 작업방 조사의 결과 log 커밋은 그 브랜치에만 있다. 끝내기 전에 main에 합친다
  - 합치기 준비(「6-1.」)가 카드를 만들 때, 조사 세션이고 **바뀐 파일이 모두 `log/` 새 파일**(`git diff --raw base...브랜치`의 상태가 모두 A)이고 충돌, 묻는 말, 늘-사람 까닭이 없으면 승인자를 `auto`로 둔다(`mergeprep.log_only_why`, `_auto_why`). 관리자 카드 글, 「합치기 준비됨」 텔레그램, 사람 승인 물음은 내지 않는다
  - 브리지가 `approve(by="auto")`로 세션을 끝내고 합치고(커밋이 둘 이상이면 squash, 「6-1.」 그대로) 작업방과 브랜치를 지운다. 관리자 입력 칸에 「[FOREMAN 합치기] 조사 세션 N 「제목」이 log 새 파일만 커밋해 브리지가 승인 없이 … 합쳤다 … 결과 log: … push는 관리자가 한다」가 간다. push는 하지 않는다
  - **승인자를 거치지 않는 근거**: 조사 브랜치에 들어갈 수 있는 것은 `roleguard` `inspector-write`가 막아 `log/` 새 파일 커밋뿐이다(「10-2.」). log 새 파일은 다른 파일을 바꾸지 않고, 시험이나 브리지 동작에 닿지 않으며, 늘-사람 경로(`config/*.toml`, `CLAUDE.md`, 마이그레이션 등)에 들지 않는다. 그래도 규칙만 믿지 않고 합치기 전에 브랜치를 다시 본다(규칙이 관찰로 돌거나 브리지 밖에서 커밋했을 수 있다). 다른 세션이 커밋한 log를 고치거나 지운 것(상태 M, D)도 `auto`가 아니다
- **스스로 합치지 않는 것**(지금처럼 카드로 남고 알린다): `log/` 밖 파일이 섞임, 있던 log를 고치거나 지움, 충돌, 묻는 말이나 사람 답 기다림, 늘-사람 까닭. 카드에 `auto_why`(까닭)가 실리고, 텔레그램 한 번(`mergeprep:noauto:<세션>:<커밋>`), 관리자 카드 글에 「조사 세션이지만 브리지가 스스로 끝내고 합치지 않았다: …」가 붙는다. 세션은 끝내지 않는다. 이미 `auto`로 만든 카드에 나중에 묻는 말이 생기면 지금 카드(관리자 또는 사람 승인)로 돌린다(`demote_auto`)
  - 스스로 합치려는 사이 main에 같은 이름의 log가 생겨 충돌하면 세션에 풀라고 보내지 않고(조사는 rebase를 못 한다) 관리자에게 넘긴다(`conflict_manager`)
- **커밋이 없는 작업방**: 잃을 것이 없어 세션을 끝내고 작업방을 버린다(`worktree_act discard`). 관리자에게 「작업 보고」 한 번
- **커밋 안 한 변경이 있으면** 끝내지 않는다(log를 잃지 않게). 텔레그램 한 번 + 관리자 입력 칸에 「[FOREMAN 합치기, 조사 세션 끝내기] …」 + `session_action insp-close`(ok 0)에 사유
- **실패는 조용히 묻히지 않는다**: 끝내기(`/exit`), 합치기, 치우기가 실패하거나 확인 자체가 실패하면 텔레그램 한 번(열쇠 `insp:…`) + 관리자 세션에 한 번 + `insp-close`(ok 0)에 사유. 합치기 실패와 충돌은 「6-1.」 그대로 카드에 사유가 남는다
- 시험 세션(`hidden_reason='test'`)도 같은 길이다(숨긴 세션도 카드를 만든다, `check_one(with_hidden=True)`)
- 끄기: `config/handoff.toml [inspector_close] enabled = false` + 브리지 다시 띄우기. 칸이 없으면 켜짐, `projects`가 없으면 foreman만

**11-10 실수** (237 합치기): `merge-tree`와 합치기 API를 한 명령에 묶어, 충돌로 "충돌 없음"이 안 찍혔는데도 합치기를 불렀고, `end: true`로 불러 세션 237이 먼저 끝났다(tmux도 닫힘). 다음 242는 살아 있는 채 충돌을 그 세션이 풀게 했다. 이 일로 위 두 줄을 정했다.

**`pgrep -f` 같은 함정**: 시험이 끝났는지 같은 확인을 합치기와 같은 명령에 묶으면 확인용 글자가 자기 셸에 걸린다 → `docs/operations.md` 「4. 작업 규칙의 상세」.

## 7. 다른 저장소는 읽기만 (11-09, `bridge/reposcope.py`) [log:repo_scope_readonly_20261109.md]

FOREMAN 세션은 다른 저장소(runshoes · petmint-rag-chatbot · ronanlab-infra · k8s-cluster)를 **읽기만** 한다. 훅으로 막는다(1단계). 11-09 하루만 봐도 다른 저장소에 쓰는 일이 있었다(Jenkinsfile · values.yaml · 런슈즈 settings.json · CLAUDE.md, 펫퍼민트 fetch).

  - Edit · Write · MultiEdit · NotebookEdit: 대상이 자기 저장소(+ `.worktrees/*`) 밖의 git 저장소 안일 때
  - git: `-C` · `cd`(줄을 넘어 이어짐) · `--git-dir` · `--work-tree` · `GIT_DIR=`로 다른 저장소를 가리키며 읽기가 아닌 것. `fetch` · `pull`도 막는다(그 저장소 `.git`에 쓴다)

## 8. 화면 말을 바꿀 때 — 화면 말 시험 (11-15, `tests/test_screen_words.py`) [log:foreman-4_screen_words_test_20261115.md]

「자기가 바꾼 기능의 docs 절은 같은 브랜치에서」(CLAUDE.md 「따로 작업(worktree)에서 일할 때」)를 pytest가 지키게 한다. 화면 글을 고쳤는데 호버 설명 · 서버 거부 사유 · 문서 인용이 옛 이름으로 남는 것을 잡는다(11-14 「세션 창」, 11-09 [인계 요약 받기]가 6일 남았던 것). 설계는 `log/foreman-6_screen_text_sync_proposal_20261115.md` 4절 「먼저 할 것」, 판정은 `tests/screen_words.py`, 목록은 `tests/data/screen_words.toml` 하나. 전체 pytest 안에서 1초 안에 돈다.

| 갈래 | 보는 것 | 걸리면 |
|---|---|---|
| 바꾼 이름(`[[rename]]`) | 옛 이름이 코드 문자열(`bridge/**/*.py` · `bridge/static/js/*.js` · `*.html`, 주석 · 로그 호출 · docstring 뺌)에 남음. 범위가 「화면과 문서 인용」이면 문서(`docs/*.md` · `README.md`, 11-15 `16dcb3a`부터 원고 `notion/**/*.md`, `portfolio/*.md`도) 인용 「…」 "…" […] 안도 | 새 이름으로 고친다. 세션 · `claude -p`에 넣는 프롬프트처럼 문서 말을 쓰는 곳이면 `[[code_exception]]`(그 문자열 안 한 조각 `near`까지) |
| 문서 [버튼] | 문서가 [버튼]으로 인용한 글이 지금 코드에 없음(N · M · … · 숫자는 아무 글로 본다, ＋와 +는 같게). 근거 표시(대괄호 안이 `c:`, `log:`, `code:` 등으로 시작하는 것)는 버튼으로 읽지 않는다(11-15 `e5d584b`, 이름 목록은 `bridge/evidence.py` `MARK` 한 곳) | 문서를 지금 이름으로. 버튼이 아닌 대괄호 · 만들지 않은 계획 · 전 이름 표는 `[[button_exception]]` |
| 호버 약속 | 호버 설명(「제목 — 설명」)이 더블클릭 · 두 번 누르 · 끌어 · ↑↓ · Esc · Enter · Ctrl · 휠을 말함 | `[[promise]]`에 한 줄(시험이 없으면 `test = ""`). CC에 보내는 키 설명일 뿐이면 `[[promise_skip]]` |

- **문서 줄의 이력 표시**: 그 줄에 전 이름 · (전 · 전 「 · 전 [ · 전에는 · 옛 · ~~ · → · 바뀜 · 바꿨다 · 지웠다 · 뺐다 · 였다 · 되돌 · 11-NN 전 중 하나가 있으면 옛 이름을 적어도 된다. 바뀐 것을 적는 줄은 「(전 이름 「…」)」처럼 쓴다
- **이름을 바꾸는 코더가 같은 브랜치에서 할 일**: 목록에 한 줄(`old` · `new` · `scope` · `commit`) + 시험이 가리키는 코드 · 문서 줄을 고친다. 범위는 문서에서는 그대로 쓰는 말(디스패처처럼)이면 `화면`, 문서가 화면 글로 인용하는 말이면 `화면과 문서 인용`. 옛 이름이 다른 뜻으로도 흔히 쓰이면(11-15 역할 이름 「점검」, 화면 점검 · 문서 점검은 그대로) `whole = true`로 문자열 전체가 그 낱말일 때만 걸고, 역할 이름이 쓰이는 꼴(「역할이 점검」 등)을 따로 한 줄씩 적는다
- **`docs/operations.md` · `docs/style_guide.md`에서 걸리면**(11-15 `16dcb3a`부터 원고 `notion/`, `portfolio/`도 같다): (11-17 바뀜, 사용자 지시 21) 이름을 바꾼 코더가 같은 브랜치에서 고친다(앞의 둘은 고치면 합치기 카드가 사람에게 간다). 고칠 수 없는 까닭이 있을 때만 `[[scribe]]`(서기 몫)에 `doc`, `text`(걸린 글)를 적고 그 까닭을 보고한다. 전에는 코더가 고치지 않고 늘 서기 몫에 적었다. 남은 수는 pytest 끝 요약 줄 「화면 말 시험: 서기 몫 N줄 남음 …, 호버 약속 7곳 중 시험 없음 6 · 일부만 1」에 늘 찍힌다. 서기가 맞추면 시험이 그 줄을 지우라고 실패한다
- **목록이 낡으면 실패한다**: 이제 걸리지 않는 예외 · 서기 몫 · 약속 줄은 「이 줄을 지웁니다」로. 목록이 조용히 쌓이지 않게
- 실패 글이 갈래마다 무엇을 어디에 적을지 알려 준다. 손으로 전체를 보려면 `.venv/bin/python tests/screen_words.py`
- 화면 말 밖의 문서 밀림은 「9.」의 거꾸로 찾기가 본다
- **못 잡는 것**: 목록에 적지 않은 이름 바꾸기 중 버튼이 아닌 글(띠 · 칩 · 거부 사유)의 문서 인용, 버튼 글과 그 호버 제목의 어긋남(안 C, 아직 안 함), 호버가 약속한 조작이 실제로 되는지(진짜 입력으로 해 보는 `screen.py --promises`, 아직 안 함, 11-15 사용자)
