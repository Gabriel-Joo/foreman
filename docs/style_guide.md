# 문서 쓰는 기준 (서기 · 모든 세션 공통)

> 상태: 12a(2026-11-06) 초안. 펫퍼민트 문서 관행(`~/AI_programming/petmint-rag-chatbot/docs/README.md`, `docs/pipeline.md` 「6. 문서 작성 원칙」)과 이 프로젝트에서 사용자가 준 지시를 모았다. 서기(`docs/12_scribe.md`)는 글을 쓰기 전에 이 문서를 읽는다.

## 1. 문서 종류 — 섞지 않는다

| 종류 | 자리 · 이름 | 무엇 | 언제 고치나 |
|---|---|---|---|
| 설계 · 브리프 | `docs/NN_<이름>.md` | 만들기 전에 정하는 것. NN은 README 로드맵 단계 번호 | 설계가 바뀌면 그 자리를 고친다 |
| 결과 | `log/NN_<이름>_result.md` · `log/stage<N>_<이름>_result.md` | 한 일 · 조사 결과 · 설계와 다른 점 · 판단 근거 · 남은 것 | 이어서 한 일은 절을 덧붙인다 |
| 서버 작업 | `log/infra_<날짜>_<주제>.md` | 서버 PC에서 바꾼 것 · 되돌리기 자원 | — |
| 점검 · 측정 | `log/<프로젝트>_<무엇>_<YYYYMMDD>.md` | 압축 손실 점검처럼 한 번 잰 결과 | 다시 재면 새 파일 |
| 회고 | `log/retro_<YYYYMMDD>_<주제>.md` | 기간의 판단 · 바로잡은 곳 · 뒤집힌 결정 · 실수 · 숫자 | 다시 쓰지 않는다(새 회고가 앞 회고를 가리킨다) |
| 규칙 | `CLAUDE.md` · 이 문서 | 꼭 지킬 것만 짧게. 상세는 docs를 가리킨다 | 사용자가 정할 때 |
| 미룬 일 | README 「나중에 할 일 (정해 두고 미룬 것)」 표 | 정해 두고 아직 안 한 것 | 하면 줄을 지운다 |
| 포트폴리오 | `portfolio/<NN>_<주제>.md`, 사진 `portfolio/img/<NN>_<주제>_*.png` | 저장소 밖 독자가 읽는 글. 주제 목록은 `config/portfolio.toml` | 다시 써도 같은 파일(다시 게시하면 Notion 페이지를 자리 지키며 고친다) |

- **HISTORY 파일은 따로 두지 않는다.** 결정의 역사는 결과 문서의 「설계와 다른 점」과 회고에 있다. 한 파일에 문제 · 결정 · 측정을 쌓으면 길어지기만 한다(펫퍼민트 `KNOWN_ISSUES.md` 477줄)
- 프롬프트 원문 · 압축 요약 전문 · 비밀값은 저장소에 넣지 않는다. 판정 재료는 `~/.foreman/` 아래(700)에 둔다

## 2. 이름 · 번호 · 날짜

- 파일 번호는 README 로드맵 번호를 따른다. 새로 매기지 않는다
- 날짜: 본문 `2026-11-05`, 줄여서 `(11-05)`, 파일 이름 `20261105`. 시각은 KST로 쓰고, DB의 UTC를 옮길 때는 바꾼다
- 늦게 붙은 절에는 제목에 날짜와 커밋을 단다: `## 이어서(11-06, b88c0d3) — …`
- 절 번호는 `## 1.` · `### 1-1.`. 짧은 결과 문서는 번호 없이 절 이름만 써도 된다

## 3. 문서 안 구성

**설계 문서(docs/)** — 펫퍼민트 순서를 따른다.
1. 머리 `> 상태:` — 날짜와 ✓(됨) · △(일부 · 확인 전) · ✗(안 됨)
2. 한 줄 요약
3. 최종 설계 — 처음부터 그렇게 정한 것처럼 쓴다
4. 왜 이렇게 했나 — 결정 하나에 이유 하나
5. 시도했던 것들 — **수치와 함께**. "이것저것 해봤다"가 아니라 "재보고 판단했다"로 읽혀야 한다
6. 남은 한계 · 정할 것
7. 검증 항목(`- [ ]`)

**결과 문서(log/)** — CLAUDE.md 「작업 규칙」 그대로: 한 일 · 조사 결과 · 설계와 다른 점 · 판단 근거 · 남은 것. 브리프를 다시 쓰지 않는다.

**회고(log/retro_*)** — 이 시스템만 가진 재료를 앞에 둔다(`docs/12_scribe.md` 「7. 포트폴리오 관점」).
1. 머리 `> 상태:` — 기간(KST), 재료 묶음 경로, 근거 확인 여부
2. 한 줄 요약
3. **사람이 바로잡은 곳** — AI가 틀리고 사람이 고친 자리. 무엇을 틀렸고 사람이 뭐라 했고 무엇으로 바꿨나
4. **뒤집힌 결정** — 옛 결정 → 바꾼 것 → 이유. 지우지 않는다
5. **실수 · 고친 버그** — 현상 · 원인 · 고친 것 · 왜 늦게 알았나
6. 한 일 — 단계별로 짧게, 결과 문서를 가리킨다(다시 쓰지 않는다)
7. 숫자 — 세션 · 턴 · 커밋 · 토큰 · 비용(표)
8. 남은 것

**포트폴리오(portfolio/)** — 읽는 사람이 이 저장소 밖에 있다(채용 담당 · AI 인프라 · AI 엔지니어). 갈래를 나누지 않고 한 줄로 쌓는다: 앞에 「한눈에」, 뒤에 주제 글(11-06 사용자 결정).
1. `# 제목` 바로 아래 `> 이 글은 …을 다룬다.` 한 줄 — 주제 글마다(11-06 사용자: "주제 글마다 머리에 이 글은 뭘 다루는지 한 줄")
2. 한 줄 요약(굵게)
3. 문제 — 왜 필요했나
4. 판단 — 무엇을 고르고 무엇을 버렸나, 이유
5. 구조 · 흐름 — ```mermaid 블록 가능(Notion에 코드 블록으로 올라가고, 사람이 한 번 미리보기로 바꾸면 다시 게시해도 남는다)
6. 겪은 문제와 풀이
7. 결과 · 숫자
8. 한계 · 다음
- 근거 표시(`[c:]` · `[log:]` · `[docs:]`)는 그대로 단다. 저장소가 비공개라 게시할 때 **링크 없이 글자만** 남는다(`bridge/notion.py` 포트폴리오 모드). `[t:]`는 쓰지 않는다
- 내부 주소 · 서버 경로 · tmux 이름처럼 바깥 독자에게 뜻 없는 것, 프롬프트 · 대화 원문 긴 인용은 넣지 않는다
- 화면 사진은 `tools/screen.py`로 세션이 직접 찍고 `![설명](img/<NN>_<주제>_<무엇>.png)`로 단다 — 게시할 때 Notion에 파일로 올라간다. 찍은 뒤 비밀값 · 다른 프로젝트 글이 없는지 본다
- 다른 주제 글과 겹치면 다시 쓰지 않고 `→ 「제목」`으로 가리킨다

## 4. 문체

- **반말 평서문(-다)**. 화면에 뜨는 글(툴팁 · 안내 · 확인 창 · 서버 거부 사유)만 "~습니다"(CLAUDE.md)
- 결론을 먼저, 굵게. 이유는 그 뒤에. 문장은 짧게
- 긴 문단 대신 목록. 한 줄에 사실 하나. 두세 단계까지 들여 쓴다
- **근거를 바로 단다** — 숫자 · 커밋 · 경로
  - 회고와 서기가 쓰는 글은 문장 끝에 근거 표시: `[c:e223f2e]`(커밋) · `[t:5871]`(턴 id) · `[log:stage11_roles_result.md]` · `[docs:12_scribe.md]`
  - 브리지가 표시가 실제로 있는지 확인한다(12b). 표시 없는 주장은 쓰지 않는다
- **한 것과 안 한 것을 정직하게**: "시험만 통과했다", "실제 화면은 보지 못했다", "돌려 보지 않았다"
- 사용자가 정한 것은 `(11-06 사용자 결정)`과 함께 원문 한 줄을 인용한다
- **쓰지 않는 것**
  - 과장 — "혁신적", "완벽하게", "획기적으로"
  - 근거 없는 수치 — 숫자는 DB · git · 측정 파일에서 온 것만
  - 일반론 회고 — "소통이 중요했다", "많이 배웠다"
  - 설계 문서의 시간순 서술 — "이렇게 했다 → 수정 → 다시 수정". 변경 이력은 「시도했던 것들」로 모은다
  - 영어 진행 글 — 문서 · 진행 글 모두 한국어(코드 · 명령 · 경로 · 로그는 원문 그대로)

## 4-1. 화면 글 (툴팁 · 버튼 · 띠 · 확인 창 · 거부 사유 · 텔레그램)

- **겉은 쉽게, 호버는 친절하게**(11-09 사용자). 버튼 · 칩 · 띠는 처음 보는 사람도 아는 말로 짧게, 숫자 · 내부 이름(id · pid · tmux 창)은 호버로 [log:cross_paste_20261109.md]
  - 예: "▶ 턴 나 · 10분 전 시작" → "▶ 작업 중 · 10분째"(무엇으로 시작했는지는 호버), "5h · 주 · ~" → "5시간 · 주간 · 약"
  - "서브에이전트" · "CC"는 바꾸지 않는다. 진행 줄에 "(내 요청)"을 붙이지 않는다(사용자)
    - **다른 말로 풀어 쓰는 것도 바꾸는 것이다**(11-09 사용자). "일꾼" · "AI" · "세션이 일을 나눠 맡긴 …" · "세션 기록"(CC 세션 ID 대신)처럼 새로 쓰지 않는다 — 11-09 감사에서 "그대로"라는 지시를 받고도 고쳐 쓰는 문장 안에 "AI"를 새로 넣었고, 처음부터 있던 "일꾼"은 감사 대상이 아니라 남았다. 화면 글을 고친 뒤 `일꾼|\bAI\b|디스패` 를 찾아본다
- **무엇인지 이미 분명한 화면에는 설명 줄을 붙이지 않는다**(11-10 사용자 — "터미널이라는 게 이미 분명하다. 매번 설명할 필요 없다"). 그날 터미널 막대의 「사람이 직접 치는 셸 · 승인 정책 없음 · 친 명령은 비밀값을 가려 기록」 줄을 뺐다
- **지금 눌러야 하는 버튼은 `primary`**(11-09 사용자 — "어디를 눌러야 하는지 바로 보이게"): 채운 색 · 굵게 · 테두리 빛(`panel.css` `button.primary`, 그것이 끝내기 · 지우기면 `primary danger`로 빨강). **한 줄에 하나만**, 옆의 [멈추기] · [취소] · [나중에]는 `ghost`. 긴 글 아래 버튼 줄은 `.flow-act`처럼 아래에 붙여 묻히지 않게
  - 승인 카드의 [승인]은 `primary`로 하지 않는다 — 판단을 물을 때 한쪽을 밀면 읽지 않고 누른다
- **창은 중요한 것만 먼저, 나머지는 [자세히]로 접고 접힌 줄에 지금 값을 한 줄로**(11-09 사용자 — "칸이 8개에 체크박스에 긴 글까지 한 화면에"). 긴 목록은 "N개"로 접는다. 내부 처리 기록(LLM 제안을 다듬은 것 등 사람이 할 일이 없는 것)은 화면 경고에 올리지 않고 로그로. 본보기: 계획 창 — 프로젝트 · 방식 · 이름 · 넣을 첫 글만, 역할 · 모델 · 보낼 세션 · 읽기 전용 · worktree는 [자세히], 노트 제안은 개수만 [log:plan_dialog_escape_retry_20261109.md]
- **대기 · 멈춤 글에는 푸는 곳을 넣는다**(11-09 사용자 — "배포 승인 기다림"이 FOREMAN 안에서 승인할 것처럼 읽혔다). FOREMAN 밖에서 푸는 것은 그 이름과 링크로: "⏸ 배포 대기 — ArgoCD에서 Sync를 눌러야 올라갑니다 ↗"(배너 줄을 누르면 ArgoCD 앱 화면), 짧은 칸은 "ArgoCD Sync 대기". FOREMAN 안에서 푸는 것(승인 · 질문)은 "멈춤 — 승인 대기 N"처럼 "멈춤"으로 시작한다. 종류가 다른 대기를 같은 말로 쓰지 않는다
- **그림과 글 상자는 겹치지 않는다**(11-09). 한 방(⌂ 감독실 포함)은 그 방만 그린다 — 방 사각형 밖은 배경. 방의 경고는 탭 줄 바로 밑 배너(폭 전체, 넘치면 줄바꿈)이고 방은 그 아래에서 시작한다 — 배너가 없으면 방이 탭 밑에 붙는다. 현장 카드는 **[전체]** 화면에서 각 방 바로 아래 한 줄에 두 줄(이름 · 지금 상태: 작업 중 N / 멈춤 — … / 쉼 / 세션 없음), 같은 높이, `…`로 자르지 않고 줄을 바꾼다. 토큰 · Opus · 최근 사용량은 카드 호버로. 점검은 `window.office.cardAudit()` · `bannerAudit()`
- **화면 이름을 탭 글자로 말한다**(11-09 — "감독실 카드"를 [⌂] 화면으로 알아듣고 [전체] 화면을 고치지 않았다). 보고 · 기록에는 [⌂] · [전체] · [런슈즈]처럼 탭 글자를 쓴다
- **사람이 해야 풀리는 대기는 "쉼"이 아니다**(11-09): 패널 칩 "권한 거부"(CC 자체 auto mode 거부 — 승인 카드로 안 온다) · "답 기다림"(마지막 응답이 묻고 끝남), 방 배너 "✋ 권한 거부 N — …" · "💬 답 기다림 N — …", 카드 "멈춤 — …". 사람이 다시 입력하면 풀린다
- **글씨는 본문 16px를 기준으로, 모든 화면(머리 · 내용 · 창)이 글씨 배율(`--ui-zoom`, [가−] · [가+])을 따른다**(11-09). 배율은 80~110% · 5씩, 처음 90%(11-10 — 브라우저 100% 기준). 범위 · 처음 값은 `js/uiscale.js` `STEPS` · `DEF` 하나이고, CSS는 `var(--ui-zoom)`만 쓴다(처음 값은 `panel.css` · `usage.html`의 `:root` 한 줄) 보조 글 14 · 표 15 · 제목 18, 한글은 낱말 단위 줄바꿈(`word-break: keep-all`). 새 화면 · 창을 만들면 배율이 걸리는지 본다 — /usage 내용과 [+ 세션] 창이 배율을 받지 않아 고쳤다(`5c93b2b` · `0cba431`)

  - **"쌓인 대화 N%" ↔ "한도"는 이름을 나눈 것이다**(11-09) — 둘 다 %라 헷갈렸다. 세션 대화 크기는 "쌓인 대화", 계정 한도는 "한도"로만 쓴다. 한도 칩 호버 첫 줄: "한도 — 구독 사용 한도를 몇 % 썼는지입니다. 세션마다 쌓인 대화 %(패널 머리줄)와는 다릅니다." [log:foreman-2_screen_ctx_switch_overlap_20261109.md]

  - 화면에는 "디스패처"를 쓰지 않는다(11-09 사용자 — "디스패처가 뭔지 모르면 아무 도움이 안 돼"). 감독실 캐릭터 설명은 하는 일로: "뭘 할지 말하면 계획을 세워줍니다. 어느 프로젝트에서, 새 세션으로 할지 기존 세션에 붙일지, 무엇을 읽어야 하는지를 정해서 보여줍니다. 확인하면 세션이 뜹니다."
  - 텔레그램 · 서버 거부 사유도 화면 글이다
- **툴팁 글 약속**: `제목 — 설명\n숫자줄\n숫자줄`(`bridge/static/js/tip.js` `textTip`)
  - 첫 줄의 ` — ` 앞은 굵은 제목, 뒤는 설명. 쓰는 쪽은 설명 안에 `\n`을 넣지 않는다(`\n` 뒤는 숫자 줄이 된다)
  - **보이는 모양(11-09)** [log:tips_and_credit_signal_20261109.md]
    - 설명은 **문장마다 줄을 바꾼다**(`splitSentences` — `다.` · `요.` · `죠.` · `?` · `!` 뒤 공백에서 나눔). 문장 안은 낱말 단위(`keep-all`) + `text-wrap: pretty`. ~~설명 안에서는 줄을 바꾸지 않는다~~(11-09 바뀜 — 긴 한 문단이 "넘쳐 쓸 / 크레딧이"처럼 뜻 가운데서 끊겼다)
    - 숫자 줄(구분선 아래)은 한 줄에 하나씩 쓰되, **넘치면 줄을 바꾸고 이어지는 줄은 들여 쓴다**(`.tip-n > div`). ~~`nowrap` + `…`로 자름~~(11-09 바뀜 — 모든 툴팁에서 "11월 10일 …"처럼 잘렸다)
    - 띄어쓰기 없는 긴 글(경로 · 명령 · 주소, 16자 넘는 낱말)은 `/ _ - . = , : ?` 뒤에서만 끊는다(`softEsc`가 `<wbr>`를 넣는다)
    - 폭 제한 `min(440px × 글씨 배율, 화면 폭 − 16px)`. 높이 제한은 없고, 화면보다 높으면 폭을 화면 폭까지 넓힌다(`fit`)
    - 예: `사용량 — 구독 한도를 몇 % 썼는지입니다.\n5시간 51% — 02:10 리셋\n주간 5% — 11월 15일 22:00 리셋`
  - **점검 `window.office.tipAudit()`** — 지금 화면의 모든 호버 글(버튼 · 패널 `data-tip`/`title` · 캔버스 칸 · 캐릭터)을 실제 툴팁 상자에 넣어 넘침 · 낱말 끊김(끊을 자리 없이 줄 폭보다 긴 낱말) · 화면보다 큼을 센다. `tools/screen.py`가 화면마다 기본으로 센다(`docs/operations.md` 「3. 돌리기 · 확인」) [log:tips_and_credit_signal_20261109.md]
  - `title`은 붙는 순간 `data-tip`으로 옮겨진다(브라우저 기본 툴팁과 둘이 뜨지 않게). 꺼진 버튼만 기본 툴팁
