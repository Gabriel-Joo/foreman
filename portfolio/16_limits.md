# 알려진 한계

> 이 글은 FOREMAN을 만들며 고른 결정과, 그 결정 때문에 하지 못하게 된 것을 다룹니다.

**앞의 편들은 화면 하나씩 무엇을 해 주는지를 보였습니다. 한계는 화면으로 나눌 수 없어서, 이 편만은 결정으로 묶었습니다. 결정마다 무엇을 왜 골랐는지와 그 값으로 치른 것을 적습니다. 끝의 하나는 고른 것이 아니라 바꿀 수 없는 조건입니다. 자세한 까닭은 기술문서의 알려진 한계 편에 있습니다.**

## 1. 관제 화면을 인터넷에 열지 않았습니다

FOREMAN 화면에는 서버 셸, 세션에 글을 넣는 칸, 명령을 허락하는 버튼이 있습니다. 이 화면이 한 번 뚫리면 화면 하나를 내주는 것이 아니라, 네 저장소 전부에 올리기(push)와 위험한 명령 통과와 비밀값이 든 설정까지 내주게 됩니다. 다른 서비스는 뚫려도 그 서비스 하나에서 끝나지만 여기는 나머지 전부로 번집니다. 그래서 인증 관문을 앞에 두는 데서 그치지 않고 아예 열지 않았고, 밖에서 필요한 소식은 텔레그램으로 받습니다 [docs:00_design.md] [log:foreman-5_todo_collect_20261117.md]. 같은 서버의 다른 서비스들은 이미 밖에 열려 있으니, 못 해서가 아니라 따져 보고 열지 않은 것입니다.

치른 값은 이렇습니다.

- 화면은 서버 PC 앞에서 보거나 SSH로 붙은 사람만 엽니다
- 텔레그램은 알리기만 하고 답을 받지 않습니다. 승인이나 계획 시작은 텔레그램에서 누를 수 없습니다
- 알림에 붙는 링크는 서버 PC 안의 주소라, 휴대폰에서 누르면 열리지 않습니다 [log:wake_link_20261115.md]

## 2. 사람에게 묻는 것은 되돌릴 수 없는 명령뿐입니다

FOREMAN이 띄우는 세션은 Claude Code의 auto mode(세션이 묻지 않고 스스로 판단해 진행하는 모드)로 돕니다. 사람이 매번 허락을 누르면 여러 세션을 동시에 돌리는 의미가 없기 때문입니다. 브리지(FOREMAN의 서버 프로그램)는 통째로 지우기나 강제 push처럼 사람이 실제로 거부할 만한 명령에 걸릴 때만 사람에게 묻게 합니다 [code:config/approval.toml]. 브리지가 꺼져 있을 때는 아무것도 돌려주지 않아 Claude Code가 원래대로 스스로 정합니다. 브리지 장애가 모든 세션을 멈추게 하면 안 되기 때문입니다 [code:scripts/foreman-decide.sh].

치른 값은 이렇습니다.

- 브리지가 꺼진 동안은 묻기로 한 명령도 auto mode의 판단에 맡겨집니다. 허용 쪽으로 새지는 않지만 꼭 물어 준다고 할 수는 없습니다 [log:stage5_approval_result.md]
- 화면 카드는 한 시간까지만 답을 기다립니다. 사람이 화면을 계속 보지 않는다는 사용자 판단(2026-11-06)으로 정한 길이이고, 지나면 Claude Code 창에서만 답합니다 [code:config/approval.toml]
- 규칙으로 묻게 하는 것은 FOREMAN과 인프라 세션입니다. 런슈즈, 펫퍼민트는 관찰로 시작해 결과를 보고 바꾸기로 한 사용자 결정(2026-11-02)에 따라 기록만 남깁니다 [code:config/approval.toml]

## 3. 사람이 직접 치는 것은 승인 카드를 거치지 않습니다

세션 패널의 `!` 명령, 셸 패널, 세션 화면 창은 사람이 직접 치는 길입니다. 사람이 Claude Code 창 앞에 앉아 치는 것과 같다고 보고 승인 카드에 올리지 않았습니다. 다만 `!` 명령은 세션이 쳤다면 물었을 명령이면 보내지 않습니다 [code:bridge/inject.py].

치른 값은 이렇습니다.

- 셸 패널에서 친 명령은 묻지 않고 실행됩니다(→ 「셸 패널」)
- `!`로는 암호를 물어 멈추는 `sudo`와, 사용자 결정(2026-11-09)에 따라 여러 줄 명령을 보내지 않습니다
- 세션 화면 창은 열고 닫은 때만 남기고 친 키는 남기지 않으며, 키에 제한을 두지 않습니다(→ 「세션 화면 창」)

## 4. 교장은 부를 때만 뜨고, 겹쳐도 막지 않습니다

교장은 늘 떠 있는 세션이 아닙니다. 사람이 말을 걸 때마다 AI 모델을 한 번 불러 계획 하나를 받고 끝나며, 파일을 읽을 수만 있습니다. 세션은 사람이 [이대로 시작]을 눌러야 뜹니다. 같은 일을 하는 세션이 있거나 맡을 파일이 겹치면 알리지만 막지는 않습니다. 일부러 나눠 시킬 수 있기 때문입니다 [docs:11_foreman_dispatch.md] [code:bridge/overlap.py].

치른 값은 이렇습니다.

- 교장은 세션을 스스로 띄우지 않고, 문서로 볼 수 없는 것(지금 도는 프로세스, 시험 결과)은 관리자가 따로 봅니다
- 겹침 경고를 읽고 정하는 것은 끝까지 사람 몫입니다(→ 「교장 계획 창과 감독실」)

## 5. 도구 결과 본문을 남기지 않습니다

세션이 도구를 쓴 결과(파일 내용, 명령 출력)는 데이터베이스에 넣지 않습니다. 양이 크고, 모양을 알 수 없는 비밀값이 섞일 수 있기 때문입니다. 비밀값을 가리는 장치가 있어도 모르는 모양은 놓치므로, 가장 위험한 곳은 아예 담지 않는 쪽을 골랐습니다 [code:bridge/assembler.py] [log:stage2_transcript_result.md]. 본문이 필요하면 Claude Code가 남긴 대화 기록 파일에서 그때 읽어 옵니다.

치른 값은 이렇습니다.

- 대화 기록 파일이 지워진 뒤(기본 120일)에는 도구 결과 본문을 볼 수 없습니다(→ 「세션 패널: 대화와 활동」)

## 6. 조건: 물리 서버 한 대, 다 볼 수 없는 사용량

이것은 고른 것이 아니라 바꿀 수 없는 조건입니다. FOREMAN은 물리 서버 한 대 위에 있어 서버가 죽으면 화면, 기록, 세션이 함께 멈춥니다. 그래서 화면과 기록 수집을 나눠 띄워도 얻는 것이 없어 하나로 두었습니다 [docs:00_design.md]. 서버 한 대라는 조건이 무엇을 묶는지는 인프라 기술문서의 알려진 한계 편에 자세히 있습니다. 사용량도 다 볼 수 없습니다. Anthropic은 한도를 토큰 수로 밝히지 않고, FOREMAN은 이 PC의 Claude Code만 봅니다 [code:bridge/usage.py].

- 서버가 죽으면 모든 것이 함께 멈춥니다
- 웹이나 앱, 다른 PC에서 쓴 양은 보지 못해, 한도는 「적어도 이만큼」인 하한으로만 구합니다(→ 「사용량 화면」)
