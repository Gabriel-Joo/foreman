# 승인 카드

> 이 글은 세션이 되돌릴 수 없는 명령을 하려 할 때 화면에 뜨는 승인 카드와, 그 카드가 사람에게 무엇을 보여 주고 어떻게 답을 받는지를 다룹니다.

**세션은 대부분의 일을 묻지 않고 스스로 합니다. FOREMAN 세션이 규칙으로 사람에게 묻는 것은 통째로 지우기, 강제 push, 운영 데이터베이스 지우기처럼 되돌릴 수 없는 명령뿐입니다. 그런 명령이 걸리면 그 세션 패널의 제목 줄 아래에 승인 카드가 뜨고, 카드 둘째 줄에 「이 명령이 무엇을 대상으로 하는지」가 한 줄로 보입니다. 사람은 카드나 그 세션의 Claude Code 창 중 편한 곳에서 답하고, 먼저 답한 쪽이 정합니다.**

![승인 규칙에 걸린 명령이 기다리는 모습입니다. 픽셀 화면의 그 세션 캐릭터 머리 위에 ❗가, 화면 머리줄과 방 이름 아래에 「승인 대기 1」이 뜨고, 오른쪽 패널의 제목 줄 아래에 승인 카드가 있습니다. 카드는 어느 프로젝트의 몇 번 세션인지, 무슨 도구인지, ▶ 대상 한 줄, 접힌 「명령 전체」, 걸린 까닭, [승인] [거부] [세션] 단추로 되어 있습니다. 걸린 규칙은 그때 시험용으로 넓게 잡았던 것이라 지금 규칙으로는 묻지 않는 명령입니다 〔실제 기록 재생, 승인 시스템 시험 때의 실제 승인 한 건〕](img/05_approval_card.png)

FOREMAN이 띄우는 세션은 Claude Code의 auto mode(세션이 도구를 쓸 때마다 사람에게 묻지 않고 스스로 판단해 진행하는 모드)로 돕니다. 계획만 세우는 계획 모드로 띄운 읽기 전용 세션만 예외입니다. 사람이 매번 「허락」을 누르면 여러 세션을 동시에 돌리는 의미가 없기 때문입니다. 대신 브리지(FOREMAN의 서버 프로그램)가 세션이 도구를 부르기 직전마다 그 호출을 받아 봅니다. 대부분은 그냥 통과시키고, 정해 둔 위험한 명령에 걸릴 때만 Claude Code에 「사람에게 물어라」라고 돌려줍니다. 그러면 Claude Code는 auto mode 중에도 자기 창에 승인 창을 띄우고, 브리지는 같은 순간 화면에 승인 카드를 띄우고 텔레그램으로 알립니다 [code:bridge/approvals.py] [log:stage5_approval_result.md]. 이렇게 규칙으로 묻게 하는 것은 지금 FOREMAN과 인프라 프로젝트 세션입니다. 런슈즈, 펫퍼민트 세션은 같은 규칙에 걸려도 기록만 남기고 Claude Code에 판정을 돌려주지 않습니다 [code:config/approval.toml]. 다만 Claude Code가 스스로 판단해 승인 창을 띄울 때는 네 프로젝트 모두 같은 승인 카드와 텔레그램 알림이 붙습니다.

## 무엇을 묻나

묻는 기준은 「위험해 보이는 것」이 아니라 「사람이 실제로 거부할 만한 것」입니다. 규칙은 설정 파일 하나에 모여 있고, 앞에서 말한 대로 그 판정대로 묻는 것은 FOREMAN과 인프라 프로젝트 세션입니다. 대표적인 것은 홈 폴더, 프로젝트 하나, 데이터 볼륨 하나를 통째로 지우는 것, 운영 쪽 데이터베이스에서 테이블이나 데이터베이스를 지우는 것, 서버 재부팅과 종료와 가상 머신 파괴, `git reset --hard`나 강제 push처럼 작업 이력을 날리는 것, 비밀값이 든 파일을 `curl`이나 `scp`로 밖에 보내는 것, 쿠버네티스 네임스페이스나 저장 볼륨처럼 지우면 데이터가 사라지는 자원을 지우는 것입니다. 그 밖에 Claude Code 세션이나 tmux를 한꺼번에 끄는 것, 인터넷에서 받은 스크립트를 바로 셸에 넣어 실행하는 것 등도 묻습니다. 파일을 고치거나 서비스를 다시 띄우는 것처럼 되돌릴 수 있는 일은 묻지 않고 통과시킵니다 [code:config/approval.toml] [code:bridge/approval.py].

같은 `rm -rf`라는 글자라도 실제로 실행되는 것과 글로 적히는 것은 다르게 봅니다. 셸이 실행하는 명령에 들어 있으면 묻고, 메모 파일에 적거나 커밋 메시지에 쓰기만 하면 통과합니다. 대신 그렇게 파일에 적어 둔 스크립트를 나중에 실행하는 순간 그 파일 내용을 읽어 다시 검사하므로, 파일에 숨겨 돌아가는 길도 막힙니다 [code:bridge/approval.py] [c:6cffabb]. 이 다시 검사는 셸에 바로 친 명령과 같은 기준으로 합니다. 실행하는 스크립트든, 여러 줄 글을 통째로 셸에 넘겨 실행하는 경우든, 그 안의 명령 하나하나를 똑같이 판정합니다. 지울 경로가 글에 다 적혀 있지 않고 「지금 있는 폴더」처럼 실행할 때 정해지는 경우에도, 그 경로를 풀어 보아 통째로 지우기면 묻고, 끝내 무엇을 지울지 확정할 수 없으면 역시 묻습니다. 다만 변수가 든 평범한 경로는 변수 앞의 고정된 부분과 변수가 비었을 때 남는 경로만 보아, 어느 쪽도 통째로 지우기가 아니면 묻지 않습니다.

## 카드 꼴과 요약 한 줄

카드 첫 줄은 「🔐 프로젝트 · [역할] 세션 번호 · 도구」입니다. 어느 세션이 묻는지 먼저 보여 주어, 여러 세션이 동시에 돌 때 헷갈리지 않게 합니다. 둘째 줄 ▶ 뒤가 이 카드의 핵심인 요약 한 줄입니다. 명령 전체는 길고 읽기 어려워서, 판단에 필요한 「무엇을 대상으로 하나」만 뽑아 보여 줍니다. 예를 들면 이렇습니다 [code:bridge/approval_summary.py] [c:4ced99a].

| 걸린 명령 | 카드의 요약 한 줄 |
|---|---|
| 폴더를 통째로 지움 | `rm -rf → …/volumes (기존 디렉토리, 파일 1,234개)` |
| 쿠버네티스 자원 삭제 | `kubectl delete → pod/jenkins-0 (jenkins 네임스페이스)` |
| 데이터베이스 삭제 | `DROP DATABASE … (컨테이너 …)` |

지우는 대상이 이미 있는 폴더면 안에 든 파일 수도 셉니다. 「파일 3개」와 「파일 1,234개」는 같은 명령이라도 판단이 달라지기 때문입니다. 다만 브리지는 몇 초 안에 Claude Code에 답해야 하므로, 세기는 0.3초 안에서만 하고 그 안에 다 못 세면 숫자 뒤에 「+」를 붙입니다. 요약은 규칙 이름이 아니라 명령을 보고 만들므로, 우리 규칙이 아니라 Claude Code가 스스로 묻는 승인 창에도 같은 꼴로 붙습니다. 같은 요약 한 줄이 텔레그램 알림, Claude Code 창의 승인 창, 승인 기록에도 똑같이 쓰입니다. 원래 명령이 궁금하면 카드의 「명령 전체」를 펼치면 되고, 그 아래 작은 글로 어느 규칙에 왜 걸렸는지가 적힙니다.

## 어디에 뜨고 누가 답하나

카드는 그 세션의 패널에만 뜹니다. 다른 세션이 기다리는 것은 지금 보는 패널의 카드 자리 끝에 「다른 세션 승인 대기 N」 한 줄로만 보이고(질문은 「질문 N」으로 따로 셉니다), 펼치면 어느 세션의 무슨 요청인지와 [세션 열기]가 나옵니다. 답은 그 세션 패널에 가서 합니다. 엉뚱한 프로젝트를 보다가 무심코 다른 세션의 요청에 답하지 않게 하려는 것입니다. 기다리는 승인이 있으면 화면 머리줄에 「승인 대기 N」이, 픽셀 화면의 그 캐릭터 머리 위에 ❗가 떠서 패널을 열지 않아도 알 수 있습니다 [code:bridge/static/js/render.js].

답하는 곳은 둘입니다. 화면 카드의 [승인]이나 [거부]를 누르거나, 그 세션의 Claude Code 창에 이미 떠 있는 승인 창에서 고르면 됩니다(브라우저 안에서 그 창을 보고 고르는 길은 → 「세션 화면 창」). 둘 중 먼저 답한 쪽이 정하고, 나머지 쪽은 저절로 닫힙니다. Claude Code 창에서 먼저 답하면 브리지가 대화 기록에서 그 도구의 결과가 온 것을 보고 기다림을 풀고, 카드에는 그쪽에서 답했다고 적습니다. [거부]를 누르면 거부 까닭을 묻는 칸이 뜨고, 적은 글은 그대로 세션의 모델에게 전해져 다른 방법을 찾게 합니다. 텔레그램은 알림만 보냅니다. 「🔐 승인 대기」와 요약 한 줄, 명령, 걸린 규칙을 보내 화면을 보고 있지 않은 사람을 부르고, 답은 화면이나 Claude Code 창에서 합니다 [code:bridge/approvals.py] [code:bridge/api/approvals.py].

브리지가 화면 답을 기다리는 시간은 한 시간입니다. 그동안 아무도 답하지 않으면 텔레그램으로 「⏰ 승인 대기 시간이 지났습니다」를 한 번 더 보내고 화면 카드를 닫습니다. 그 뒤로는 Claude Code 창의 승인 창에서만 답할 수 있습니다. 브리지가 꺼져 있을 때는 아무것도 돌려주지 않아 Claude Code가 원래대로 스스로 정합니다 [code:config/approval.toml] [log:stage5_approval_result.md]. 그동안 무엇을 잃는지는 → 「알려진 한계」에 모았습니다.

![승인 요청이 떴다가 처리되는 모습입니다. 캐릭터 머리 위에 ❗가 뜨고 패널에 카드가 나타났다가, [승인] 뒤에는 카드가 「✓ 허용함 ▶ rm -r junk-a — 시험용 폴더 지우기」 한 줄로 접히고 세션이 다시 일합니다 〔실제 기록 재생, 승인 시스템 시험 때의 실제 승인 한 건〕](img/05_approval_flow.gif)

답한 카드는 그 세션 패널에서 「✓ 허용함」이나 「✕ 거부함」 한 줄로 접힙니다. 누르면 다시 펼쳐 전체를 보고, 끝의 [×]로 치웁니다. 치워도 답은 [세션 정리] 탭의 「승인 기록」에 남습니다. 이 「승인 기록」을 펼치면(클래식 대시보드에서는 같은 표가 「승인 이력」이라는 이름입니다) 기간별로 어느 규칙이 몇 번 걸렸고 몇 번 승인, 거부했는지를 표로 보여 주고, 매번 허락만 한 규칙에는 「늘 허락함, 묻지 않게 바꿀 후보」라고 표시합니다. 묻는 규칙을 계속 좁혀 가는 근거가 되는 표입니다 [code:bridge/static/js/render.js].

## 질문 카드

세션이 일하다가 사람에게 고를 것을 물을 때(Claude Code의 질문 도구)도 같은 자리에 카드가 뜹니다. 이때는 승인이 아니라 ❓ 질문 카드이고, 질문과 선택지가 단추로 나옵니다. 선택지를 누르면 그 답이 세션에 바로 들어가고, 답과 함께 보낼 글을 적을 칸도 있습니다. 답한 질문은 「✓ 답함 「질문」 → 고른 답」 한 줄로 접힙니다 [code:bridge/static/js/render.js] [c:650f0a0].
