# 텔레그램 알림

> 이 글은 FOREMAN이 휴대폰 텔레그램으로 보내는 알림, 곧 언제 무엇을 보내고 무엇을 모았다가 보내는지를 다룹니다.

**화면 앞에 없어도, AI 세션이 일을 마쳤거나 사람의 답을 기다리거나 무언가가 조용히 망가졌을 때 휴대폰으로 알려 줍니다. 급하지 않은 것은 모아 두었다가 저녁 9시에 한 통으로 보냅니다.**

![감독실 — 맨 위 현황판에서 런슈즈 칸이 빨갛고(빌드 실패), 팀장 머리 위에 「시작할 일 1」이 떠 있습니다. 실패가 부른 「살펴볼 계획」이 사람의 [시작]을 기다리는 표시이고, 텔레그램에는 같은 계획이 [시작] 링크와 함께 갑니다 〔시연 재생 — 실패와 계획은 시연 값〕](img/15_telegram_suggest.png)

FOREMAN 화면은 여러 세션을 한꺼번에 보여 주지만, 사람이 늘 그 앞에 앉아 있지는 않습니다. 세션이 일을 끝냈는지, 승인을 기다리느라 멈춰 있는지, 빌드가 깨졌는지를 화면에만 띄우면, 자리를 비운 동안에는 아무도 모르는 채로 시간이 흐릅니다. 그래서 FOREMAN은 사람이 봐야 할 일이 생기면 텔레그램 봇으로 휴대폰에 보냅니다. 알림을 보낼지 말지는 AI 모델이 판단하지 않습니다. 브리지(FOREMAN의 서버 프로그램)가 세션의 턴(사람이나 다른 쪽이 넣은 입력 하나에 세션이 응답을 마치기까지의 한 덩어리)이 닫히는 순간이나 실패를 알아챈 순간에, 설정 파일의 규칙대로 기계적으로 보냅니다. 예전에는 모델이 지시문을 읽고 알림 스크립트를 부르게 했는데, 그때는 알림이 빠지는 일이 있었고, 빠진 것이 규칙대로 안 보낸 것인지 그냥 누락인지 가를 수도 없었기 때문입니다 [code:bridge/notify.py] [code:config/notify.toml] [log:stage4_notify_result.md].

텔레그램 화면은 FOREMAN 안에 없어 사진을 찍지 않았습니다. 이 글의 사진은 알림이 가리키는 FOREMAN 화면 쪽이고, 알림 글의 꼴은 코드에 있는 글 그대로 아래 표에 옮겼습니다.

## 턴이 끝날 때

세션의 턴이 닫히면 브리지가 그 턴이 어떻게 끝났는지에 따라 제목을 다르게 붙여 보냅니다. 정상으로 끝났으면 「끝남」, API 오류로 멈췄으면 「⚠ API 오류로 멈춤」, 사람이 중단했으면 「⏹ 중단됨(사용자)」, 턴이 진행 중일 때 세션이 끝났으면 「세션 종료」, 프로세스가 끝 신호 없이 사라졌으면 「⚠ 프로세스가 사라짐」입니다. 제목 뒤에는 걸린 시간이, 그 아래에는 무엇을 시켰는지 첫 줄이 붙고, 정상으로 끝난 턴이면 응답 첫 줄이, API 오류로 멈춘 턴이면 오류 첫 줄이 더 붙어서 휴대폰 알림만 보고도 어떤 일이 어떻게 끝났는지 알 수 있습니다. 서브에이전트(세션이 일을 나눠 맡긴 보조 AI)는 하나하나 알리지 않고, 세션 턴이 끝날 때 몇 개가 끝났는지 한 줄로 요약합니다. 세션이 서브에이전트를 뒤에서 돌려 둔 채 턴을 끝냈다면, 그 서브에이전트가 모두 끝났을 때 한 번 묶어 보냅니다 [code:bridge/notify.py].

알림은 프로젝트마다 앞머리(「[런슈즈]」, 「[펫퍼민트]」, 「[FOREMAN]」, 「[인프라]」)가 붙고, 턴 끝 알림은 앞머리가 정해진 프로젝트의 세션만 보냅니다. 승인 대기나 인계 실패처럼 아래의 바로 가는 알림은 어느 프로젝트에도 속하지 않는 세션이어도 「[미분류]」를 달고 갑니다. 프로젝트마다 규칙을 달리 줄 수도 있어서, 펫퍼민트는 5분 안에 끝난 짧은 턴은 보내지 않습니다(실패는 예외). 보낸 알림과 보내지 않은 알림은 모두 까닭과 함께 DB 알림 기록에 남습니다. 알림이 안 왔을 때 「안 보낸 것」인지 「보내다 실패한 것」인지를 나중에 가를 수 있게 하려는 것입니다 [code:config/notify.toml] [code:bridge/notify.py].

## 바로 가는 알림

어떤 알림은 기다리면 안 됩니다. 아래 것들은 생기는 순간 바로 나갑니다.

| 언제 | 알림 첫 줄(앞머리 뒤) |
|---|---|
| 세션이 승인을 기다린다 | `🔐 승인 대기 · Bash` 다음 줄에 무엇을 하려는지, 규칙, 몇 분 뒤 화면 승인이 닫히는지 |
| 세션이 사람에게 묻는다 | `❓ 세션이 묻습니다 — 답을 기다립니다` 다음 줄에 물음과 선택지 |
| 승인 대기 시간이 지났다 | `⏰ 승인 대기 시간이 지났습니다 · Bash` |
| 파이프라인 단계가 실패했다 | `❌ 파이프라인 실패 · Jenkins 빌드 · Test` 다음 줄에 커밋과 그 커밋을 만든 세션 |
| push 뒤 빌드가 시작되지 않았다 | `⚠ 빌드 알림 없음 — push … 뒤 17분째 Jenkins 시작 알림이 없다. Jenkins 확인` |
| Jenkins, Harbor, ArgoCD가 응답하지 않는다 | `⚠ Jenkins 응답 없음 — 연달아 5번(5분째, …)` |
| 세션 기록을 DB에 쌓는 일이 막혔다 | `⚠ 적재 막힘 — 세션 … N분째 같은 자리에서 실패` |
| 구독 한도에 가까워졌다 | `⚠ 주간 · 전체 사용량 약 80% — …` (95%면 🛑) |
| 관리자 세션이 사람의 답을 기다린다 | `❓ 관리자가 사용자 답을 기다립니다 · 세션 …` |
| 합치기 카드에 승인 규칙 파일이 걸렸다 | `⑂ 합치기 준비됨` 아래에 🛡 줄 |
| 합친 뒤 시험과 push 같은 관리자 몫을 관리자 세션에 전하지 못했다 | `관리자 세션이 없어 텔레그램으로 남깁니다` (전하다 실패했으면 `관리자 세션에 보내지 못해 텔레그램으로 남깁니다`) |
| 새 세션으로 옮길 인계 요약이 실패했다 | `⚠ 인계 요약 실패, 표지가 없습니다(원문은 패널에 있습니다)` (시간 초과, 기다리는 중에 세션이 끝남도 ⚠로 시작) |
| 압축으로 잊은 것 찾기나 대화 결정 문서에 적기가 실패했다 | `⚠ 압축으로 잊은 것 찾기 실패`로 시작 (문서에 적기는 `⚠ 대화 결정 문서에 적기`로 시작하고 목록 실패나 확인 실패를 적음) |
| 세션이 안전 규칙 파일을 고쳤다 | `🛡 안전 규칙 파일 수정` 뒤에 도구 이름, 다음 줄에 파일 경로 |
| 합치기로 안전 규칙 파일이 바뀌었다 | `🛡 안전 규칙 파일이 합치기로 바뀌었습니다` 뒤에 작업방 이름, 다음 줄에 파일 |
| 브리지 자신이 멈춰 다시 뜨지 못한다 | `브리지가 멈췄습니다(systemd가 다시 띄우기를 포기)` |

마지막 줄만은 브리지가 아니라 따로 둔 작은 스크립트가 보냅니다. 브리지가 죽으면 브리지 안의 알림도 함께 멈추므로, 서버의 서비스 관리자(systemd)가 브리지를 다시 띄우다 포기한 순간 그 스크립트가 바로 텔레그램으로 보냅니다. 앞머리는 늘 「[FOREMAN]」이고, 이 알림은 DB 알림 기록에 남지 않습니다.

표의 글은 코드에 있는 그대로이고, 「…」 자리는 그때의 세션 번호, 커밋, 시간 같은 값이 들어갑니다. 실패나 막힘을 알린 것은 대부분 회복될 때 「✅ 적재 회복」, 「✅ Jenkins 다시 응답」처럼 한 번 더 알려서, 문제가 아직 남아 있는지 휴대폰에서 바로 알 수 있습니다. 출하 라인의 실패 표시와 빌드 알림 없음은 → 「출하 라인」, 한도 알림은 → 「사용량 화면」, 승인 카드는 → 「승인 카드」에서 화면 쪽을 다룹니다 [code:bridge/notify.py] [code:bridge/pipeline.py] [code:bridge/approvals.py] [code:bridge/ingest_health.py] [code:bridge/usage.py] [code:bridge/api/dashboard.py].

## 21:00 하루 묶음

알림이 너무 많으면 사람은 알림을 보지 않게 됩니다. 세션 여럿이 하루 종일 턴을 끝낼 때마다 휴대폰이 울리면, 정말 봐야 할 실패 알림이 그 사이에 묻힙니다. 그래서 일상 알림은 바로 보내지 않고 모아 두었다가 매일 저녁 9시(한국 시간)에 프로젝트마다 한 통으로 보냅니다. 모으는 것은 정상으로 끝난 턴, 서브에이전트 묶음, 합치기 카드, 새 세션으로 옮기기 기록, 노션 문서 게시, 어긋남 알림입니다. 묶음 한 통은 「📦 하루 묶음 11-15 — 일상 알림 N건(급한 것은 그때그때 보냈습니다)」으로 시작하고, 종류별로 「■ 턴 끝 N건」 아래에 시각과 한 줄씩 늘어놓습니다 [code:bridge/notify.py] [code:config/notify.toml] [log:notify_relay_20261112.md].

묶음으로 미루는 종류여도 글에 ⚠, ❌, 🛑, ⏰, ❓ 가운데 하나가 있으면 바로 보냅니다. 턴이 API 오류나 중단으로 끝났거나, 프로세스가 사라졌거나, 진행 중에 세션이 끝났거나, 세션이 사람에게 묻는 말로 턴을 끝냈을 때도 바로 갑니다. 합치기 카드 알림도 대개는 묶음으로 가지만, 승인 규칙 파일이 바뀌어 🛡 줄이 붙었거나 관리자 세션에 전하지 못해 사람에게 넘기는 것이면 바로 갑니다. 새 세션으로 옮기기 기록 가운데 인계 요약, 압축으로 잊은 것 찾기, 대화 결정 문서에 적기가 실패했거나 시간이 지난 것은 글 앞에 ⚠를 달아 바로 보냅니다. 잊은 것 찾기가 끝났더라도 판정 묶음 일부가 실패했으면 같습니다. 실패는 묶어서 늦게 알 까닭이 없기 때문입니다. 묶음을 보내지 못하면 그 사실을 바로 알리고 10분마다 다시 보내며, 모아 둔 알림이 26시간 넘게 나가지 못하고 있으면 그것도 알립니다. 묶음 자체가 조용히 막혀 일상 알림이 통째로 사라지는 일을 막기 위해서입니다 [code:config/notify.toml] [code:bridge/notify.py].

묶음을 켠 프로젝트에서는 작업 세션의 턴 끝 보고가 사람에게 바로 가지 않고 먼저 그 프로젝트의 관리자 세션 입력 칸으로 갑니다. 관리자가 사람에게 올릴 것을 골라 보고로 올리면 그 보고는 저녁 묶음에 실리고, 물음으로 올리면 바로 갑니다. 화면에서는 관리자 머리 위에 「사용자에게 보고함」이나 「사용자 답 기다림」으로 같은 것이 보입니다(→ 「머리 위 표시와 띠」) [code:bridge/notify.py] [code:bridge/api/dashboard.py].

## [시작] 링크

빌드 실패, 빌드 알림 없음, 웹훅 끊김 의심, 인프라 응답 없음, 적재 막힘처럼 무언가가 망가졌다는 알림이 나가면, FOREMAN은 거기서 한 걸음 더 갑니다. 계획 세우기(어느 프로젝트에서 어떤 세션으로 무엇을 할지 AI가 계획을 짜 주는 기능)에 그 실패 알림을 넘겨 「이렇게 살펴보자」는 계획을 만들고, 그 계획을 텔레그램으로 한 번 더 보냅니다. 다만 적재 막힘 가운데 데이터베이스 연결이 잠깐 끊기거나 시간이 초과된 것은 기다리면 돌아오므로 계획을 세우지 않고 알림만 보냅니다. 이 알림은 「🧭 파이프라인 실패 — 이렇게 살펴보자는 계획을 세웠습니다」처럼 시작하고(「파이프라인 실패」 자리에는 「빌드 알림 없음」, 「적재 막힘」처럼 그때의 실패 종류가 들어갑니다), 세션 이름과 역할, 이유 한 줄을 적고, 맨 끝에 「[시작]? 계획을 보고 화면에서 눌러 주세요」와 링크를 붙입니다. 계획만 세울 뿐 세션을 띄우지는 않습니다. 사람이 화면에서 계획을 보고 [이대로 시작]을 눌러야 세션이 뜹니다 [code:bridge/wake.py] [code:config/wake.toml].

![[시작] 링크가 여는 창 — 맨 위에 「실패 이벤트가 부른 제안입니다」와 실패 한 줄, 「팀장이 계획만 세웠습니다. [이대로 시작]을 눌러야 시작합니다」가 있고, 아래에 프로젝트, 방식(새로 시작), 세션 이름, 넣을 첫 글이 채워져 있습니다 〔시연 재생 — 실패와 계획 내용은 시연 값, 창은 실제 화면 코드〕](img/15_telegram_plan.png)

링크는 FOREMAN 화면 주소 뒤에 그 계획 번호를 붙인 것이라, 열면 위 사진처럼 새 세션 창이 그 계획을 채운 채로 열립니다. 같은 계획은 화면에서도 기다리고 있습니다. 감독실 캐릭터 머리 위의 「시작할 일 N」이 그것이고, 캐릭터를 누르면 같은 창이 열립니다. 다만 FOREMAN 화면은 밖으로 열어 두지 않았으므로 링크 주소는 서버 PC 안의 주소이고, 알림 글도 「서버 PC 화면이나 ssh -L 8000:localhost:8000으로 엽니다」라고 함께 적습니다. 휴대폰에서 링크를 눌러 바로 열리는지는 이 글을 쓰며 확인하지 않았습니다. 같은 실패로는 12시간 안에 다시 계획하지 않고, 자동 계획은 하루 5번까지만 세우며, 그 수에 닿으면 그날 한 번 「다 썼습니다」를 알리고 나머지는 실패 알림만 보냅니다 [code:bridge/wake.py] [code:config/wake.toml] [docs:14_dispatcher_note_wake.md].
