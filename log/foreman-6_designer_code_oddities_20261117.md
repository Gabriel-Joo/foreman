## 2. 같은 종류로 더 찾은 것

- 위 주석 셋 말고 화면에 보이는 옛 말은 더 없었다. `디스패처`, `따로 작업`, `모든 세션이 멈`을 js, html, theme에서 찾았고 남은 것은 코드 주석뿐이다(style_guide가 코드 주석의 「디스패처」는 허용)
- `chainStage`(배송 담당이 설 단계)는 push 앞 실패를 이미 ① 빌드 실패로 둔다. 같은 판정 정규식을 `shipstate.js`에서 가져다 쓰게 해 두 곳이 어긋나지 않게 했다
- `render.js` `pipeBlock`(클래식 체인 줄)은 Harbor 기록이 없으면 「Harbor ·」(아직)로 그리고 ✓로 추정하지 않는다. 고칠 것 없음

## 3. 고치지 않은 것과 까닭

- **웹훅 끊김 의심과 빌드 알림 없음이 단계 실패와 같은 🔥 · ✕ 표시를 켜는 것(`siteState`)**: 의도로 본다. 이 프로젝트는 조용한 고장을 알리려는 것이고, 호버(`boardTip`)가 「파이프라인이 깨졌거나 빌드 알림이 끊겼습니다」라고 둘 다 말한다. 그대로 두었다. 포트폴리오 03편 37줄은 글에 「웹훅 끊김, 빌드 알림 없음도 같은 표시」를 한 줄 더하면 된다
- Harbor 단계 이름을 「매니페스트 · manifest · 배포 · deploy」로 본 것은 `log/stage8_cicd_result.md`의 Jenkinsfile 초안에서 가져왔다. 런슈즈와 펫퍼민트의 실제 Jenkinsfile은 이 저장소 밖이라 보지 못했다. 단계 이름이 다르면 「기록 없음」으로 떨어져 틀린 ✓는 나오지 않지만, push 뒤 실패인데 ✓가 아니라 비어 보일 수 있다
- 서버가 Jenkins 실패 때 `harbor` 단계를 따로 채우는지(파이썬 쪽)는 보지 않았다. 화면은 그것이 있으면 먼저 따른다
