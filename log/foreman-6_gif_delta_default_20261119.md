# GIF 바뀐 곳만 담기 기본 문턱을 40으로 (코더, 관리자 410 일감)

- 규칙 위반 있음(아래 「규칙 위반」)
- 시작한 main 커밋: `a7e0786`(`fix: 문서 도구가 한글 이름 파일을 덮기 밖으로 세던 것 고침`)
- `portfolio/img/`는 바꾸지 않았다. 만든 GIF는 스크래치에만 있다

## 1. 한 일

`tools/frames_to_gif.py --delta`의 기본 문턱을 120에서 40으로 바꿨다. 40은 디자이너 573이 실제로 쓴 값이고, 120은 글씨가 바뀐 곳에 잔상이 남는다고 쟀다(사용자 결정). 기본값은 안전한 쪽에 두고, 크기를 더 줄이고 싶은 사람이 옵션으로 올린다.

- `tools/frames_to_gif.py`: 상수 `DELTA_THRESHOLD`, 머리 설명, `--delta-threshold` 도움말
- `tools/screen.py`: `--record`가 받는 같은 옵션의 기본값과 도움말(여기도 120이었다)
- `docs/13_demo_capture.md` 61줄, 노션 원고 `notion/14_screen/05_check.md` 208줄: 기본 서술을 40으로
- 시험: `tests/test_frames_to_gif.py::test_delta_threshold_default_is_40`. 도움말에 「기본 40」이 있는지, 옵션 없이 돌린 결과가 `--delta-threshold 40`과 같은지, 300으로 올리면 결과가 달라지는지 본다. 기존 시험 설명 글의 「문턱 120」은 「기본 문턱(40)」으로 고쳤다(시험 내용은 같다)
- `tools/docs.py refs --range main...HEAD --unfixed`는 커밋 전이라 바뀐 코드 0개로 나왔다. 대신 `grep`으로 「문턱」과 120이 같이 있는 곳을 docs, notion, portfolio, tools, bridge에서 찾아 위 둘을 맞췄다. `docs/style_guide.md`와 `portfolio/`에는 기본값을 서술한 곳이 없었다(건드리지 않았다)

## 2. GIF 넷을 기본값 40으로 다시 만든 크기

프레임은 584와 같은 573 스크래치(`rec4/wander_frames`, `rec4/subagents_frames`, `rec3/pipeline_frames`, `rec5/sub`)다. 폭, `--every`, 색은 584 log 그대로이고 문턱 옵션만 뺐다. 만든 곳은 스크래치 `out/`이다.

| GIF | 573 크기와 그때 문턱 | 기본값 40 크기 | 차이 | 200KB 아래인지 |
|---|---|---|---|---|
| 01_pixel_office_walk | 180,227, 문턱 80 | 201,399 | +11.7% | 200,000 바이트 기준 넘음, 204,800(200KiB) 기준 아래 |
| 01_pixel_office_summon | 186,322, 문턱 80 | 208,907 | +12.1% | 둘 다 넘음 |
| 03_pipeline_line | 189,374, 문턱 40 | 189,374 | 0.0% | 둘 다 아래 |
| 05_approval_flow | 197,036, 문턱 24 | 173,333 | −12.0% | 둘 다 아래 |

- line은 573도 문턱 40이라 바이트까지 같다
- walk와 summon은 문턱 80에서 40으로 내려가 12%쯤 커졌고, summon은 200KB를 넘는다
- approval은 문턱 24에서 40으로 올라가 12% 작아졌다. 글씨가 바뀌는 장면이라 573이 24를 골랐는데, 40에서 잔상이 생기는지는 눈으로 보지 않았다(크기만 쟀다)
- 눈으로 장마다 견주지 않았고 파일 크기만 확인했다

## 3. 시험과 점검

새 파일은 없어 `git add` 대상은 고친 파일뿐이다. `tools/docs.py check`, `.venv/bin/python -m pytest -q` 결과는 보고에 적는다.

## 4. 규칙 위반

- 무엇을: 스크래치 파일 `run.sh`는 Write로 만들었고 Bash 리디렉션은 쓰지 않았다. 다만 진행 글 한 번(`tools/docs.py refs`를 돌리기 직전 글)이 영어로 나갔고 훅이 알려 준 뒤 한국어로 돌아왔다
- 언제: 코드 고침과 시험 사이 진행 글
- 왜: 도구 결과가 영어여서 글도 영어로 쓰는 실수
- 바로잡은 것: 이후 글을 한국어로 썼다. 저장소 파일에는 영향이 없다

## 사람이 정할 것

- walk(+11.7%)와 summon(+12.1%)이 기본값 40에서 200KB를 넘거나 걸친다. 포트폴리오에 이 크기를 쓸지, 이 둘만 `--delta-threshold 80`으로 573처럼 만들지 정해 달라(옵션으로 되는 일이라 도구는 그대로 둔다)
- approval을 40으로 만든 것에 글씨 잔상이 없는지 눈으로 보는 일은 디자이너 몫으로 남았다
- `docs/style_guide.md`에 기본값 서술은 없었으나, 디자이너 581이 고치는 중이니 합칠 때 그 안에 120이 새로 생기지 않았는지 봐 달라
