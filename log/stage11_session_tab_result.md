## 바꾼 것

- **[세션] 탭 순서**
  1. 한 줄 — 프로젝트 · 경로 · 열린 턴
  2. **인계**(늘 보임) — [요약하고 끝내기] [지금 요약] [새로 띄우기], 요약 카드(머리에 [고치기]) · 요약 이력 · 읽을 곳
  3. **세션**(늘 보임) — [세션 끝내기], 「더」 안에 작업 중단 · 일시정지 · 다시 시작 / 따로 작업(worktree일 때)
  4. **문서 정리**(접힘) — 압축 손실 [잃은 것 찾기] · 문서에 남기기 [남길 것 찾기]
     - 승인할 목록 · 쓰기 확인 실패 · 도는 점검이 있으면 저절로 열리고, 머리에 "승인할 목록이 있습니다" 같은 힌트가 뜬다
     - 사람이 열고 닫으면 그대로 둔다
  5. **세션 정보 · 토큰**(접힘) — 프로세스 · 지금 · 서브에이전트 · 모델 · 토큰 · 모델별. 머리에 모델 · 오늘 출력
  6. **승인 이력**(접힘, 전과 같음)
- **이름**(화면 · 확인 창 · 텔레그램 · 서버 거부 사유 · 세션에 보내는 요청 머리)
  - 문서로 옮기기 → **문서에 남기기**
  - 옮길 것 뽑기 → **남길 것 찾기**
  - 잃은 것 보기 → **잃은 것 찾기**(칸 이름 「압축 손실」)
  - 옮길 것 뽑기에 넣기 → **문서에 남기기로**
  - 코드 주석 · 지난 log의 옛 이름은 그대로 뒀다
- **호버 설명**: 모든 버튼에 "무엇 — 한 줄 설명". 빠져 있던 [요약을 확인했습니다 — 세션 끝내기] · [취소] · [요약 없이 시작]을 채웠다. 칸 이름(압축 손실 · 문서에 남기기 · 문서 정리 · 세션 정보 · 토큰)에도 달았다

## 확인

- 시험: Python 402, JS 42(이름 바꾼 기대값 2곳)
- 브라우저 도구가 이 세션에 연결돼 있지 않아 **실제 화면은 보지 못했다**
  - 대신 저장소 밖 스크립트로 가짜 DOM · 가짜 API에 `mountHandoff`를 그려 봤다
  - 평소: 인계 → 세션 → 문서 정리(닫힘), 1판 체크 없음
  - 승인할 목록이 있을 때: 문서 정리 열림 + 힌트
  - 끝난 세션: 죽은 세션 요약 · 압축 요약 보임
  - 호버 설명 없는 버튼 0개
- 브리지를 다시 띄웠다(이름 바꾼 서버 글)

## 판단 근거

- 버튼을 지우기보다 접었다. 0번인 것도 "끝난 세션에서만 필요한 것"(죽은 세션 요약 · 압축 요약)은 그때 없으면 대신할 길이 없다
- 1판 고르기만 뺐다. 설계가 이미 "써 본 뒤 뺀다"였고, 쓴 적이 없다
- 「문서 정리」를 저절로 여는 조건을 "사람이 할 일이 있을 때"로 좁혔다. 평소에 열려 있으면 다시 버튼이 많아 보인다. 할 일이 있는데 닫혀 있으면 조용히 묻힌다
