### 1-3. 다섯 개를 쓰며 정한 것(522개에도 그대로)

- **근거는 그 커밋의 diff와 그 시점 파일만.** 그 커밋에 함께 들어간 log 파일은 그 시점 기록이라 쓴다. 뒤 커밋 · 지금 파일은 보지 않는다(`4159f5d`의 `docs_done`, `81aa3ea`의 `6153c9d`처럼 몇 분 뒤 일이 섞이기 쉽다)
- **세션 번호 · dispatch 번호 · README 줄 번호는 뺀다.** 마이그레이션 번호(0032)처럼 저장소 안에서 파일로 찾을 수 있는 번호는 남긴다
- **옛 메시지가 해시에 무엇을 붙였는지 믿지 않는다.** 인용한 해시는 그 커밋 제목 · diff로 짝을 다시 본다(`8e115de`에서 하나 틀림)
- **「끔 · 켬 · 바꿈」은 diff 앞 값과 맞댄다.** 설정 파일에 값을 처음 적은 것은 기본값과 같으면 동작이 안 바뀐다고 적는다(`81aa3ea`)
- 타입: 「기록」 · 「log」 · README · CLAUDE.md만 바꾼 커밋은 docs, 꼴 없는 코드 커밋은 diff로 feat · fix · refactor · test를 가른다. 「설정」(`config/*.toml`)은 chore로 했다 — 알림 · 감시 · 배포 설정이면 ops가 맞을 수 있다. **설정을 chore로 둘지 ops로 둘지는 사용자에게 묻는다**(타입 표의 ops = 인프라 · 배포 · 모니터링)

## 2. 522개 전체를 하는 방법

### 2-1. 메시지 지도 파일

저장소 밖 한 폴더(예: `~/foreman-reword-20261113/`, 다시 쓴 뒤 백업과 함께 둠). 저장소에 넣지 않는 까닭: 다시 쓰는 도중 트리가 바뀌면 안 되고, 옛 메시지가 그대로 남는 파일이라 「옛 메시지는 원격 태그로만」과 어긋난다.

```
~/foreman-reword-20261113/
  index.tsv          # 옛 전체 해시 <TAB> 할 일(reword|keep) <TAB> 묶음 번호 <TAB> 날짜
  msg/<옛 전체 해시>.txt    # 새 메시지 전문, Co-Authored-By 줄은 넣지 않는다
  why/<옛 전체 해시>.md     # 바꾼 숫자 · 근거 · 뺀 것(검토용, 다시 쓰기에는 안 씀)
  check.sh           # 아래 3-3 검사
  msgfilter.sh       # filter-branch에서 부를 것
```

- `msg/*.txt`에 Co-Authored-By 줄을 넣지 않는 까닭: 사람이 옮기다 틀릴 수 있다. `msgfilter.sh`가 **옛 메시지에서 `^Co-Authored-By:` 줄을 그대로 뽑아** 끝에 붙인다(옛 메시지에 없으면 안 붙는다) — 원문 그대로가 기계로 보장된다
- 해시 인용은 `{{옛 짧은 해시}}`로 쓴다. 다시 쓸 때 filter-branch의 `map` 함수로 새 해시(같은 7자리)로 바꾼다. 다섯 개 중 둘이 쓴다. 전체에서 main 안 커밋을 가리키는 해시를 적은 비머지 커밋은 27개(해시처럼 생긴 낱말 58종 중 main 안 커밋 30, 나머지 28은 다른 저장소 · 사라진 브랜치 · squash 원래 커밋 등 — 그대로 둔다. `refs/foreman/squashed/*`는 다시 쓰지 않으니 squash 본문의 원래 해시도 그대로 맞다)
- `{{…}}`는 **그 커밋의 조상만** 가리킬 수 있다(나중 일을 앞 커밋에 적지 않기 — 검사로 막음)

`msgfilter.sh` 뼈대(검토용, 이 세션은 돌리지 않았다):

```sh
f="$DIR/msg/$GIT_COMMIT.txt"
old=$(cat)
if [ -f "$f" ]; then
  body=$(cat "$f")
  # {{abc1234}} → 새 짧은 해시
  for h in $(printf '%s' "$body" | grep -oE '\{\{[0-9a-f]{7,40}\}\}' | tr -d '{}' | sort -u); do
    full=$(git rev-parse "$h^{commit}") && new=$(map "$full") && body=$(printf '%s' "$body" | sed "s/{{$h}}/$(git rev-parse --short=7 "$new")/g")
  done
  printf '%s\n' "$body"
  co=$(printf '%s\n' "$old" | grep '^Co-Authored-By:')
  [ -n "$co" ] && printf '\n%s\n' "$co"
else
  printf '%s\n' "$old"
fi
```

(`sed`는 문자열을 바꾸는 데만 쓰고 파일을 고치지 않는다. 실행 전 관리자 검토 몫)

| 3 | 11-06 | 66 |
| 4 | 11-08 · 11-09 | 91 |
| 5 | 11-10 | 55 |
| 6 · 7 | 11-11 | 127(둘로) |
| 8 | 11-12 · 11-13 | 90 − 그대로 둘 8 |

- 묶음 하나 = 코더 세션 하나(sonnet으로 충분, 이 다섯 개를 본보기로 넣음). 그 묶음만 `msg/` · `why/`를 쓴다
- 묶음이 끝나면 `check.sh` 통과 → 관리자가 `why/`에서 숫자 있는 것을 대여섯 개 골라 diff와 맞대 본다 → 사용자에게 몇 개 보이기(1단계처럼)
- 묶음끼리 겹치는 것은 `{{해시}}` 뿐이고, 옛 해시로 쓰니 순서와 상관없이 따로 써도 된다 — 동시에 띄워도 되나 검토가 밀리니 둘씩

### 2-3. 검사(`check.sh`) — 쓰는 동안 · 다시 쓰기 전

메시지 파일마다:
- 첫 줄이 `^(feat|fix|docs|refactor|perf|test|ops|build|ci|chore|revert): `, 설명 50자 이하, 마침표로 끝나지 않음, `타입(…):` 없음
- 파일 전체에 `—` · `·` 0, `Co-Authored-By` 0, 둘째 줄이 빈 줄
- `{{해시}}`가 main 안 커밋이고 그 커밋의 조상
- 옛 제목을 통째로 담지 않음(옛 메시지와 같은 줄 0)
- `index.tsv`의 reword 수 = `msg/` 파일 수 = 522(+ 그 사이 새 커밋 중 꼴 밖), keep은 머지 8 · squash 4 · 규칙 꼴 커밋

다시 쓴 뒤(옛 끝 `O`, 새 끝 `N`):
- `git rev-list --count` 같음, `--merges` 수 같음
- `git rev-list --topo-order --reverse`로 짝을 지어 커밋마다: 트리 · 작성자 이름 · 메일 · 날짜 · 커미터 이름 · 메일 · 날짜 · 부모 수 같음, 부모가 `map`으로 짝과 같음
- 메시지가 다른 커밋 = 정확히 reword 목록, keep 커밋은 메시지 바이트까지 같음
- 커밋마다 `^Co-Authored-By:` 줄이 옛것과 바이트까지 같음
- `git diff O N` 빈 것

### 2-4. 실제로 다시 쓰는 명령 — 관리자가 원본 폴더에서, 모든 세션을 재운 뒤

이 세션은 아무것도 돌리지 않았다. 런슈즈 11-12 차례를 따르되 둘을 바꾼다: ① **연습은 임시 복제본에서**(런슈즈에서 미리보기 명령이 참조를 실제로 옮긴 일이 있었다), ② 원본 폴더 main은 트리가 같으니 `reset --soft`로만 옮긴다.

1. 멈추기: 모든 CC 세션 재우기(쉬게 하기), 합치기 카드 0, 승인 대기 0. **worktree 브랜치가 남아 있으면 먼저 합치거나 버린다** — 옛 이력 위의 브랜치를 그대로 합치면 옛 커밋 수백 개가 다시 들어온다(런슈즈 11-12 「남은 것」). 남겨야 하면 다시 쓴 뒤 `rebase --onto <새 짝> <옛 밑> <브랜치>`(그 세션이 직접, 사용자가 시킬 때)
2. `git fetch origin` → `git rev-parse origin/main` = `O` 적어 둠, `git status` 깨끗
3. 연습: `git clone --no-local <원본> <스크래치>/rehearsal` → 거기서 `git filter-branch --msg-filter 'sh <DIR>/msgfilter.sh' -- main` → 2-3 검사. 실패하면 지도 파일을 고치고 복제본을 지워 다시
4. 원본에 백업 참조 `refs/backup/main-before-reword-YYYYMMDD` = `O`, 태그 `archive/main-before-reword-YYYYMMDD` = `O` → **태그를 먼저 push**하고 `git ls-remote`로 확인
5. 복제본에서 `git push --force-with-lease=main:O origin main` — **사용자 승인 필요**(CC 자동 모드 분류기가 force push를 막는다, 런슈즈 11-12. 우회하지 않는다)
6. 원본 폴더: `git fetch origin` → `git reset --soft origin/main` → `git diff --quiet HEAD`와 `git status`로 깨끗함 확인(트리가 같으니 작업 트리 · 색인은 그대로)
7. 뒤 확인: 원격 main = 복제본 끝, 태그 = `O`, 브리지 다시 띄우기(합치기 카드 · 정리 후보가 새 main 기준으로 다시 잼), Notion 자동 맞추기는 트리가 같아 바뀐 것 없음

다시 쓴 뒤에도 옛 해시를 가리키는 곳 — 바꾸지 않고 태그로 열린다고 적어 둘 것:
- 저장소 안 `log/` · `docs/` · README의 해시(트리를 안 바꾸니 그대로 옛 해시)
- 다른 저장소의 FOREMAN 해시(예: 런슈즈 CLAUDE.md 「FOREMAN 9fa7831」)
- 브리지 DB(합치기 카드 `head`, 띄우기 · 합치기 기록)
- 새 해시와 옛 해시 짝표: filter-branch가 남기는 `.git-rewrite/map`을 지우기 전에 `~/foreman-reword-20261113/oldnew.tsv`로 옮겨 둔다

### 2-5. 걸리는 시간

- 메시지 쓰기: 커밋 하나에 diff를 보고 숫자를 맞대는 데 1 ~ 2분(이 다섯 개는 셋 이상의 명령이 들었다) → 522개에 9 ~ 17시간의 세션 시간, 묶음 8개로 하루 둘씩이면 나흘. 검토(관리자 · 사용자)가 더 든다
- 다시 쓰기: filter-branch가 커밋마다 셸을 띄우니 538개에 몇 분, 검사 몇 분. 세션을 재우는 시간은 1 ~ 7단계를 합쳐 30분 남짓으로 본다
