## 설계와 달랐던 점 · 판단 근거

- **할 일 목록은 열려 있다.** 「목록은 접힘이 기본」을 파일이 많은 목록(포트폴리오 글 10 · 게시 파일 10)에 적용했다. 핵심 단추(시키기)가 있는 다섯 줄 목록을 접으면 또 묻히기 때문이고, 접어도 머리에 「밀린 것 N」이 보인다. 접힘을 원하면 `scribe.js`의 `keep(…:list, true)` 한 곳을 `false`로.
- **[갱신]은 쓴 글 중 그 뒤 커밋이 가장 많은(가장 옛) 글을 고쳐 쓰게 한다.** 서버가 주제 없이는 일을 시킬 수 없어서, 전체를 한꺼번에 다시 쓰는 대신 가장 뒤처진 글 하나로 했다. 다른 글은 「글 목록」에서 고른다. 「뒤 커밋」은 저장소 전체 커밋 수라 글과 상관없는 커밋도 센다(코드가 바뀐 정도의 거친 신호).
- **문서 고치기(`docfix`)는 메뉴에 없다** — 결과에서만 뜬다. 서버 `TASKS`에 새 일을 더했고, 고칠 곳(`README.md` · `docs/` · `CLAUDE.md`)은 README 갱신 · 나중에 할 일 정리 · CLAUDE.md 정리와 겹치므로 `TOUCHES`로 같이 못 연다. 점검 결과는 main에 합쳐진 `log/doccheck_*.md`만 가리킬 수 있고(이름 형식 · 존재를 서버가 확인), 물어보기 답은 4000자까지.
- **스키마는 바꾸지 않았다.** 고쳐서 합친 점검 결과 표시는 `session_action`의 `scribe-task` detail(`docfix <결과 이름>`)과 `wt-merge`로 센다.
- **서기 줄 CSS 버그**: `.sc-row > .small {flex:1}`이 `button.small`에도 걸려 모든 [시키기]가 글 칸만큼 늘어나 글이 좁았다(main도 같다). `button.small`만 `flex:none`.
- 서기 화면 CSS는 `office.html`이 아니라 `bridge/static/css/panel.css`에 있다(맡은 파일 「서기 화면 CSS」로 보고 거기만 고쳤다).

## 못 한 것 · 남은 것

- **「서기와 대화 — 이어 묻기」의 이어 묻기 자체**는 하지 않았다(한 번 묻고 끝). 찾은 것을 시키기로 잇는 부분만 했다.
- **「docs를 커밋마다 고치면 일이 끊기니 묶는 기준」**(README 줄 「문서 할 일과 시킬 일 섞여 보임」의 앞부분)은 하지 않았다 — 기준을 정하는 일이라 사용자 판단이 필요하다.
- `docs_pub`의 실제 값(Notion이 켜진 브리지)은 합친 뒤 관리자가 서기 패널에서 펫퍼민트 · 런슈즈 방으로 한 번 확인해야 한다. 값이 안 나오면 「읽지 못했습니다」로 보인다(조용히 0으로 나오지 않는다).
- 「문서 고치기」 세션은 실제로 띄워 보지 않았다(시험 세션이 필요하고 Opus를 쓴다). 서버 쪽은 프롬프트 · 거부 · 막힘만 시험했다. 합친 뒤 시험 세션 하나로 [바로 고치기] 한 번(그리고 `hidden_reason='test'` 숨김)을 권한다.
