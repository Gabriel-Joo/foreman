## 1. create = false가 휴지통 보내기를 막지 않았다 — 그냥 옮겼으면 20쪽이 휴지통으로 갈 뻔했다

- 사용자 방향: docs 구조를 Notion에 맞게(「02. 파이프라인 설계」 아래 18쪽 → `docs/02_pipeline/`), 그 뒤 Notion이 docs를 따라가게
- 짝(doc_publish)은 **경로**로 걸려 있다. 파일을 옮기면 맞추기는 새 경로를 "새 파일", 옛 경로를 "원본 지워짐"으로 본다
  - 새 경로 → `create = false`라 페이지를 만들지 않고 실패(이건 막혔다)
  - **옛 경로 → `archive()`로 기존 Notion 페이지를 휴지통에.** `create = false`는 만들기만 막고 지우기는 막지 않았다
  - 게다가 맞추기는 `docs/` 바로 아래만 읽었다 — `docs/02_pipeline/`로 옮긴 18편은 안 보여 모두 "지워짐"
- 펫퍼민트가 `git mv` 커밋을 push하고 30분 조용하면 20쪽이 휴지통(30일 안 되살리기 가능, 사이드바에서 사라짐) — 짝을 고칠 틈 없이
- 고침: `create = false`면 원본이 사라져도 휴지통으로 보내지 않고 실패로 남긴다(`docsync.sync` · `Publisher.archive` 둘 다). 경로만 바뀐 것이면 짝을 새 경로로 옮기면 풀린다
- 같이: 하위 폴더 읽기(`docs/**/*.md`), 빼기는 경로 앞부분으로 — `docs/archive/`는 늘, skip의 "…/"는 폴더 통째로(`docs/ops/` — 운영 기록 · 체크리스트). 런슈즈 하위 폴더는 archive뿐 · 펫퍼민트는 img(.md 없음)라 지금 대상은 그대로

## 2. "!" 명령이 실행되지 않고 모델에게 글로 갔다

- 공백은 보내는 쪽(`bridge/inject.guarded`)이 일부러 붙였다 — 3단계(11-01): '!'는 bash 모드라 CC 도구 호출이 아니고 승인 훅(approval.toml)을 거치지 않는다. 패널에서 그 길을 열지 않으려고 늘 앞에 공백 한 칸
- 그런데 사람이 실행하려던 명령이 글로 갔고 아무도 몰랐다(턴 기록 prompt_text가 " !"로 시작 — 0x20 0x21): 런슈즈 `!bash …/reviews-20261109/dump.sh` 2번(11-09 13:17 · 14:33), 백업 `mkdir … chmod 700` 2번(13:15 · 13:16), `!scripts/load-prod.sh --apply` 3번(11-07 · 11-08). 11-01 시험 3건 빼고 7건
- 고침: 입력 API가 앞뒤 공백을 떼고, '!'면 같은 명령을 Bash 도구 호출처럼 승인 규칙에 넣어 본다(`inject.bang_check`) — 묻는 규칙에 걸리면 막고 이유 · 할 일을 글로("그 세션에 '… 실행해 줘'로 맡기면 승인을 묻습니다"), sudo(비밀번호에 세션이 멈춤) · 여러 줄 · 빈 명령도 막음. 그 밖은 공백 없이 보내 bash 모드로 실행
- 지난 7건은 이제 모두 보내진다. `git push --force`는 막힌다(규칙 git-강제push)
- 남은 확인: 실제 세션에서 '!'가 실행되는지(시험 세션으로), bash 모드 기록 모양을 제출 확인(`find_delivery`)이 알아보는지 — 못 알아보면 "제출 확인 못 함"으로 뜰 수 있다
