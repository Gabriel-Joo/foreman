# 터미널에서 글자를 끌어 고를 수 없음 — 고침 (터미널 디자이너, 2026-11-11)

## 1. 원인

- 맞았다: 11-11 휠 스크롤(`014f3de`)이 그룹 세션에 켠 **tmux `mouse on`**이 끌기를 가져갔다. mouse on이면 tmux가 마우스 추적을 켜 xterm.js가 끌기를 앱(tmux)에 넘기고, tmux는 끌기를 복사 모드 선택으로 바꾸다 놓으면 선택을 풀어 버린다(`copy-pipe` 없이는 클립보드로도 안 간다). 그래서 끌면 바로 풀렸다.
- 브라우저 글 선택은 Shift+끌기로만 됐다(`d1` 기록에 적었던 부작용) — 사용자에게는 알려지지 않았다.

## 2. 고침 — mouse off + 휠은 화면이 보낸다

- `foreman-term-view`: 그룹 세션 `mouse on` → **`mouse off`**. tmux가 마우스를 추적하지 않으므로 끌기는 xterm.js(브라우저) 글 선택이 받는다.
- 휠: `terminal.js`가 iframe 문서(같은 출처)의 `wheel`을 캡처해 `/api/terminal/scroll`의 새 동작 `wheel_up` · `wheel_down`으로 보낸다. 서버(`bridge/terminal.py scroll`): `wheel_up` = 복사 모드(`-e`)가 아니면 들어가 `scroll-up -N 3`, `wheel_down` = 복사 모드일 때만 `scroll-down -N 3`(맨 아래에서 `-e`로 저절로 끝남). 스크롤 중이 아닐 때 아래 휠은 요청도 안 보낸다. 요청은 한 번에 하나, 쌓인 칸은 최대 10까지 이어 보낸다. Ctrl+휠(확대) · Shift+휠은 건드리지 않는다.
- 끌어 고른 글이 클립보드로 가는 길: **브라우저(xterm.js) 선택**을 쓴다 — Ctrl+Shift+C(또는 Ctrl+C: xterm 선택이 있으면 복사), 마우스 오른쪽 메뉴. tmux 복사 · OSC52는 쓰지 않았다(ttyd 클립보드 애드온 의존 · 브라우저 권한 문제). 한계: 선택은 **지금 보이는 화면 안**에서만 된다(스크롤하면 tmux 복사 모드가 그린 화면에서 선택, 한 쪽을 넘는 선택은 안 된다).
- 그대로 도는 것: [▲ 위로] · [▼ 아래로] · [입력으로](`up`/`down`/`exit` 길은 안 건드림), 탭 그룹 세션, [새 셸].
- 시험: `tests/test_terminal.py` — wheel_up이 복사 모드로 들어감, 복사 모드가 아닐 때 wheel_down은 무동작, 그룹 세션 `mouse off`로 바꿈. 33 통과 · 1 건너뜀(ttyd 없음). 전체 pytest 651 통과 · 1 건너뜀.
- **확인 못 한 것**: 실제 브라우저에서 끌어 복사 · 휠 한 칸 감촉(3줄이 맞는지)은 헤드리스로 못 봤다. 합친 뒤 라이브에서 본다.

## 3. 되돌리는 법

- 이 커밋 revert → 휠이 다시 tmux `mouse on`(끌기는 다시 안 됨).
- **브리지를 다시 띄워야 한다**(`wheel_*` 동작은 `bridge/terminal.py`, 새 동작이 없는 옛 브리지에서는 화면 휠이 422로 막대 경고를 낸다). 화면(`terminal.js`)은 새로고침.
- **이미 열린 그룹 세션에는 안 먹는다**: `mouse on`은 세션을 만들 때 한 번 걸린다. 옛 세션은 탭을 닫았다 열면(그룹 세션이 사라지고 새로 만들어짐) 바뀐다. 급히 풀 때: `tmux -S <소켓> set-option -t =<기준>-v-<탭>: mouse off`.
- 끌 설정 없음(스위치 없는 변경).

## 4. 조용한 고장 점검

- 휠 요청이 실패하면 막대 경고(`스크롤하지 못했습니다 — …`)가 뜬다. 옛 브리지와 새 화면이 섞이면 같은 경고(422)로 드러난다. 텔레그램은 보내지 않는다(사람이 보는 화면 동작).
