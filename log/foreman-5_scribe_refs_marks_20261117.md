## 1. 못 푸는 참조 판단

점검(`tools/docs.py check`)은 백틱으로 감싼 `→ 「제목」`도 참조로 읽는다(`bridge/doctext/titles.py`의 정규식은 화살표 바로 뒤에 낫표 제목이 붙으면 코드 구간 안이어도 잡는다). 게시기는 코드 구간 안을 링크로 만들지 않는다. 그래서 설명용 꼴 셋은 코드 구간으로만 감싸서는 안 풀린다. 화살표와 낫표 제목을 떼어 적어 점검이 참조로 읽지 않게 했다.

| 참조 | 고른 것 | 까닭 |
|---|---|---|
| `notion/10_scribe/04_notion.md` 50줄 「제목」 | 글자로 둠(꼴 설명) | 꼴을 설명하는 예시라 가리킬 편이 없다. 화살표 `→`와 낫표로 감싼 제목을 따로 풀어 적었다 |
| 같은 편 275줄 「승인 카드」 | 글자로 둠(예시) | 「승인 카드」 편은 없고(07_merge/01_card 편의 제목은 다르다) 예시 제목일 뿐이라, 편을 새로 만들거나 다른 편으로 돌리지 않았다. `→` 뒤에 `「승인 카드」`를 붙인다고 풀어 썼다 |
| 같은 편 277줄 「제목」 | 글자로 둠(꼴 설명) | 게시기가 무엇을 만나면 링크를 거는지 설명하는 문장이다. 「화살표 뒤에 낫표로 감싼 제목이 붙은 것」으로 풀어 썼다 |
| `notion/14_screen/05_check.md` 222줄 「Claude Code 창」 | 참조가 아니라 이름 바꾸기 표현이라 화살표를 뺌 | 「세션 창」을 「Claude Code 창」으로 바꾼 일을 말하는 화살표다. 그 제목의 편은 없고 만들 까닭도 없어, 「~을 ~으로 바꾼」 꼴로 고쳤다 |

없는 편은 만들지 않았다. 다른 편으로 돌린 참조도 없다.
