# 겹침 알림 헛알림 — 인계로 이어받은 세션 · 세지 않는 한글 낱말 (2026-11-08)

사용자: 인계받은 세션 214에 세션 211(인계해 주고 끝낸 세션)과 "겹친다"는 알림(728)이 왔다. 겹친 낱말은 `300k, 500k, 쉬어서, 중이라, 하한`이었다.

## 조사

- 시각: 04:33:17.117 겹침 판정 → 04:33:17.415 인계 넣음 기록(`summary.injected_at`, `injected_cc_session` = 214) → 04:33:23 211 끝냄(`session_action exit`)
- **끝난 세션은 원래 맞대지 않는다** — `live_sessions`(멈춘 T 빼고) + `detached_at IS NULL`. 판정하던 순간에는 211이 아직 살아 있었다. 인계 스크립트는 요약 → 새 세션에 넣기 → 옛 세션 끝내기 순서라, 새 세션의 첫 요청은 늘 옛 세션이 살아 있을 때 들어온다
- 인계 관계를 보지 않았다. 그리고 넣음 기록이 인계 글 적재보다 0.3초 늦어서 기록만으로는 첫 요청 때 알 수 없다
- 점수 4는 `300k` · `500k`(식별자 2점씩)에서 나왔다. 한글 셋은 0점인데 낱말 목록에는 찍혔다

## 고친 것 (`bridge/overlap.py`)

- `_handoff_linked`: 인계로 이어진 세션을 뺀다 — 이 요청의 `[FOREMAN 인계 r=X]`(첫 요청, 기록보다 먼저 옴) · 나에게 넣은 인계 · 내가 넘겨준 인계. 그 뒤의 요청도 양쪽 다 빠진다
- `match`: 보여 주는 낱말도 점수에 든 것(식별자 · 영문)만. 한글은 세지도 보여 주지도 않는다
- 남는 것: `300k` · `500k` 같은 숫자+글자는 여전히 식별자로 2점이다. 이번 일에서는 실제로 같은 일의 낱말이었다. 인계를 빼면 이번 헛알림은 없어진다

## 확인

- 시험: `tests/test_overlap.py`에 보이는 낱말 시험, `tests/test_stage2_db.py` 겹침 시험에 인계 셋(r=로 첫 요청 · 기록이 찬 뒤 · 넘겨준 쪽)을 더했다. 전체 473 통과
- 브리지 재기동(승인 대기 0, 새 PID 1881475). 재기동 때 찍힌 `WebSocketDisconnect`는 터미널 웹소켓이 끊긴 것이다
