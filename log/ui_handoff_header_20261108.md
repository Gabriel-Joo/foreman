# 넘기고 새로 시작(버튼 하나) · 머리말 두 줄 · 사용량 칩 바로 따라오기 (2026-11-08)

## 1. 런슈즈 [요약하고 끝내기]가 끝나지 않은 일

- [요약하고 끝내기]는 원래 요약만 받는다. 받은 뒤 [요약을 확인했습니다 — 세션 끝내기]를 한 번 더 눌러야 끝나는 구조였다(버튼 이름과 다르게)
- 200은 그 사이 [새로 띄우기]로 217에 넣었다(05:13:57 UTC) → 확인 버튼이 사라져 일반 [세션 끝내기]를 눌렀고, 첫 번째(05:14:51)는 `/exit`를 보냈지만 **15초 안에 CC가 내려가지 않아 실패**, 두 번째(05:15:09)에 끝났다. 맥락 520k 세션이 내려가는 데 15초보다 오래 걸린 것으로 본다
- 고침: 끝내기 기다림 15 → **45초**(`bridge/handoff.py`)

## 2. 넘기고 새로 시작 — 버튼 하나 (`js/handoff.js`)

- ① 요약 → ② 확인(넣을 글 · 읽을 곳 · 인계 뒤 바뀐 것을 보여 줌) → [확인 — 새 세션 띄우고 이 세션 끝내기] → ③ 새 세션(같은 폴더, 요약을 첫 입력으로) → ④ 옛 세션 끝내기
- 단계 표시(✓ · 지금 · 실패 빨강), 어느 단계에서나 [멈추기](요약은 남음). 실패하면 그 단계에서 [다시 …]
- 어디까지 왔는지는 이 브라우저에 세션마다 기억한다(`foremanFlow:<세션>`) — 단계는 저장한 것 + 서버 데이터(요약 상태 · 넣었나 · 살아 있나)로 정한다(`flowStep`, 순수 함수 · 시험). 새로 고친 뒤 "넣었는데 옛 세션이 살아 있음"이면 [옛 세션 끝내기]만 남는다
- 끝난 세션이면 확인 창(식은 맥락이라 비쌈) 뒤 headless 요약으로 같은 흐름
- **같은 버튼, 같은 이름**: [세션] 탭 · 맥락/압축 띠(예전 [인계 요약 받기]) · 교장실 창(그 방의 살아 있는 세션마다 맥락 크기와 함께) — 모두 `window.foremanHandoff.start(세션)` 하나를 부른다
- 줄인 것: [요약하고 끝내기] · [요약을 확인했습니다 — 세션 끝내기]는 뺐다(흐름이 대신). [지금 요약(계속 돎)] · [새 세션만 띄우기] · [압축 요약으로 만들기](끝난 세션)는 [더보기]로 접었다. [죽은 세션 요약 받기]는 흐름이 대신한다. 「세션」 칸의 [세션 끝내기]는 그대로

### 압축 요약이란

- CC가 맥락이 차서 자동 압축할 때 트랜스크립트에 남기는 요약을 그대로 인계로 쓰는 것. 토큰을 쓰지 않는다
- 끝난 세션에만 쓸 수 있고, 2판 인계의 「읽을 곳」 · 「문서와 다른 지금」이 없는 거친 요약이다. 압축 뒤 대화는 빠진다
- 쓸 일: 끝난 세션을 비용 없이 대충 이어받고 싶을 때뿐 — 그래서 [더보기]로 접었다

## 4. 사용량 칩이 바로 따라오게

- 화면은 이미 1분마다 `/api/usage/brief`를 읽고 있었다(로그로 확인). 다만 브리지가 `/usage`를 새로 읽은 순간을 몰라 최대 1분쯤 늦었다
- 브리지가 읽을 때마다 웹소켓으로 `{"type":"usage"}`를 보내고, 화면은 받자마자 칩을 다시 읽는다(1분 폴링은 읽기 사이 추정 %를 위해 그대로)
- 확인: 화면에서 `/api/usage/poll` → 이벤트 1번 도착

### 방 위 카드 — 판단

- 카드의 작업 · 쉼 · 토큰은 머리말(프로젝트 버튼 · 작업 수)과 겹친다. 그러나 **승인 대기 · 파이프라인 실패 · 웹훅 끊김 · 빌드 알림 없음**은 머리말에 없는 "조용한 고장" 신호다
