# 화면 글의 「터미널을 확인」을 「대화창」으로 (11-13, 일감 B)

사람은 터미널이 아니라 대화창을 본다는 사용자 결정(11-13)에 따라, 사람에게 확인하라거나 답하라고 시키는 글을 「대화창」으로 바꿨다. 기능 이름으로서의 「터미널」(터미널 탭, `terminal.js`, `terminal.py`)은 그대로 둔다.

## 바꾼 줄

- `bridge/handoff.py`: 새 세션을 못 찾음, 45초 안에 안 끝남, 끝나지 않아 멈춤, 5초 안에 다시 시작 안 함 (네 곳). 「대화창에서 확인해 주세요」 꼴
- `bridge/stallwatch.py`: 알림의 「silent」(대화창에서 무엇이 도는지 보고), 「exit_confirm」(대화창에서 고릅니다)
- `bridge/human_wait.py`: 권한 거부 알림, API 오류 멈춤 알림의 「(패널 입력 칸이나 터미널)」을 「(대화창 입력 칸)」으로
- `bridge/approvals.py`: 질문 규칙 사유, 시간 초과 알림, 질문 알림, 승인 대기 알림 마지막 줄 (네 곳)
- `bridge/api_error.py`: API 오류 할 일 글
- `bridge/static/js/opanel.js`: 「끝났는지 모름」 두 곳(칩 툴팁, 목록 툴팁)
- `bridge/static/js/render.js`: 답 기다림 툴팁, API 오류 할 일 글, 질문 카드 툴팁, 선택지를 잃은 질문 안내(글과 툴팁), 「답 확인 못 함」 툴팁
- `bridge/static/js/store.js`: 제출 안 됨 · 제출 확인 못 함 · 모델 바꾸기 확인 못 함 (세 곳)
- 시험: `tests/test_approval_summary.py`, `tests/js/api_stop.test.mjs`
- docs: `docs/10_office_design.md` 191행(멈춘 턴 「…」 호버 글)

시험: pytest 859 통과 · 1 건너뜀, `node --test tests/js/` 152 통과.

## CC 창이 화면을 막아 터미널에만 보이는 경우 (관리자가 사용자에게 알린다)

글은 사용자 말대로 「대화창」으로 바꿨지만, 아래는 CC의 안내·확인 창이 세션을 붙잡고 있을 때라 대화창에는 안 보일 수 있다.

- `stallwatch.py` 「exit_confirm」: 끝내기 확인 창(뒤에서 도는 일이 있으면 1 · 3을 고르는 창). 이 창은 CC 터미널에만 뜬다
- `handoff.py` 「45초 안에 끝나지 않았습니다」 · 「끝나지 않아 멈췄습니다」: 11-13 서기 339처럼 CC 안내 창(「Autocompact at 400k tokens?」)이 세션을 붙잡은 경우
- `handoff.py` 「45초 안에 새 세션을 찾지 못했습니다」: 폴더 신뢰 창이 떠 있는 경우
- `approvals.py` 승인 대기 · 질문 알림, `render.js` 「선택지를 잃은 질문」: CC 승인 창과 질문 창은 터미널에 뜬다
- `stallwatch.py` 「silent」, `opanel.js` 「끝났는지 모름」: 끝 신호가 안 온 세션이 CC 창 때문에 멈춘 경우

## 일부러 안 바꾼 것 (상태 · 명령 실행 안내)

- 「어디서 답했나」를 나타내는 상태 표시: `render.js` 245 · 246 · 280 · 281 · 336행(「터미널에서 답했습니다」 등), `api/approvals.py` 108 · 124행의 거부 사유 「이미 답했거나(터미널 · 시간 초과)」. 사실을 적은 것이라 그대로 둔다
- 명령을 어디서 치라는 안내: `usage.py` 723 · `usage.html` 151행(「아무 CC 터미널에서 /login」), `bang_watch.py` 60행(「터미널에서 맨 앞에 '!'를」). 터미널에서 치는 일이라 그대로 둔다. 바꿔야 하면 알려 달라
- 주석, 로그 글, 기능 이름(터미널 패널 · 터미널 창)

## 규칙 위반

규칙 위반 없음. 진행 글은 한국어로 썼다. 한 번 `cd`가 이어져 작업 폴더가 `bridge/static/js`로 옮겨졌으나 그 뒤 바로 저장소 루트로 돌아와 시험을 돌렸다(규칙 위반은 아님).
