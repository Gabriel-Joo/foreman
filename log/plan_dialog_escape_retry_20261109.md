# 계획 창 정리 · [+ 세션] 창 키우기 · 입력 줄이 가려지면 Esc로 닫고 보내기 (2026-11-09, 원본 폴더)

## 1. 계획 창 — 중요한 것만 먼저

사용자: "칸이 8개에 체크박스에 긴 글까지 한 화면에", "중요한 것만 먼저, 나머지는 자세히로, 노트 제안은 개수만".

- 먼저 보이는 것: 프로젝트 · 방식 · 이름 · 넣을 첫 글(12줄). 넣을 요약은 방식이 "옮기기용 요약 넣고 시작"일 때만
- [자세히](접힘): 역할 · 모델 · 보낼 세션 · 읽기 전용 · 따로 작업(worktree). 접힌 줄에 지금 값을 한 줄로("코더 — 고치기 · 만들기 · Opus (역할 기본) · 원본 폴더"). 방식이 "살아 있는 세션에 보내기"면 보낼 세션이 꼭 필요해 저절로 펼친다
- 노트 고치기 제안: 접고 "노트 고치기 제안 N개"만
- 칸 id는 그대로라 `collect()` · [이대로 시작]은 바뀌지 않았다

## 2. 맨 위 노란 글 — 내부 처리는 빼기

- "노트 제안의 출처 ''를 알아볼 수 없어 '이번 요청'으로 바꿨습니다"는 `foreman_note.check_ops`가 디스패처(LLM)의 노트 제안을 다듬은 기록이다. 출처를 비워 낸 제안이 2개라 두 번 떴다. 사람이 할 일이 없다
- `foreman.check`: 노트 제안 다듬기 · "모르는 방식 → new"는 로그(`foreman.dispatch` info)로만. 화면에는 계획이 바뀐 것 · 골라 달라는 것만 남김(모르는 프로젝트, 요약 · 보낼 세션을 쓸 수 없어 바꿈, 점검 역할이라 읽기 전용)
- 이미 저장된 옛 계획을 열 때도 "노트 …"로 시작하는 줄은 화면에서 거른다
- `check_ops`의 반환(warn)은 그대로 — 시험이 쓴다

## 3. [+ 세션] 창 · 계획 창 크기 · 글씨

- 창이 글씨 배율(가+ · 가−, `--ui-zoom`)을 따르지 않았다(16px 고정, 폭 560) → `#nsDlg .box.ns`에 zoom, 폭 880(창 94%까지), 글씨 17px
- 입력칸 2줄 → 6줄(최소 8em), 자리표시에 "Ctrl+Enter로 계획 받기"
- 안내: "감독에게 말하기 — 뭘 하려는지" → 제목 "교장에게 말하기" + "하려는 일을 적으면 교장이 어느 프로젝트에서 어떻게 할지 계획을 세워 보여 줍니다. 확인해야 세션이 뜹니다."
- 상태 글: 버튼 옆 작은 회색 글 → 입력칸 아래 상자(기다리는 중이면 도는 표시 + 지난 초 "… 7초" + 둘째 줄 "프로젝트 상황 · 노트 · 문서를 읽느라 보통 20초쯤 걸립니다."). 끝/실패는 왼쪽 줄 색(초록 · 빨강)
- "직접 고르기 — 프로젝트 · 시작 방식을 내가 정한다" → "계획 없이 직접 띄우기 — 폴더 · 이름 · 시작 방식을 내가 고릅니다"(호버: 감독실을 거치지 않고 골라 바로 띄움, 계획이 틀렸을 때)

## 4. 입력 줄이 가려지면 Esc로 닫고 보내기

사용자: "CC가 설정 화면을 띄워두면 입력이 막히는 게 반복된다(오늘 세 번째). 보내기 전에 입력 줄이 없으면 Esc를 자동으로 보내고 다시 시도, 끝내기처럼(Esc 최대 3번). 안 풀리면 그때 알려줘."

- `bridge/inject.clear_screen(t, busy)` — 입력 줄(❯)이 없으면 Esc를 보내고 0.6초 뒤 다시 본다, 최대 3번. 돌아오면 보낸 Esc 수를 돌려주고 그대로 보낸다. 3번에도 안 되면 거부("Esc를 3번 보내도 닫히지 않았습니다 — 그 세션 터미널에서 확인해 주세요")
- `deliver`가 붙여넣기 전에 부른다 — 패널 입력 · 옮기기 넣기 · 감독실 [보내기] · 끝내기(/exit) 모두 같은 길. 끝내기에 따로 있던 Esc 반복은 지웠다(한 곳으로)
- **작업 중(busy)이면 Esc를 보내지 않는다** — Esc는 작업을 끊고, 승인 · 질문 창(도구가 도는 중이라 busy)에서는 거부 · 취소가 된다. 이때는 "작업 중이라 Esc를 보내지 않았습니다"로 알린다. 지금 상태 파일의 status는 busy · idle 둘뿐이었다
- 화면: 잘 보냈으면 "보냈습니다. 떠 있던 설정 화면을 Esc N번으로 닫고 보냈습니다." — 반복되는지 보이게. 입력 이벤트 기록에 `esc` 수
- 시험: Esc 2번에 열림 → 그 뒤에야 붙여넣음 / 3번에도 안 됨 → 붙여넣지 않고 거부 / 작업 중 → Esc 없이 거부(전의 "모달이면 거부" 시험을 셋으로)
