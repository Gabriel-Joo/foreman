## 7. 인프라에 넘길 것 (이 일이 합쳐진 뒤 관리자가)

- README 편 목록은 **맨 위 편만** 넣고, 하위 편이 있는 편은 「하위」 칸에 「하위 N」을 적는다. 하위 편은 노션에서 본다(사용자: README는 길 안내, 50줄이면 목차가 된다). 인프라 README도 같은 생성기라 그대로 이 규칙이 된다
- 소개 문단은 포트폴리오 00편 「한눈에 보는 홈랩」의 첫 본문 문단이다
- `[readme]` 표를 켜면 거꾸로 찾기가 맨 위 README.md를 트리거로 보지 않고, 포스트잇 [→]와 서기 「알려진 한계 쓰기」가 거부된다(인프라에서 쓰고 있다면 알릴 것)
- 543 9절의 걸리는 것(인프라 README 14줄을 근거로 쓰는 10곳)은 그대로 남아 있다. 그 근거를 실제 파일로 옮긴 뒤 켜는 차례
- 인프라도 README를 옮기며 옛 자리에 생성물을 만들면 줄표 검사는 `-C`로 복사를 알아본다(인프라는 아직 `dashdot_base`가 없어 검사하지 않는다)

## 8. 규칙

- **진행 글 셋을 영어 낱말로 시작했다.** 「Mention이 없어 그대로 둡니다」, 「Edit 두 곳(…)에 README 조건을 더합니다」, 「Now 전체 시험과 문서 점검을 돌립니다」. 모두 도구 호출 사이 짧은 글이었고 보고를 쓰며 찾았다. 그 뒤 글은 한국어로 썼다
- 그 밖에 규칙 위반 없음: 파일은 Edit, Write로만 고쳤다(`git mv`와 `tools/docs.py readme`는 일감의 도구). sed, heredoc, `>` 리디렉션, `python -c`로 파일을 고치지 않았다. `pgrep -f`, stash, push, 브리지 다시 띄우기 없음. `git add`는 고친 파일 이름만. 서브에이전트 셋(원고 근거 바꾸기, 절 번호 가리킴, 근거 지도 조사)은 같은 금지를 넘겼고 셋 다 「규칙 위반 없음」으로 보고했으며 모두 끝났다
