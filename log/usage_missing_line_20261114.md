# /usage에 5시간 줄이 없을 때 「읽기 실패」로 세지 않기 (11-14)

## 원인 확인

- 11-14 14:23 `claude -p "/usage"`(CC 2.1.325) 결과에는 「Current session」 줄이 없고 주간 두 줄만 있었다. 글 모양이 바뀐 것이 아니라 CC가 줄을 뺀 것이다.
- 전 코드는 한도 하나라도 못 찾으면 `RuntimeError`로 읽기 전체를 실패로 세어, 찾은 주간 값까지 버렸다(`poll`). 화면 머리에 「읽지 못하고 있습니다」 띠가 뜬 까닭이다.
- 「limit이 비면 CC가 줄을 뺀다」는 관리자 추정은 실행 파일 안 글을 찾는 검색(grep)이 오래 걸려 확인하지 못했다. 근거는 11-14 실제 출력(주간 줄은 있고 5시간 줄만 없음)뿐이다.

## 고친 것

- `bridge/usage.py`
  - `head_keys()` 추가: 줄 머리가 글에 있는 한도를 센다. 머리는 있는데 `% used`가 없으면 글 모양이 바뀐 것(실패), 머리가 아예 없으면 CC가 줄을 뺀 것(실패 아님)으로 가른다.
  - `poll()`: 한도 줄이 하나도 없으면 실패, 머리만 있고 %가 없으면 실패, 그 밖에 일부 한도의 줄만 없으면 성공. 찾은 한도는 그대로 기록하고 없는 한도는 `UsageMonitor.absent`(한도 key → 마지막으로 본 때, 없으면 처음 안 때)에 둔다. 줄이 돌아오면 지운다. 돌아왔다는 알림 글은 읽힌 한도만 적는다.
  - `limit_status(absent=…)`: 빠진 한도는 측정 · 추정 · 이 속도면 언제 100%를 비운다(`absent`, `absent_since`, `last_pct`, `last_at`, `scoped` 추가). 그래서 80 · 95% 알림, 「1시간 안에 5시간 한도」 예측이 옛 %로 경고를 내지 않는다(`check_alerts`는 값이 없으면 건너뛴다).
  - `check_alerts()`: 모델별이 아닌 한도(5시간 · 주간 전체)의 줄이 `ABSENT_ALERT_H`(6시간) 넘게 없으면 텔레그램 한 번(rule `usage:<한도>:absent:<빠진 때 MMDDHHMM>`).
- `bridge/api/usage.py`: `limit_status`에 `absent`를 넘기고 `/brief`에 새 칸을 싣는다. **일감의 맡을 파일에는 없었지만 화면에 값을 보내려면 꼭 필요해 고쳤다.**
- 화면
  - `static/js/office.js` 머리 칩: 「5시간: CC가 보이지 않음」, 6시간 넘게 없으면 노랑. 호버에 「/usage에 5시간 줄이 없습니다. 서버가 5시간 한도 값을 주지 않을 때 CC가 줄을 뺍니다」와 마지막으로 본 값(지금 값이 아님). 모델별 한도(Fable)는 칩에서 빼고 호버에만.
  - `static/usage.html`: 줄이 빠진 한도마다 띠와 카드 문구.
- 시험 `tests/test_usage.py`: 11-14 실제 글로 `head_keys` 구분, 5시간 줄이 없어도 읽기 성공 · 옛 값 안 냄 · 6시간 뒤 한 번 알림 · 돌아오면 평소대로 · 줄이 하나도 없음/머리만 있음은 실패.
- docs `docs/15_usage.md` 6-3절 새로 씀.

## 정한 값

- 알림 6시간(`ABSENT_ALERT_H`, 코드 기본값. `config/usage.toml`은 고치지 않았다). 5시간 창이 한 번 지나가고도 없으면 일시적이 아니라고 보았다.
- 모델별 한도(Fable 등, `models`가 있는 한도)는 알리지 않는다. 요금제 · 서버에 따라 나타나고 사라지는 줄이라 화면 호버에만 둔다(일감 4번). 「(Sonnet only)」 줄은 `config/usage.toml`에 한도가 없어 지금도 읽지 않는다. 쓰려면 `[[limits]]`를 더하면 같은 길로 다뤄진다.

## 설계와 달랐던 점 · 남은 것

- 빠진 때(`absent_since`)는 메모리라 브리지를 다시 띄우면 그때부터 다시 센다(알림이 하루 더 늦거나 한 번 더 나갈 수 있다). DB에 남기려면 스키마가 필요해 하지 않았다.
- 칩 · 띠를 실제로 빠진 상태로 그려 `tools/screen.py`로 잘림 · 겹침을 본 것은 아니다. 라이브 브리지는 옛 코드라 빠진 상태가 나오지 않는다. 합친 뒤 브리지를 다시 띄우고(승인 대기 0 확인) 세 테마 × 좁게/넓게로 본다. 칩 글이 길어졌다(「한도: 5시간: CC가 보이지 않음 · 주간 10%」).
- `docs/operations.md` · `docs/style_guide.md`에 고칠 곳은 없다.
