## 1. 한 일

### ① 「잊은 것 찾기」 — 없음과 실패를 가른다 (서버도 고침)
- **서버가 둘을 가르지 않았다.** 압축된 적 없는 세션은 `status='failed'`(글 「압축된 적이 없습니다」)로, 묶음 일부가 실패하거나 건너뛴 말이 있는 점검은 `status='done'`으로 남았다. 그래서 (가) 볼 것 없음이 「실패」로, (나) 일부 실패가 「사라짐 0 · 약해짐 0」, 곧 「없음」처럼 보일 수 있었다. 접힌 「옮기기 전 정리」 머리는 실패해도 아무것도 띄우지 않았다
- `bridge/losscheck.py` `outcome()` — found · clean · nothing · partial · failed · running. 목록(`list`)이 점검마다 `outcome` · `groups_failed` · `skipped`를 낸다. 압축 없음은 이제 `status='nothing'`으로 저장(`VARCHAR(12)`라 스키마는 그대로). 11-13 전 기록(`failed` + 그 글)은 `nothing`으로 읽는다
- 화면(`losscheck.js`): 실패는 빨강 「✗ 찾기 실패 — 잊은 것이 없는 것이 아니라 찾지 못했습니다」, 일부는 노랑 「⚠ 일부만 찾았습니다 … 0이어도 「없음」이 아닙니다」, 없음은 초록 「✓ 끝까지 찾았고 잊은 것이 없습니다」, 볼 것 없음은 회색 「찾을 것 없음」. 머리 상태 글도 같은 갈래
- 옮기기 한 흐름(`moveflow.js lossNote`)은 그 갈래를 흐름 맨 위 한 줄로 같은 색으로 남긴다. 전엔 실패일 때만 노랑 한 줄이었고 없음 · 일부는 아무 말이 없었다
- 「옮기기 전 정리」 접힌 머리에 「잊은 것 찾기 실패」 · 「잊은 것 찾기 일부만 끝」

### ② 문서 후보 고르기 첫 화면을 둘째처럼
- 후보마다 칸: 종류 꼬리표 + 무엇 / 「갈 문서」 경로 「절」 / 「왜 거기」. 고를 수 없는 것(목적지 확인 실패 · 세션이 버림을 권함)은 흐리게, 까닭을 칸 안에
- 목록은 제 높이(`min(55vh, 640px)`) 안에서 스크롤하고, [고른 N개를 문서에 쓰고 옮기기]는 목록 아래에 그대로(`.mv-act`, sticky 끔). 전엔 sticky라 스크롤하면 아래 후보를 가렸다
- **고른 수가 어긋나던 까닭(코드로 찾은 것)**: 수는 draft의 승인을 세고, 체크 표시는 목적지 확인 실패를 빼고, 쓰기는 `promote.js merged`(목적지 `drop`이면 승인 → 빼기)를 봤다. 세 곳이 달라 「고른 N개」와 실제 쓰는 수가 다를 수 있었다. 이제 셋 다 `moveflow.js chosen()`을 보고, 쓰기 직전 `chooseFinal`이 화면에 체크 없는 승인(고를 수 없는 후보의 서버 값)을 빼기로 바꾼다. 사용자가 본 「고른 1개를」 사례 그대로를 되살려 보지는 못했다
- `office.html`의 `label:has(> input[type=checkbox])`(inline-flex · 가운데)가 `.mv-item`보다 세서 체크 상자가 칸 아래로 갔다 — `.flow label.mv-item`으로 세게. 패널 `code`가 블록이라 경로가 제 줄로 떨어지던 것도 `.mv-meta code`를 inline으로

### ③ [전부 고르기] · [전부 풀기]

## 4. 되돌리는 법
- 이 브랜치 커밋을 `git revert`. 되돌린 뒤에도 DB에 `status='nothing'` 행이 남을 수 있다 — 옛 화면은 이를 모르는 상태로 「nothing」 글자를 그대로 보일 뿐 동작은 안 깨진다. 필요하면 `UPDATE loss_check SET status='failed' WHERE status='nothing'`
