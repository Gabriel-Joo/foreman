# 픽셀 화면 키우기 · 질문(AskUserQuestion)을 패널에서 답하기 · 화면 코드 지문 (2026-11-09, 원본 폴더)

## 1. 질문 카드 — 승인이 아니라 질문, 패널에서 답한다

사용자: "승인 카드에 질문이 JSON으로 잘려 선택지를 못 본다", "질문하는 게 왜 승인이 필요해", "선택지를 패널에 버튼으로, 누르면 답이 세션에".

- **왜 승인 카드로 떴나**: FOREMAN 정책(`approval.toml`)에는 AskUserQuestion이 없다(판정 pass). CC가 질문 창을 띄울 때 PermissionRequest hook을 부르고, `remote_approval = true`라 브리지가 CC의 창을 모두 승인 대기로 받았다. 카드 글은 `_target()`이 입력을 JSON으로 300자에서 잘랐다
- **빼지 않은 까닭**: hook에서 빼면 질문이 터미널에만 뜬다. 텔레그램 · 화면 알림이 없고 턴도 안 끝나 턴 끝 알림도 없다 → 세션이 조용히 멈춘다. 그래서 알림은 두고 모양 · 답하는 길을 바꿨다
- **답하는 길**(문서 확인 — hooks 레퍼런스 AskUserQuestion: PermissionRequest `decision.behavior: "allow"` + `updatedInput` = 원래 입력 전체 + `answers`(질문 글 → 선택지 이름, 여러 개는 쉼표)):
  - `ApprovalManager.questions` · `answers` · `questions_of()` · `answer()`, `POST /api/approvals/{id}/answer {picks}` — 선택지 이름만 받고, 하나만 고르는 질문에 둘이면 422
  - 카드(`render.js questionCard`): "❓ 세션이 묻습니다", 선택지마다 버튼(이름 + 설명). 질문 하나 · 하나만 고름이면 누르는 즉시, 아니면 고른 뒤 [답 보내기]. 브리지가 다시 떠 선택지를 잃었으면 "터미널에서 답합니다"
  - 텔레그램 "❓ 세션이 묻습니다 — 답을 기다립니다" + 질문 · 선택지. 머리말 · 현장 버튼 · 방 카드 · 패널 머리에서 "승인 대기"와 "질문"을 따로 센다(경고는 같다 — 둘 다 사람을 기다린다)
  - 다른 승인 카드도 화면으로 보낼 때 300자 → 1024자(DB 칸과 같게)
- **실제로 답이 세션에 들어가는지는 아직 못 봤다** — 시험 질문 두 번은 터미널에서 답했다(아래 2). 다음 질문 때 패널로 답해 확인한다. 여러 개 고름의 구분자(", ")는 문서에 정확히 없다

## 2. 화면 코드 지문 — 열린 탭이 옛 코드로 도는 것을 알린다

- 질문 버튼을 만들고 브리지를 다시 띄웠는데 사용자 탭은 01:05 이후 js를 새로 받지 않아 옛 카드가 떴다. 브리지 기록에는 질문(#69, 규칙 "질문")이 제대로 있었다 — 조용한 고장
- `bridge/uiver.py ui_version()` — static 아래 js · css · html의 이름 · 크기 · 수정 시각 지문(5초 캐시). WS `hello` · `/api/dashboard`의 `ui`. `store.checkUi()`가 처음 받은 값과 다르면 맨 위 노란 띠 "화면 코드가 바뀌었습니다 — [새로 고침]"(저절로 고치지 않는다 — 입력 칸 글이 날아간다)
- 이 장치를 넣기 전에 연 탭은 한 번 손으로 새로 고쳐야 한다

## 3. 픽셀 화면 키우기

사용자: 글씨는 130%에서 맨 윗줄 탭 정도로 · 가+/가−를 따라가게, 캐릭터 · 가구는 방이 다 들어가는 선에서 최대한.

- **방은 이미 무대에 꽉 차 있었다**(1920은 높이, 1366 · 1024는 폭이 한계, 남는 여백 약 5%) — 방을 다 보이게 둔 채 키우려면 방 안에서 그림을 키워야 한다. 물어서 **캐릭터만 1.5배**(가구는 칸 배치 · 길찾기 · 앉기와 묶여 그대로)
  - `sprites.js charFrame`이 `{img, width, height, scale}`(키운 크기)를 돌려준다 — 얼굴 칸 · 소품 자리 · 이름표 높이 · 점검이 모두 같은 크기를 본다. 그리는 네 곳만 `drawImage(c.img, x, y, w, h)`. 사원증 끈 · 안전모 · 흔들림 · 자는 자리 자르기 · 선택 테두리 · 몸 크기 상한도 배율을 따른다. 테마 `sprites.char_scale`로 바꿀 수 있다
  - 방 여백 0.4 → 0.2칸
- **글씨**: 화면 좌표 글씨 = 원래 px × 글씨 배율 × 1.2(130%면 14px → 22px, 탭 17px × 1.3 ≈ 22px). 구역 이름표(`TAG.font` getter), 캐릭터 이름표, 말풍선(할 일 N), 방 · 현장 카드(줄 높이 · 폭 포함), 감독실 현황판 이름. 툴팁(CSS)도 `--ui-zoom`을 따른다. 전에는 `uiscale.js`가 픽셀 화면을 건드리지 않았다
- 커지면서 생긴 것 · 고친 것
  - 작은 창에서 배포 단계 이름이 다음 단계를 덮고 화면 밖으로 → 안 들어가면 앞부분(「① 검수대」)만, 전체는 툴팁
  - 방 밖 배달꾼 이름이 왼쪽 끝에서 잘림 → 이름표를 화면 안으로 당김
  - layoutAudit 테마마다 3~4건(가구가 몸을 2~14% 가림) → `layoutPlan()` 값대로 자리 0.1~0.3칸 옮김(마법학교 아치 창 · 원탁 · 봉인 문양, 오피스 라운지 · QA · 팀장실 모니터, 현장 도면실 · 검수대 · 트럭)
  - office 1024 「QA 부스」 3% — 실제 방 화면에선 0건이었다. 점검이 카메라가 방으로 다가가기 전(지도 배율)에 이름표 칸을 재서 글씨만큼 부풀었다 → `tagRects`는 방 하나를 볼 때의 배율(`roomViewScale`)로 잰다(주석이 원래 그렇게 말하고 있었다). 이름표 후보 끝에 "구역 바로 아래" 하나 추가
- 감독실 현장 카드는 글씨가 커져 긴 줄이 "…"로 줄어든다(호버에 전체)
