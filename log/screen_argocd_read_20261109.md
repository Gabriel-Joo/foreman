## 1. "❗ 붙으면 이름이 밀려 잘림" — [전체]가 아니라 [⌂] 현황판이었다

- ❗를 그리는 곳은 감독실 현황판 위 현장 이름(`drawHQCards`) 하나뿐이고, 이 이름은 **[⌂]** 화면에서만 그린다([전체]는 캐릭터 · 현황판 이름을 그리지 않는다). 탭 줄 · [전체] 카드에는 ❗가 없다
- 원인: 바탕 상자는 이름 폭만 쟀는데 글은 "이름 ❗"를 가운데 정렬로 그렸다 → 이름이 왼쪽으로 밀려 상자 밖으로 나가 잘려 보였고, 1024에서는 칸 폭을 넘어 「FOREMAN」 · 「라운지(떠돌이)」가 겹쳤다(세 테마 모두, 사진으로 확인)
- 고침: 이름은 표시와 상관없이 늘 칸 가운데. 칸 폭(옆 칸과 3px씩 띄움)에 들어갈 때까지 글씨를 줄이고(17 → 12px), 그래도 넘치면 자르지 않고 줄을 바꾼다. 표시(❗ · 🔥)는 이름 오른쪽에 자리가 있으면 거기, 없으면 이름 아래 자기 상자(1024에서는 아래로)
- `cardAudit()`에 현황판 이름 점검: 다른 칸 이름과 겹침 · 칸 밖 · 낱말 가운데서 끊김. **`tools/screen.py`가 화면마다 cardAudit를 기본으로 센다**(전엔 `--eval`로 따로 불러야 봤다 — 빠뜨리면 안 보였다)

## 2. 빨간 표시 종류 · 호버 이유

판단은 하나(`siteState`)이고 테마마다 그림이 다르다. 이제 [⌂] 현황판 칸에 마우스를 올리면 이유가 뜬다("런슈즈 — 빨간 표시: 사람이 풀어야 하는 대기가 있습니다…" + 승인 대기 · 질문 · 권한 거부 · 답 기다림 · 배포 대기 · 빌드 알림 줄). 칸 호버는 사람 이름 자리 피하기에 쓰지 않는다(`soft`)

| 표시 | 어디 | 뜻 |
|---|---|---|
| ❗(이름 뒤) · 붉게 맥박 치는 촛불(마법학교) · 노란 모니터 띠 · 테두리 깜빡 + "!"(오피스) · **빨간 자석, 칸 오른쪽 위**(현장) | [⌂] 현황판 칸 | 사람이 풀어야 하는 대기: 승인 대기 · 질문 · 권한 거부 · 답 기다림 |
| 🔥 · 꺼진 촛불 + 연기 · 빨간 모니터 + "✕" · 빨간 자석 | [⌂] 현황판 칸 | 파이프라인 실패 · 웹훅 끊김 의심 · 빌드 알림 없음 |
| 아래 줄의 작은 빨간 자석(최대 4) | [⌂] 현장 테마 | 승인 대기 한 건에 하나 |
| 현황판 오른쪽 위 깜빡이는 등 — 빨강 · 노랑 | [⌂] · [전체] | 빨강: 사용량 90% 이상, 노랑: 사용량을 못 읽음. **이번에 호버 붙임**(사용량 칩과 같은 숫자 줄) |
| 머리 오른쪽 빨간 원 + 📦 | 캐릭터 | 대화 자동 요약 4번째부터(호버에 이미 있음) |
| 빨간 글씨 · 테두리 | 카드 · 배너 | 파이프라인 실패, 빌드 알림 없음, 최근 10분 200만 토큰 넘게 씀 |

"빨간 점"은 지금 화면에서는 현장 테마 칸 오른쪽 위 자석(= 위 첫 줄)이다. 다른 곳에서 본 것이면 위치를 알려 주면 맞춰 본다

## 3. 크레딧 — 읽을 수 없다

- FOREMAN은 `claude -p "/usage" --output-format json`(모델 호출 없음)을 읽는다. 15:2x 원문: 한도 줄 셋(Current session 33% · Current week (all models) 24% · Current week (Fable) 0%)과 "What's contributing" 뿐 — **크레딧 · 추가 사용량 칸이 없다**. JSON 칸에도 없음(`total_cost_usd`는 이번 호출 비용 0)
- 트랜스크립트 전체에서 "extra usage" · "credits" · 한도 도달 글을 찾아도 0건 — 사용자가 터미널에서 본 /usage 화면이 남은 기록도 없다
- 그래서 크레딧 상태 화면 · 알림은 만들지 않았다. 대화형 /usage 화면(TUI)에 크레딧 칸이 따로 뜨는지는 확인하지 못했다(대화형 세션을 띄워야 한다)

## 4. ArgoCD "진행 중"이 안 끝나는 것 — 직접 읽어 닫기 + "배포가 끝나지 않습니다" 알림

- 실측 모양(DB): 펫퍼민트 109번 `running` — health Progressing · Synced · 작업 Succeeded. Healthy 알림이 안 와서 다음 결과가 올 때까지 남았다
- 읽기 수단: 호스트에 kubectl이 없고 ArgoCD API는 401(토큰 없음). **`cd ~/k8s-cluster && vagrant ssh m-k8s -c 'kubectl get applications.argoproj.io -n argocd <앱> -o json'`**(읽기 전용, 약 2초). ArgoCD API 토큰은 두지 않았다 — Jenkins API 토큰을 안 쓰는 것과 같은 이유(새 열쇠를 늘리지 않는다)
- `PipelineManager.check_argo_running`(30초 감시 루프): running이 **10분** 넘으면 앱을 읽고(같은 앱은 5분에 한 번), 그 리비전 작업이 Succeeded + Healthy면 성공, Failed · Error · Degraded면 실패(실패 알림은 기존대로)로 닫는다 — 메시지 끝에 "[끝 알림이 없어 ArgoCD를 읽어 확인]". **30분**이 지나도 안 끝났거나 못 읽으면 행마다 텔레그램 한 번(kind `argorun`, rule `argo_stuck:<프로젝트>:<행>`): "⏳ 배포가 끝나지 않습니다 — ArgoCD Sync 시작 뒤 N분째 …" + 지금 ArgoCD 상태 또는 못 읽은 이유 + ArgoCD 앱 링크
- OutOfSync일 때 `sync.revision`은 아직 안 올라간 목표 리비전이라 Synced일 때만 "배포됨"으로 본다(처음 판정에서 고침)
- 설정: `config/pipeline.toml [argocd_read]` (vagrant_dir · vm · namespace). 비우면 읽지 않고 알림만
