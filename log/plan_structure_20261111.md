## 설계 원칙

- **판에 박힌 단계는 브리지가 기계로, 판단만 관리자(LLM)나 사람에게.** merge-tree · 시험 · push · 승인 대기 0 확인 · 브리지 다시 띄우기 · 화면 점검은 브리지 코드로 한다(README 「운영 → 브리지」 줄). 관리자 LLM은 충돌 풀기와 「넷」(표 · 문서 정리)만 한다. 사람은 합치기 승인과 「무엇을 문서에 넣을지」만 한다
- **조용한 고장 금지**: 자동 받기 · 준비가 멈추거나 실패하면 텔레그램 한 번 + 패널 표시(예: 「합치기 준비가 10분째 멈춤」)
- **단계마다 스위치**: 띄우기 · 끝내기 길을 바꾸는 것은 `config/*.toml`의 켜기 값 뒤에 둔다(처음엔 꺼 둠 → 시험 → 켬). 되돌리기 = 값 끄기 + 브리지 다시 띄우기, 그래도 안 되면 그 단계 커밋 `git revert`. 마이그레이션은 더하기만(칼럼 · 표 추가, 지우기 없음) — 되돌릴 때 코드만 되돌려도 DB가 그대로 돈다
- 각 세션은 log에 「되돌리는 법」 절을 둔다(무엇을 끄고 · 무엇을 revert하고 · 브리지를 다시 띄우는지)
