  - 운영 데이터를 건드려야 할 때
  - 되돌리기 어려운 결정이 생겼을 때

## 운영 · DB — 금지

- 운영에 시험 계정을 만들지 않는다. 로그인 확인은 시드 계정으로 한다(1-11)
- 운영에서 429(로그인 잠금)를 일부러 일으키지 않는다(1-14)
- 체험 카드와 데모 사용자는 시드 계정과 데모 관리자만 쓴다. 실제 가입자와 진짜 관리자는 넣지 않는다(9-2 · 8-18)
- 마이그레이션은 추가 + 복사로 한다. RENAME은 쓰지 않고, DROP은 안정된 뒤 따로 한다. 옛 이미지로 롤백해도 앱이 떠야 한다(3-11)
- 계약 테스트 기준선은 추가만 한다. 기존 케이스는 다시 녹화하지 않는다(5-9)
- 덤프 → Sync는 끊지 않고 이어서 한다. 스키마 변경이 없으면 덤프 없이 이미지만 Sync한다(8-3 · 8-9)
- Redis 등 인프라를 늘리지 않는다(1-0)
- 권한은 백엔드에서 막는다. 버튼만 숨기는 것으로는 안 된다(1-0)
- 새 관리 기능에는 데모 관리자 차단을 같이 넣는다(9-2)
- `updated_at`은 관리자의 등록 · 수정 · 숨김 · 되살리기에서만 찍는다. 적재기 요청은 제외하고, 기존 행은 NULL 그대로 둔다(11-7 · 11-8)
- 기존 리뷰가 어느 신발에 달렸는지는 절대 바꾸지 않는다(1-1)
- 상세: `docs/06_deployment.md` · `docs/07_database.md` · `docs/05_api_contract.md` · `docs/03_admin.md`

## 카탈로그 값 — 금지 · 결정

- 판단을 사람과 Claude로 나눠 남긴다. 사람이 정한 값은 덮지 않는다. 출처나 by 기록이 없는 옛 값도 사람이 정한 것으로 보고 건너뛴다(13-8)
- 출처 코드는 `docs/01a` 1-8을 따른다(12-16)
  - WEB = Claude가 찾은 값, MAN = 사람이 넣은 값
  - DB · SX는 기존 값에만 붙인다
- 스펙은 제조사 공식값을 쓰고, 실측값은 섞지 않는다(2-21 · 3-6 · 3-21)
  - 무게는 US M9 기준이다
  - 우선순위는 STORE · PR → BITR → RSG이고, WEB · MAN은 순위 밖이다
- 다른 세대 리뷰의 값은 쓰지 않는다(5-15). 여성 상품 가격을 남성 값으로 쓰지 않는다(7-4)
- 쓰지 않는 출처(2-15 · 3-10 · 5-9 · 7-6)
  - press.on-running.com(사용자가 정할 때까지 접근 금지)
  - Doctors of Running, HOKA IR, solereview, Marathon Sports
  - ABC마트 구매 후기의 발볼 통계
- 발볼 판정(3-25 · 5-9 · 11-29)
  - 같은 브랜드 문구를 실은 소매점은 여러 곳이어도 1곳으로 센다
  - 와이드 판 언급, 바닥 폭, 다른 신발 얘기는 근거가 아니다
  - "리뷰 없음"은 "확인 불가"로 둔다
  - 와이드 판정에 소매점 사이즈 선택지를 쓰지 않는다(4-1)
  - 상세 7단계: `docs/01a` 1-6 · 1-7
- 영어 리뷰가 없다는 이유로 모델의 존재를 의심하지 않는다. 현행은 국내 판매 기준이다(5-17)
  - 린콘 5와 스펙투어 2는 넣지 않는다(11-30)
  - 라인 전체가 국내 미판매면 기록만 한다(11-34)
- null은 모름, "없음"은 확인한 값이다. 보완 필요는 null만 센다(11-17)
- 이미지는 핫링크만 하고 저장하지 않는다(2-6 · 11-34 · 15-3)
  - 공식몰 사진은 쓰지 않는다
  - 출처 표기는 가리기만 하고 지우지 않는다
- 영구 삭제한 신발은 `decisions.json`에 제외 기록을 남긴다. 숨긴 신발은 적재기가 다시 넣지 않는다(11-7 · 9-2)
- 상세: `docs/01a_catalog_sources.md` · `01b_catalog_images.md` · `01c_catalog_loader.md`
