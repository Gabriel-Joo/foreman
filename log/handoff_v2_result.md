# 인계 2판 · 압축 알림 결과 (2026-11-05~)

설계: `docs/11_handoff_v2.md`. 단계 a(압축 알림) → b(짧은 인계 + 읽을 곳 + Read 확인) → c(문서로 옮기기) → d([잃은 것 보기]) 순서로 이 파일에 이어 쓴다.

## a. 압축 알림 (11-05)

### 한 일

- **기준** `config/notify.toml` `[compact]`
  - `due_at = 2`: 2번째 압축부터 "넘어갈 때"
  - `late_at = 4`: 4번째부터 "늦었음"
  - `notify_at = [2, 4]`: 그 압축 직후 텔레그램 한 번씩
  - `short_turns = 3`: 압축 사이 사람 턴이 3 이하로 두 번 이어지면 "간격도 짧다"
- **판정** `bridge/compactwatch.py`
  - 세션별 압축 횟수는 DB `event` type `compact`(조립기가 `compact_boundary` 줄에서 만든다)로 센다
  - 수동 `/compact`도 센다. 압축은 수동이어도 깎는다
  - 새 세션(인계로 띄운 것 포함)은 새 행이라 0부터, `--resume`은 같은 행이라 이어 센다
- **텔레그램**
  - 조립기에 `on_compact` 콜백을 더했다. 실시간 적재 때만 부르고, 커밋 뒤에 부른다
  - 정한 횟수면 `notifier.send_direct`(kind `compact`)로 보낸다. 기록은 DB `notification`에 남는다
  - 접두어 없는 프로젝트(미분류) · 숨긴 세션은 보내지 않는다
- **대시보드 API**: 세션마다 `compact` = {count, last_ts, level, short, gaps}
- **화면**
  - 패널 머리줄 아래 띠: "📦 압축 N번 — 넘어갈 때입니다 / 늦었습니다"
    - [인계 요약 받기]: 지금 있는 1판의 끝내기 전 인계 요청을 보내고 [세션] 탭으로 옮긴다
    - [나중에]: 이 브라우저에서 다음 압축까지 숨긴다(횟수로 기억)
  - 픽셀 화면: 캐릭터 머리 옆에 📦, 늦었음이면 빨간 테두리. 툴팁에 "📦 압축 N번"
  - [나중에]로 숨긴 세션은 📦도 숨긴다

### 확인

- 시험: Python 381(압축 알림 4개 추가), JS 35
- 실제 DB: 런슈즈 156 19번 · 펫퍼민트 155 12번 · 이 세션 158 7번 → 모두 late. 펫퍼민트 139는 1번 → 표시 없음
- 헤드리스: 이 세션 패널에 띠가 뜨고 버튼 둘이 보인다. 캐릭터 옆 표시도 확인했다
- 텔레그램
  - 압축을 일부러 일으킬 수 없다. 그래서 실제 DB의 158로 `on_compact`를 가짜 알림기에 돌렸다
  - 7번은 대상이 아니라 보내지 않았다. 대상 횟수로 바꾸면 문장 "[포먼] 세션 「포먼 작업 세션」 압축 7번 — 늦었습니다. …"이 나왔다
  - 실제 발송은 다음 2번째 · 4번째 압축 때 본다

### 설계와 다른 점 · 판단 근거

- [잃은 것 보기]는 d단계에서 붙인다. 아직 만들지 않은 버튼을 띠에 두지 않았다
- [문서로 옮기고 새로 시작] 자리에는 지금 있는 1판 [인계 요약 받기]를 붙였다. 2판(b · c)이 생기면 바꾼다
- 이미 많이 압축된 세션(런슈즈 19번 등)은 브리지가 다시 떠도 텔레그램을 다시 보내지 않는다. 정한 횟수의 압축 "직후"에만 보낸다. 화면 띠 · 📦로는 보인다

## b. 짧은 인계 + 읽을 곳 + Read 확인 (11-05)

### 한 일

- **요청문 2판** `handoff.REQUEST_PROMPT_V2` — 2,500자 안, 문서에 없는 것만
  - 절: 지금 상태 · 다음 할 일 · 걸려 있는 것 · 문서와 다른 지금 · 읽을 곳
  - 읽을 곳 한 줄 모양: `` `경로` — 왜 ``, `` `경로:시작-끝` — 왜 ``, `` `경로` 「절」 — 왜 ``
  - 요약 API에 `fmt`(v1 · v2, 기본 v2)를 더했다. 패널 인계 칸에 "요약 통째로(1판)" 칸을 두어 고를 수 있다
- **넣는 글 2판** `INJECT_PROMPT_V2` — "먼저 「읽을 곳」을 모두 Read로 읽어라 → 문서별로 걸리는 규칙 2줄 → 문서와 다른 지금을 어떻게 다룰지 → 확인을 기다려라"
  - 2판인지는 본문에 `## 읽을 곳` 절이 있는지로 판단한다. 그래서 마이그레이션이 없다
- **기계 확인** `bridge/pointers.py`
  - 읽을 곳 한 줄마다 본다
    - 파일이 있나
    - 줄 범위가 파일 안인가
    - 「절」 이름이 문서에 있나
    - 문서가 마지막으로 바뀐 뒤 저장소 커밋 수(20개 이상이면 "오래됐을 수 있음", 막지는 않는다)
  - 틀린 곳이 하나라도 있거나 읽을 곳이 비면 **넣지 않는다**
    - 미리보기 API는 `blocked` 사유를 낸다
    - 띄우기 · 넣기는 tmux를 만들기 전에 409로 거부한다
  - 고치는 길은 [요약 고치기]다
- **Read 확인**
  - 2판 인계를 받고 시작한 세션은 `summary.injected_cc_session`으로 찾는다
  - 그 세션의 `Read` 도구 이벤트 대상(절대 경로)을 읽을 곳과 맞댄다
  - 패널 인계 칸에 "읽을 곳 N/M 읽음 — 안 읽음: …"과 [안 읽은 곳 다시 보내기]를 둔다(`POST /api/sessions/{id}/reads/resend`)
- [+ 세션]의 인계 요약 목록에서 숨긴 세션(시험)의 요약은 뺐다
