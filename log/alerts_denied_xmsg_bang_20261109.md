## 1. 권한 거부 30분 알림 (`bridge/human_wait.py`)

- 화면 판정(`human_needs` — 마지막 사람 입력 뒤의 CC auto mode 거부)을 그대로 쓴다. 60초마다, **거부 뒤 30분** 지났고 그 세션이 살아 있고 **지금 일하지 않으면**(CC status ≠ busy) 텔레그램 한 번(kind `denied`, rule `denied:<세션>:<거부 시각>` — 브리지를 다시 띄워도 한 번)
  - "일하지 않으면"을 넣은 까닭: 거부 뒤 CC가 다른 방법으로 이어 가는 일이 많다 — 그건 막힌 것이 아니다
- 글: "[런슈즈] ✋ 권한 거부 40분째 — 「…」 세션이 CC 자체 검사에 막힌 뒤 멈춰 있습니다 / ▶ 막힌 도구 Bash · 이유 [External System Writes] / FOREMAN 승인 카드로 오지 않습니다. 그 세션에 허용하거나 다른 방법을 지시해 주세요"
- 답 기다림(글로 묻고 끝남)은 알리지 않는다(11-09 제안 그대로 — 턴 끝 알림이 그 물음이다)
- 브리지에 올리기 전 운영 DB로 모의 판정: 보낼 것 0

## 2. 세션 간 메시지 읽음 (`bridge/xmsg.py`, 활동 API · 패널 활동 탭)

- 실측 모양(펫퍼민트 ↔ FOREMAN, 11-09):
  - 보낸 쪽: `SendMessage {to: "foreman-e7" | "uds:/tmp/cc-socks/<pid>.sock", message}` 도구 호출
  - 받는 쪽 트랜스크립트: `queue-operation enqueue`(`<cross-session-message from-name="보낸 세션" …>` + 본문) = **도착**, 그다음 `dequeue`(쉬던 세션이 프롬프트로 가져감) 또는 `remove`(reason `absorbed_mid_turn`) · `queued_command` attachment(작업 중에 끼어들어 읽음) = **읽음**
  - 적재기가 이미 이 줄들을 event type `queued`(payload.op)로 넣고 있었다 — 새로 적재할 것은 없었다
- 짝짓기: 보낸 본문 앞 60자(공백 정리) = 받는 쪽 enqueue 본문 앞 60자, 보낸 뒤 10분 안. 이름 · 소켓 풀기 없이 본문으로
- 패널 활동 탭의 SendMessage 줄 끝에 "— ✓ 읽음 15:01 (받는 프로젝트 · 세션)" · "· 작업 중에" · "— 도착 15:01, 아직 안 읽음" · "— 도착 기록 없음(받는 세션이 꺼졌거나 FOREMAN이 보지 않는 세션)". 활동을 다시 받을 때(세션을 고를 때) 이미 있는 줄도 고친다
- **SendMessage는 서브에이전트를 이어 부를 때도 쓴다**(`to` = 에이전트 id, 런슈즈 11-09 "a96255028a3559965" — 사용량 한도 뒤 이어 하기). 이건 세션 간 메시지가 아니라 표시하지 않는다
- 운영 데이터: 펫퍼민트(223) ↔ FOREMAN(224) 24건 모두 도착 · 읽음(가져감 18 · 작업 중에 6), 서브에이전트 2건은 표시 없음. 05:59:59 건은 트랜스크립트의 `absorbed_mid_turn`과 같게 "작업 중에"

## 3. '!'가 글로 들어감 (`bridge/bang_watch.py`)

- 사람 글(UserPromptSubmit 훅, 대기열 입력 포함)이 앞 공백 · 줄바꿈 뒤 `!`로 시작하면 실행되지 않고 모델에게 글로 간 것 → 텔레그램 한 번(kind `bang`, rule `bang:<세션>:<시각>`): "⚠ '!' 명령이 실행되지 않고 글로 들어갔습니다 — 「…」 세션 / ▶ !bash … / 돌리려면 터미널에서 맨 앞에 '!'(공백 없이) 또는 그 세션에 '… 실행해 줘'"
- 헛알림 확인: 제대로 실행된 '!'는 UserPromptSubmit 훅이 오지 않는다(06:03:53 `!echo HELLO WORLD` — 훅 start 없음, 트랜스크립트 start만, 턴 글은 `<bash-input>…`). 일반 사람 입력에는 훅이 온다(세션 224: 훅 start 21)
- 막지 않는다(이미 들어갔다). 지난 7건은 다시 알리지 않는다
