# Notion 프로젝트 구조 · 기술문서 자동 맞추기 · 사람 수정 보호 · Jenkins 건너뜀 (2026-11-09, 원본 폴더)

런슈즈 세션의 요청(`foreman-request-runshoes-portfolio.md`, 런슈즈 스크래치패드) 중 2절(기술문서 묶음) · 3절(뒤처짐 · 자동 게시) · 4절(Jenkins 건너뜀). 1절(근거 확인기 다른 저장소 표시)과 포트폴리오 게시는 사용자 지시로 아직 안 한다.

## 1. Notion 반영 방식 — git이 원본, 사람이 고친 블록은 덮지 않고 알림(사용자 결정)

- 사용자: "지금은 통째로 덮어써서 Notion에서 고친 게 날아가지 않나, '수정: …' 덧붙이기도 아니고"
- 확인: 통째로 덮어쓰지는 않는다 — `sync_children`이 블록을 내용으로 짝지어(difflib) 같은 블록은 id째 두고 바뀐 구간만 고친다(mermaid 미리보기가 남던 까닭)
- 가짜 Notion 실험(v1 게시 → Notion에서 문단 B 고침 · 메모 더함 · mermaid 미리보기 → git에서 문단 C만 고쳐 v2): A · 제목 그대로, C 그 자리 고침, mermaid id · 미리보기 유지 ✓ / **B는 git 내용으로 되돌아감, 메모는 지워짐 — 알림 없음** ✗. 견주는 상대가 "지난번 올린 것"이 아니라 "지금 Notion"이라서
- 실제 FOREMAN 포트폴리오 3편(54 · 96 · 79블록)은 모두 봇이 마지막으로 고친 블록 — 지금까지 날아간 사람 수정은 없었다
- 결정(사용자: "'git과 Notion이 조용히 갈라진다'는 게 맞아. 그게 이 프로젝트가 막으려는 거고"): 1안 + 보호
  - `Publisher.human_edits()` — 마지막으로 고친 쪽(`last_edited_by`)이 우리 봇(`/users/me`)이 아니고, 글이 새 원본의 어느 블록과도 다른 블록. mermaid 코드는 뺀다(미리보기만 바꿔도 사람이 고친 것). 봇 id를 못 읽으면 검사하지 않는다
  - 있으면 `HumanEdited` — 그 파일은 덮지 않고, 텔레그램 "✋ … 사람이 고친 곳이 있어 덮지 않았습니다" + 서기 할 일 한 줄과 [Notion 수정 버리고 덮기](force). git에 옮기면 글이 같아져 저절로 풀린다
- **사람이 실제로 Notion에서 고친 블록으로는 아직 못 봤다**(토큰이 봇이라 사람 수정을 만들 수 없다) — 가짜 Notion 시험만

## 2. Notion 구조(사용자 지시) — 「프로젝트」 > 프로젝트 > [기술문서] · [포트폴리오], 「인프라」

통합을 사용자가 「프로젝트」에 연결. 고치기 전(되돌리기용):

```
프로젝트 3e33218bb5248093a493f63394f7a1e7
  [기술문서]RUNSHOES-러닝화 스펙·리뷰 아카이브 3e33…324a06 (빈 페이지)
  [기술문서]펫퍼민트 … — 사내 LLM 플랫폼 구축 3ea3…9ccb (01 · 02 · 클로드 코드 · 삭제후보)
  [기술문서]FOREMAN - AI 에이전트 관제실 40f3…5aa(옛 게시 루트) — 포트폴리오 00~09가 바로 아래
  Cloudflare Tunnel 세팅 · Cloudflare Tunnel 세팅 (트러블슈팅 기록) · 인프라/서버 구축 포트폴리오 문서 · 쿠버네티스 설치
  이력서 · 데브옵스_자기소개서_초안 · 데브옵스_자기소개서_수정본(프롬프트)
```

한 일(스크립트 — 같은 제목이 있으면 만들지 않음):
- 프로젝트 페이지 셋을 만들고 `[기술문서]…` 셋을 각각 그 아래로 옮겨 이름을 「[기술문서]」로, 그 옆에 「[포트폴리오]」를 만들었다
- FOREMAN 포트폴리오 10편을 「[포트폴리오]」로(00 → 09 순서로 옮겨 번호순)
- 「인프라」를 만들고 인프라 문서 넷을 옮겼다(쿠버네티스 · Tunnel · Tunnel 트러블슈팅 · 인프라/서버 순)
- 이력서 · 자기소개서 둘은 말씀이 없어 두었다 — API로는 새 페이지를 앞에 끼울 수 없어 「프로젝트」 맨 위에 남는다(끌어서 옮겨도 게시기에는 상관없다)
- 페이지 id는 `config/notion.toml`. DB `doc_publish`의 FOREMAN 포트폴리오 10행 `parent_page_id`를 새 [포트폴리오]로 고쳤다

## 3. 게시기 — 프로젝트마다 하나

- `config/notion.toml` `[<프로젝트>]` root · docs_page · portfolio_page · github · ref · docs(off · manual · auto) · quiet_min. 브리지가 프로젝트마다 `Publisher`를 만들고(한 `NotionClient`를 같이 써 요청 간격을 같이 지킨다) 저장소 경로는 DB `project.repo_path`
- `Publisher.parent_for` — 포트폴리오는 [포트폴리오], docs/는 [기술문서]. 정해진 자리가 아니면 옮긴다. `reorder(rows, parent)` — 차례가 이미 맞으면 옮기지 않는다
- `ref` — FOREMAN은 HEAD, 런슈즈 · 펫퍼민트는 `origin/main`(push된 것). `git_show` · `git_bytes` · `content_digest` · `resolve_uploads`가 ref를 받는다
- 런슈즈 auto, FOREMAN docs off(요청 없음), 펫퍼민트 docs off — docs/README에 노션 대응(01 · 02 상위 페이지 아래 단계 문서, "노션에 옮기지 않는 문서")이 따로 있고 [기술문서]에 사람이 옮긴 사본이 이미 있다. 그 세션이 정한 뒤 켠다
- API: `POST /api/publish {project, force, action: docsync}`. Notion 오류 알림 머리말이 늘 [포먼]이던 것을 프로젝트로

## 4. 기술문서 자동 맞추기(`bridge/docsync.py`)

- 범위: ref의 `docs/` 바로 아래 `.md`(`git ls-tree`, `docs/archive/` 빼고)
- 차례: `docs/README.md` **표의 줄** 순서(README 맨 앞). 처음엔 README 어디서든 먼저 나온 이름을 따라가 overview가 requirements 앞에 왔다 → 표만 본다
- 제목(요청문 "정해서 알려 달라"): **"파일 이름 — README 표 설명의 앞부분"**(예: 「requirements — 무엇을 만드는가」, 「06_deployment — CI/CD · GitOps · 클러스터 · 스키마 변경 절차」). 런슈즈 docs는 H1이 없고 첫 줄이 "> 상태: …"라 처음엔 파일 이름만 나왔다. 괄호 안의 " — "에서는 자르지 않는다(「08_compare — 비교 페이지(설계안 — 결정 전)」). README는 「README」
- 뒤처짐: 파일마다 지문 ↔ 게시 기록(새 · 바뀜 · 지워짐 · 제목만 바뀜), 커밋 수는 `@docs-sync` 행(마지막으로 다 맞춘 ref 커밋) ↔ ref. 서기 할 일에 프로젝트마다 한 줄 "Notion 기술문서 — 커밋 N · 파일 M개 뒤처짐(새 · 바뀜 · 지워짐)" + [지금 맞추기]. 막힘 · 실패가 있으면 `@docs-sync`를 옮기지 않는다 — 뒤처짐이 남아 보인다
- 자동: 5분마다, docs 커밋 뒤 `quiet_min`(30)분 조용하면 바뀐 파일만. 지워진 원본은 휴지통. 실패 · 사람 수정은 텔레그램(같은 커밋 · 파일은 한 번)
- 서기 할 일: FOREMAN 포트폴리오도 파일마다 한 줄 → 묶음 한 줄(요청 3-1)
- 첫 실제 맞추기: 브리지를 띄우고 1분 뒤 저절로 "올림 16 · 멈춤 0 · 실패 0"(마지막 docs 커밋 09:29라 이미 조용). 제목 · 차례를 고친 뒤 [지금 맞추기]로 16편 제목 고침 · 차례 다시 세움, 08 제목 한 번 더. 06_deployment 71블록(사본 안내 · 제목 15 · 표 2 · 목록 44)

## 5. Jenkins — 문서만 바뀐 빌드는 건너뜀이 정상(요청 4절)

- 칸 이름(FOREMAN이 정함): `foremanNotify` 본문 **`"skipped": true`**(문자열 "true"도 받는다). 런슈즈 세션이 Jenkinsfile을 고친다
- `on_jenkins`: 건너뜀 + SUCCESS면 단계 글 "건너뜀 — 문서만", 이미지 태그를 붙이지 않는다 — 시작 알림 때 붙은 태그도 끝 알림에서 지운다(`tag = IF(:skip, NULL, …)`). 그래서 `_undeployed_tag`(ArgoCD OutOfSync를 붙일 "배포 안 된 최근 빌드")가 고르지 않는다
- 화면: `chainStage`가 건너뛴 빌드를 빌드 단계 성공으로 끝낸다(전에는 Jenkins 성공이면 "이미지 기다림 30분 진행 중"으로 배송 담당이 걸어갔다), 방의 이미지 칸 없음, 파이프라인 줄의 Harbor · ArgoCD는 "–"(호버 "건너뜀 — 정상입니다")
- "빌드 알림 없음"은 push ↔ 빌드 대응이라 그대로(건너뛴 빌드도 알림은 온다). 따로 "배포 없음" 경고는 원래 없었다
- 시험: 시작(태그 붙음) → 끝 skipped(태그 지움 · 단계 글) → 배포 대기로 안 고름 · 알림 없음 · 체인 깨짐 없음
