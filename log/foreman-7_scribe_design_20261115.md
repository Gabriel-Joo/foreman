**추천: 나 + 다.** 화면 숫자는 「낡은 줄 N」(나에서 표가 늦은 줄 + 다가 1 이상이면 「표에 없는 마이그레이션 M」 한 줄 더). 나를 쓰려면 단계 docs 맨 위 15줄 안에 `> 상태:` 한 줄을 두는 약속이 필요하다. CLAUDE.md가 이미 「자기가 바꾼 기능의 docs 절은 같은 브랜치에서 고친다」고 하니, 코더가 상태 줄을 고치면 표가 따라왔는지를 기계가 본다. 상태 줄이 없는 docs는 0으로 세지 말고 「상태 줄 없음 N」으로 보인다(조용히 0이 되지 않게). 처음 한 번 6개 docs에 상태 줄을 다는 것은 서기 몫이다. 단계와 docs의 짝(01, 02는 짝 없음, 11은 넷)은 코드에 박지 말고 docs 파일 이름 번호가 10 이상인 것만 단계로 본다.

## 4. 노션 기술 문서 구조안

### 4-1. 원고 자리

- 저장소 폴더 `notion/`(사용자 예). `portfolio/`처럼 원본은 git, 노션은 사본이다. `techdoc/`도 된다(종류 이름, 목적지가 바뀌어도 이름이 맞다). 추천은 사용자가 든 `notion/`
- 나무가 곧 노션 페이지 나무다
  ```
  notion/00_foreman.md            → [기술문서] 아래 「00 FOREMAN이란」
  notion/01_structure.md          → 「01 전체 구조」
  notion/02_bridge.md             → 「02 브리지」
  notion/02_bridge/01_hooks.md    → 「02 브리지」 아래 「02-1 …」
  ```
  규칙 두 줄: 폴더 `NN_이름/`는 같은 이름 파일 `NN_이름.md` 페이지의 하위 페이지다. 파일 이름 번호가 차례다. 편 수, 깊이 제한은 두지 않는다
- 편마다 머리 주석(노션에 나가지 않는 HTML 주석):
  ```
  <!-- 다루는 곳: bridge/docsync.py, bridge/notion.py, config/notion.toml
       본 판: <서기가 읽은 main 커밋> -->
  ```
  주의: 지금 `md_to_blocks`는 HTML 주석을 빼지 않는다(첫 H1 찾기 `first_h1`만 건너뛴다, `bridge/notion.py:157-179`). 이 안을 쓰려면 변환기가 주석을 빼게 고쳐야 한다
- 제목은 첫 H1(`title = "h1"`이 이미 있다)

### 4-2. 목차를 무엇으로 정하나(설정 목록 없이)

- 목차 = `notion/` 나무 그 자체. `config/portfolio.toml` 같은 주제 목록을 두지 않는다
- 서기가 정한다: 「통으로」 쓰는 세션의 첫 단계가 코드 지도(모듈 docstring, API 라우터, 화면 js, 마이그레이션, 설정 파일)를 읽고 나무를 낸다. 지난 판 나무가 있으면 그것을 고친다
- 기계가 돕는다: **「덮지 못한 코드」** = 저장소 코드 파일 가운데 어느 편의 「다루는 곳」에도 없는 것. 서기실에 수로 보이고, 다음 통 쓰기 재료 맨 앞에 목록으로 들어간다. 「코드를 보고 필요한 글을 정한다」를 기계가 거들 수 있는 몫이 이것이다
- 사람이 더한다: 받은 할 일 [＋ 할 일] 서기 몫에 「기술문서:」로 시작하는 글 → 다음 통 쓰기 재료 맨 앞(지금 「나중에 할 일 정리」가 받은 할 일을 넣는 방식과 같다). 받는 사람 칸(0028 `assignee`)을 하나 더 두는 길도 있지만 마이그레이션이 든다(정할 것 5)

### 4-5. 「이틀」 기준과 「코드와 문서가 다르면 안 된다」

**이틀을 무엇으로 재나**

| 후보 | 약점 |
|---|---|
| (가) 마지막 기술문서 서기 세션을 합친 시각(`session_action` `wt-merge`, `scribe-task techdoc`) | 없음에 가깝다. 「서기가 쓴 때」를 DB가 안다 |
| (나) 마지막 원고 커밋 시각(`git log -1 -- notion/`) | 누가 한 글자만 고쳐도 0으로 돌아간다(지금 README, 포트폴리오와 같은 문제) |
| (다) 마지막 게시 시각(`doc_publish.updated_at`) | 쓰기가 아니라 올리기를 잰다 |

**추천 (가).** 게시 뒤처짐(합쳤는데 안 올림)은 지금처럼 따로 「Notion 기술문서: 파일 N개 뒤처짐」 줄로 둔다. 이틀이 지났어도 다루는 코드가 그대로면 띄울지는 정할 것 7.

**코드와 문서를 맞게 두는 장치**(기계로 되는 것만)
1. 편마다 「본 판」과 「다루는 곳」 → 서기실에 「본 판 뒤 다루는 코드가 바뀐 편 N」(커밋 수가 아니라 편 수, 5번과 같은 셈)
2. 한 벌이 한 커밋: 통 쓰기는 본 판 하나에서 모든 편을 쓴다. 노션 맨 아래 갱신 줄에 그 커밋
3. 게시 확인 창에 「코드가 바뀐 편 N」을 보인다(막지는 않는다)
4. 근거 확인기(`bridge/evidence.py`, 지금 `c`, `t`, `log`, `docs` 네 가지)에 `[code:경로]`를 더해 파일이 있는지 본다
5. 화면 말 시험(`tests/screen_words.py`)이 지금 `docs/*.md`만 읽는다(234줄). `notion/`도 읽게 하면 옛 화면 이름이 원고에 남을 때 시험이 실패한다
