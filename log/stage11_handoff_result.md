## 설계와 달랐던 점 · 실측

- `--fork-session` 없이도 새 세션 transcript 위치는 `~/.claude/projects/<cwd의 영숫자 밖 글자를 ->/<id>.jsonl` — 첫 입력 전에는 파일이 없어서 주입 확인은 파일이 생기기를 기다린다(15초)
- 멈춤 · 되살리기를 kill -STOP/-CONT가 아니라 Ctrl+Z · `fg` 키로: 셸이 멈춘 작업을 배경으로 돌려서 밖에서 CONT를 보내면 터미널을 읽는 순간 다시 멈춘다
- 되살리기는 `session_action`에 FOREMAN의 성공한 멈춤이 마지막으로 남은 pid만 — 사용자가 남겨 둔 정지 CC 4개는 열리지 않는다(시험에 넣음)
- 작업 중단(Esc)은 이번에 실측하지 않았다

## 입력 "제출이 확인되지 않았다" (11-05 사용자 보고)

- 원인: 보낸 글 끝에 줄바꿈이 붙어 있었고 CC는 앞뒤 공백을 다듬어 기록한다("확인\n" → "확인", 끝 빈 줄 두 개 → 감싼 안쪽 끝이 한 줄). 브리지는 글자 그대로 맞대서 못 찾았다 — 실제로는 제출됐다(11:25 "확인" 두 번, 11:54 235자)
  - 그래서 11:25의 "확인" 두 번은 사람이 pane에 직접 친 것이 아니라 패널에서 보낸 것이었다(앞서 "직접 입력"이라고 한 것은 틀림)
- 고침: 맞댈 때 앞뒤 공백을 뺀다. 기다리는 시간 6 → 10초. 그래도 못 찾으면 pane을 캡처해 입력 칸(마지막 ❯ 줄 아래)에 보낸 글 앞부분이 보이는지 본다 — 안 보이면 "보냈다 — 입력 칸은 비었다", 보이면 "제출 안 됨 — 입력 칸에 남아 있다". 회색 제안 글은 보낸 글과 달라 남은 것으로 치지 않는다

## 패널 손질 (11-05 사용자 요청)

- 서브에이전트 · 다른 세션 결과: `<agent-message>` · `[Subagent hand-back] … The report follows:` 포장과 두 칸 들여쓰기를 벗기고 본문만. 여러 개가 붙은 것 · 닫는 태그가 잘린 것도. 완료 알림은 `[상태] 요약` + 결과
- 긴 글: 메시지 안 스크롤(16em)을 없애고 14줄 · 1,400자 넘으면 앞부분 + [전체 보기 (n자)]. 펼친 것은 다시 그려도 유지
- 가벼운 마크다운(제목 · 굵게 · 인라인 코드 · 코드 블록) — 이스케이프 먼저
- 응답: 상한 6,000 → 20,000자, 마지막 글 앞의 "중간 글 n"(턴 안의 다른 text 블록, 최근 12개)
- 펼침 기본값: 대화 늘 보임 · 최근 활동 펼침 · 세션 정보는 "지금 · 서브 · 오늘 출력" 한 줄을 늘 보이고 자세한 표만 접음 · 승인 이력 · 인계는 접음(머리에 상태). 바꾼 펼침은 브라우저에 기억
- 너비: 기본 380 → 340px, 창의 60% → 40%까지. 좁은 화면(760px 아래) 아래쪽 패널 48vh → 40vh. 대화 칸 최소 높이 180 → 260px
