# 12 준비 — 세션 모델 고르기 · 모델별 토큰 결과 (2026-11-05)

서기(12단계)를 만들기 전에 넣었다(사용자 결정). 서기가 일감마다 모델을 고르려면 어차피 필요하고, Opus를 어디서 쓰는지 보여야 한다는 요청.

## 한 일

- **설정** `config/models.toml`
  - 고를 수 있는 모델: opus · sonnet · haiku. `claude --model` 별칭이라 CC가 그때의 최신으로 푼다
  - 역할별 기본값: coder opus · inspector sonnet · cicd sonnet · scribe opus
  - 읽는 코드 `bridge/model_choice.py`
    - 목록에 없는 id · 셸에 못 넣는 id는 버린다
    - 고른 값이 목록에 없으면 역할 기본값, 그것도 없으면 `--model` 없이 띄운다(CC 설정)
- **띄우기** `handoff.spawn_new(model=…)`
  - `claude --model <id>`로 띄운다. 고른 값은 새 칸 `character_session.model`에 남긴다(0019)
  - 목록에 없는 모델을 API로 보내면 거부한다
  - 세션 패널의 [새로 띄우기]는 원래 세션의 역할 · 모델을 이어받는다
- **화면**
  - [+ 세션] 직접 고르기에 역할 · 모델 칸을 더했다
  - 포먼 계획 카드에 모델 칸을 더했다. 포먼(LLM)은 모델을 고르지 않고, 브리지가 `check()`에서 역할 기본값을 채운다
  - 두 곳 다 역할을 바꾸면 모델이 그 역할의 기본값으로 따라간다. 사람이 모델을 직접 고른 뒤에는 따라가지 않는다(`js/modelpick.js`)
- **지금 모델 표시**
  - 대시보드 API: 세션마다 `model`(본 대화의 마지막 응답 — `/model`로 바꾸면 따라간다) · `model_req`(띄울 때 고른 것) · `tokens.by_model`
  - 패널 머리줄에 모델 표시. Opus는 금색, Sonnet은 파랑, Haiku는 초록
  - [세션] 탭: "모델" 줄과 "모델별" 표(출력 · 입력 · 오늘 출력)
  - 방 배지: "Opus 출력 N (서브에이전트 포함 M%)", 전부 Opus면 "오늘은 전부 Opus"

- **살아 있는 세션의 모델 바꾸기(같은 날 사용자 요청)**
  - 패널 머리줄의 모델 표시(`Opus 5.5 ▾`)를 누르면 목록이 뜬다. 고르면 `POST /api/sessions/{id}/model`이 그 세션에 `/model <id>`를 보낸다(목록에 없는 id는 거부)
  - 화면 표시: 응답 모델이 바뀔 때까지 "Opus 5.5 → Sonnet"으로 보인다. 작업 중이면 "(대기열)"이 붙는다. 실제 응답 모델이 같아지면(또는 30분 뒤) 지운다
  - 고른 값은 `character_session.model`에도 남는다. [새로 띄우기]가 이어받는다
- **'/ 명령' 체크박스를 없앴다(사용자 요청)** — `js/slash.js`
  - '/'로 시작하는 입력을 화면이 판단한다
    - 경로("/api/foo …") · 여러 줄 · 기호는 글로 보낸다
    - 아는 CC 명령(/compact /model /cost …)과 `plugin:skill` 꼴은 명령으로 실행한다
    - 맥락을 날리거나 세션을 끝내는 명령(/clear /exit /quit /logout /login)은 한 번 확인한다
    - 모르는 /낱말은 명령으로 할지 글로 보낼지 묻는다
  - "기본 켜짐"만으로 두지 않은 이유: "/etc 폴더 봐줘" 같은 글이 명령으로 실행돼 모델에 가지 않는다. /clear 실수는 되돌릴 수 없다
  - 서버(`inject.guarded`)는 그대로다. '!'는 언제나 막는다

## 조사 결과

- **CC의 `/model`은 그 세션만이 아니라 새 세션 기본값까지 저장한다**(`~/.claude/settings.json`의 `"model"`, 화면 "saved as your default for new sessions")
  - 버튼은 "이 세션만"이 목적이라, 브리지가 보내기 전 값을 기억했다가 바뀐 것을 확인한 뒤 그 키만 되돌린다(없었으면 지운다)
  - 브리지로 띄우는 세션은 `--model`을 넘기므로 원래 영향이 없다. 터미널에서 그냥 `claude`로 띄우는 세션이 영향을 받는다
- **대화가 쌓인 세션에서는 `/model`이 확인 창을 띄운다**(CC 2.1.318)
  - 창: "Switch model? … This conversation is cached for the current model. Switching … means the full history gets re-read."
  - 사람이 패널에서 이미 골랐으므로, 커서가 "1. Yes"에 있을 때만 브리지가 Enter를 누른다
  - 바꾼 뒤 첫 응답은 전체 대화를 다시 읽어 느리고 토큰이 든다. 목록에 안내를 적었다
- 명령은 트랜스크립트에 글과 다른 모양으로 남는다. 그래서 주입의 제출 확인이 504(확인 못 함)를 낸다
  - 세션 화면의 CC 답("Set model to …")으로 확인한다
  - 대기열이면 지금 일이 끝난 뒤 실행되므로, 뒤에서 최대 30분 따라가며 확인 창 · 되돌리기를 한다

- 실제로 쓴 모델은 이미 응답마다 `message.model`에 있었다
  - DB 전체: opus-5-5 18,383 · opus-4-8 178 · haiku-5-5 104 · `<synthetic>` 5
  - Haiku는 CC 내부 호출(제목 붙이기 등)로 보인다. 띄울 때 고른 적은 없다
  - `<synthetic>`(CC가 만든 가짜 응답)은 모델별 집계에서 뺐다
- 서브에이전트 토큰은 `subagent_run`의 합이 `message`에서 나온다(조립기가 다시 더한다). 모델별은 `message`만 묶어 두 번 세지 않는다
  - 방 배지의 "오늘 출력"은 본 대화만 센다. 그래서 Opus 비율은 모델별 합끼리 낸다(서브에이전트 포함이라고 적었다)
- 지금 세션은 모두 Opus 5.5다. 이 세션(158)은 Opus 출력 300만 · Haiku 1.2만이다

  - 시험 중에 바뀐 CC 기본값(`haiku` · `sonnet`)은 둘 다 사용자 설정 파일에서 지워 원래 상태(키 없음)로 되돌렸다
