# 입력 칸 높이 손잡이를 눌러도 골라지게 (foreman-4, 11-15)

## 한 일
`bridge/static/js/opanel.js`의 손잡이 `pointerdown`에서 `g.focus({ preventScroll: true })`를 직접 부른다. 끌기 · 호버 글 · 더블클릭 되돌리기 · 키보드 ↑↓는 그대로다. 누르는 것만으로는 높이가 변하지 않는다.

## 원인 (실제로 확인)
- `pointerdown`의 `ev.preventDefault()`(끄는 동안 글자 고르기 · 쪽지를 막으려는 것)가 브라우저 기본 포커스까지 막고 있었다. 고치기 전에는 눌렀다 떼도 `document.activeElement`가 `BODY`였고, 그 뒤 ↑를 눌러도 높이가 그대로였다
- 사용자가 말한 「탭으로 짚어야만 먹는다」는 Tab 키로 포커스를 주는 것이었다(손잡이가 입력 칸 앞이라 Shift+Tab으로 짚었다)

## 실제로 쟀다 (미리보기 :8200, 헤드리스 크로미움, 진짜 마우스 · 키 이벤트, 창 1366 × 768, 세션 418 패널)

| 단계 | 고치기 전 활성 요소 / 칸 높이 | 고친 뒤 활성 요소 / 칸 높이 |
|---|---|---|
| (가) 눌렀다 떼기만 | BODY / 42 | pGrip / 42 (높이 그대로, `:focus-visible` 참) |
| (나) 그 뒤 ↑ 한 번 | BODY / 42(안 바뀜) | pGrip / 66(+24) |
| (나) ↓ 한 번 | BODY / 42 | pGrip / 42 |
| (다) 위로 80 끌기 | 132 | 131 |
| (다) 위로 20 자리로 되돌림 | 64 | 64 |
| (다) 위 끝 넘김 | 345 | 345 |
| (다) 끝에서 30 되돌림 | 311 | 312 |
| (라) 더블클릭 | 42 | 42(원래 높이) |
| (바) 쓰던 중 손잡이 누름 | pText 그대로 | pGrip(글 `abc` 그대로) |
| (바) 칸을 다시 눌러 이어 침 | `def` 들어감 | `def` 들어감(글 `adefbc`, 누른 자리에 들어간 것) |
| (마) Shift+Tab으로 짚기 | 손잡이 | 손잡이(그 뒤 ↑ 42 → 66) |

- 끌기 숫자의 1px 차이는 놓는 지점의 반올림 차이이고, 끝 넘김 뒤 되돌림도 417 측정처럼 마우스를 따라온다
- 포커스 테두리: 손잡이는 가운데 막대 색만 바뀌어(`rgb(46,47,51)` → `rgb(154,154,160)`, 호버 · 끌기와 같은 색) 마우스로 눌렀을 때도 Tab으로 짚었을 때와 같은 모양이다. 눌러서 골랐다는 표시가 남는 셈이다. 입력 칸을 누르면 풀린다
- 입력하던 중 손잡이를 눌러도 글은 남고, 칸을 다시 눌러 바로 이어 칠 수 있다. 다만 전에는 손잡이를 눌러도 칸이 포커스를 지켰는데, 이제는 손잡이로 옮겨 가므로 누른 뒤 칸을 한 번 더 눌러야 친다
- 페이지 오류 0. `node --test tests/js/` 198개 통과. `tools/screen.py --base http://127.0.0.1:8200/ --no-term` 세 테마 문제 0건
- docs: 이 손잡이를 적은 docs 절이 없어 고치지 않았다. 측정 스크립트는 scratchpad에만 두었다. 미리보기(:8200)는 끝내고 껐다. 서브에이전트 · 예약 없음
