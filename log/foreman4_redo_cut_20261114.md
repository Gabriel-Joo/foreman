# 계획 다시 받기가 앞 계획을 끊음(foreman-4, 11-14, 받은 할 일 #18)

## 한 일
- `bridge/foreman.py`: `plan()`이 사람 계획을 받을 때 같은 프로젝트에서 도는 앞 사람 계획을 `_cut_earlier`로 끊는다. 앞 `claude -p`는 보관한 프로세스(`_procs`)의 PID로만 죽인다. 프로세스를 띄우는 중에 끊겨도 띄운 직후 죽인다
- 끊긴 dispatch는 status `replaced`(VARCHAR(10)에 들어감, 스키마 변경 없음) · error 「다시 받기로 끊었습니다」. 늦게 온 결과는 `_cut` 번호로 거르고 파싱 · 사용량 기록 · 계획 확인에 들어가지 않는다
- `start()`의 거부 사유에 `replaced` 추가
- `tests/test_foreman_redo.py`: 가짜 claude로 앞 프로세스 종료 · 앞 결과 무시 · `running` 하나만 · wake · 다른 방은 안 끊음
- docs `11_foreman_dispatch.md`에 한 줄 추가

## 판단
- 화면의 [계획 받기]/[다시 물어보기]는 묻는 중 버튼이 꺼져 있어, 겹침은 창을 닫았다 다시 열기 · 다른 탭 · 새로 고침에서 생긴다. 서버가 막아야 맞아 JS는 건드리지 않았다
- 끊는 기준은 「같은 프로젝트 + 사람 출처」. 같은 방에서 일부러 두 계획을 동시에 받는 길은 없다고 보았다
