## 1. claude -p 사용량 기록 (11-08)

- 빠진 것: 디스패처 · 압축 손실 점검은 `--no-session-persistence`라 트랜스크립트가 없어 `message` 표에 안 들어왔다. 인계 요약(`claude -p --resume`)은 그 세션 트랜스크립트에 이어 써져 이미 들어온다(요약 시각 근처 메시지 확인)
- 실제로 빠진 양은 작았다: 디스패처 약 8번, 기계 점검 1번(실패). 11-05 손 점검은 세션 안 서브에이전트라 집계돼 있다. 앞으로 자동 기상이 하루 5번까지 부르므로 지금 막았다
- `claude -p --output-format json`의 `modelUsage`(실측, Haiku "1"): 모델마다 inputTokens · outputTokens · cacheReadInputTokens · cacheCreationInputTokens · **costUSD(CC가 정가로 계산)** · 캐시 쓰기 5분/1시간 나눔. CC는 캐시를 1시간짜리로 쓴다 → 캐시 쓰기 정가는 입력의 2배(설계 2절 표를 그에 맞춤)
- `bridge/usage.py`(`cli_rows` · `record_cli`) → `usage_extra`(0026, 관찰 표 `usage_observation`도 같이). 디스패처는 계획마다, 점검은 묶음마다. 기록 실패는 호출한 쪽을 막지 않는다
- 실제 확인: 디스패처 #25(〔시험〕, 버림) → `claude-sonnet-5-5` 출력 246 · 캐시 읽기 10,885 · 캐시 쓰기 27,732 · $0.1145 — 1시간 캐시 정가로 손계산한 값과 맞는다
- 그 사이 정정: 주간 88% 관찰의 환산을 캐시 쓰기 1.25배로 셈한 $759 → 2배로 **$838**, 하한 약 $950
- 시험: `tests/test_usage.py`(실제 JSON 모양 · 모델 둘 · 옛 모양 · DB 기록). 전체 461 통과

## 2. 집계 · 환산 · 창 · /usage 읽기 · /api/usage (11-08)

사용자 결정(11-08): 관찰은 `claude -p "/usage"`로(tmux 화면 읽기는 보조 — 오늘 세션 둘이 `/usage` 화면 때문에 막혔다). 주간 리셋은 **일요일 22:00**(앞서 말한 "토요일"은 사용자 착오, 11-08이 일요일).

- `bridge/usage.py`
  - 환산: `config/usage.toml` 가격표(모델 이름에 든 글자로), 표에 없는 모델(`<synthetic>`)은 0
  - `/usage` 글 풀이: `claude -p` 한 줄 모양과 tmux 여러 줄 모양(머리 · 막대 · Resets) 둘 다. 리셋 글 "Nov 8, 12:10pm (Asia/Seoul)" · "12:10pm"(지났으면 다음 날) · 연말 넘김. 줄 머리를 하나라도 못 찾으면 실패로 센다(글 모양이 바뀐 것을 조용히 넘기지 않게)
  - 창: 읽은 리셋이 앞이면 [리셋 − 창, 리셋). 지났으면 주간은 7일씩 넘기고, 5시간은 리셋 뒤 첫 메시지부터 다시 짓는다(`chain_windows`). 첫 메시지가 거꾸로 셈한 시작보다 몇 분 앞서도(10-23 사례) 읽은 창에 넣는다
  - 하한: 관찰마다 그 창의 환산액 `seen_usd` → 하한 = seen ÷ % × 100, 5% 아래는 뺀다, 높은 %에 무게, 범위 · 근거 수 · 10% 안이면 안정. 읽기 사이 추정 % = 측정 % + (지금 창 환산 − 읽을 때 환산) ÷ 하한. 최근 1시간 속도로 100% 시각, 리셋 전인지
  - 표: 모델 · 프로젝트 · 세션(제목 · 프로젝트) · 시간(UTC 정시)별 토큰 넷 · 환산액 · 비중. `usage_extra`는 "claude -p · dispatch" 같은 세션 줄로
  - `UsageMonitor`: 600초마다 읽기, 같은 (한도, %, 리셋)은 한 번만 기록(`uq_uo_raw`), 연달아 3번 실패 → 텔레그램 한 번 · 돌아오면 한 번, 마지막 읽은 시각 · 오류 · 낡음(poll × 3 + 60초)을 화면용으로. **CC 로그인 만료**(`credential_expires_at`)가 24시간 안이면 텔레그램 한 번 — 만료되면 모든 세션이 말없이 멈춘다
- `/api/usage`(20초 캐시, 기간은 지금 주간 창 또는 `?hours=`) · `POST /api/usage/poll`. 시각은 UTC ISO
- 설정 `usage_enabled` · `usage_config`. 앱을 띄우는 시험 둘(`test_app_db` · `test_terminal`)은 꺼 둔다 — 켜면 실제 `claude -p`를 부르고 운영 DB에 남긴다
- 마이그레이션 없음(0026 그대로). `message.created_at`에 색인이 없지만 2.1만 행, 7일 집계 0.01초

## 3. /usage 페이지 (11-08)

사용자 요청: "시간당 $19면 꽤 쓰는 건데 어디서 많이 나가는지" — 페이지에 같이.

- `bridge/static/usage.html`(`/usage`, 토큰은 픽셀 화면과 같은 `localStorage.foremanToken`): 읽기 상태(마지막 읽은 시각 · 못 읽으면 붉은 띠 · 실패 횟수), 로그인 만료 24시간 안이면 띠, 한도 카드 셋(측정 · 추정 % · 막대 · 리셋까지 · 창 환산 · 하한(근거 · 범위 · 흔들림) · 최근 1시간 속도 · 이 속도면 언제 100% — 리셋 전이면 붉게), **어디서 나가나**(최근 1시간 · 기간의 토큰 종류별 쌓은 막대 + 쏠림 설명: 캐시 읽기 비중 · 응답당 맥락이 큰 세션 셋), 시간대별 그래프(종류별로 쌓음 · 주간 리셋 점선 · 지금 5시간 창 음영), 세션 표(**응답당 맥락** = 캐시 읽기 ÷ 응답), 프로젝트 · 모델 표, 관찰 기록. 기간 고르기(주간 창 · 24시간 · 3일 · 2주), [지금 읽기], 1분마다 다시 불러옴
- API: 표마다 종류별 환산(`usd_input` 등) · `by_kind`, `recent`(최근 1시간), `observations`(최근 40)
- 하한에 넣는 최소 %를 5 → **20**으로: 12:14 리셋 뒤 5시간 7%($2.34 → $33)가 52%($87)와 크게 어긋났다(정수 반올림 ±0.5%p가 7%에서는 ±7%)
- 화면 확인: 1280 밝음 · 어둠, 390 어둠 — 가로 넘침 없음, 페이지 오류 없음
