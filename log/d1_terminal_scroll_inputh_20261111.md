## 1. 열둘 — 터미널이 방을 따라가지 않는다

**원인: 터미널은 방을 따라갔고, 따라가지 않은 것은 접힌 막대의 이름표였다**(사용자 11-11 확인).
- 라이브 브리지(:8000)와 헤드리스 크로미움으로 따라 해 봤다 — 런슈즈 방 → 펫퍼민트 방, FOREMAN 방 → 런슈즈 방 모두 방을 옮기면 `/api/terminal/open`이 호출되고 그 탭의 그룹 세션 창이 바뀐다. `foreman-term-view`도 처음 주소의 프로젝트(`arg`)로 창을 고른다(새 탭 id + `runshoes`로 직접 돌려 확인). 서버 · 스크립트 · 펼친 화면은 문제없었다.
- 접힌 채는 `terminal.js`의 따라가기 타이머가 `open`일 때만 돌아, 막대의 「런슈즈 터미널」이 앞 방 이름으로 남았다. 펼칠 때 `setOpen`이 그제서야 창과 이름을 함께 바꿨다.
- 고침(`8ead461`): 접힌 채에도 타이머가 돌아 `want` · 막대 이름만 바꾼다. tmux 창은 건드리지 않는다(접힌 터미널이 창을 만들지 않게). 펼치면 그 프로젝트 창을 실제로 고른다.
- 확인: 열었다 접은 뒤 방 옮김 → 이름표 `runshoes` → `petmint-rag-chatbot` → `foreman` 즉시, 다시 펼치면 `foreman`, 경고 없음.

## 2. 열하나 — 터미널 스크롤 (`014f3de`)

- xterm 스크롤백은 tmux가 화면을 다시 그려 비어 있다 → tmux 복사 모드로 올려 본다.
- 휠: `deploy/shell/foreman-term-view`가 그룹 세션에만 `set-option mouse on`(세션 옵션 — 서버 전체 · 다른 CC 세션에는 걸리지 않는다. 시험으로 기준 세션은 안 바뀜 확인). 휠을 올리면 복사 모드, 맨 아래에서 저절로 나온다. 부작용: 이 탭의 마우스 끌기는 tmux가 받는다(브라우저 글 선택은 Shift+끌기).
- 단추: `POST /api/terminal/scroll {tab, action: up|down|exit}` → `copy-mode -eu` · `send-keys -X page-down` · `cancel`. 막대에 「▲ 위로」, 복사 모드 중에는 「▼ 아래로」 · 「입력으로」(primary)가 나온다. 복사 모드 여부는 `current()`의 `scrolling`(`#{pane_in_mode}`)을 3초 확인에 얹었다.
- **복사 모드에 들어간 채 입력하면**: 친 글은 셸이 아니라 복사 모드 키로 간다(셸에는 안 들어간다). 그래서 막대가 「입력으로」를 앞에 세우고(툴팁에 그 사실을 적었다), `-e`로 맨 아래에 닿으면 저절로 끝난다. CC 부탁이 셸에 미리 채우는 `prefill`은 전부터 복사 모드면 먼저 `cancel`로 나온 뒤 채운다(`bridge/terminal.py` prefill) — 그 길은 안전하다.
- 탭 그룹 세션 · [새 셸]: 스크롤은 탭의 보이는 창만 다룬다. 복사 모드 칸(pane)은 창(셸)에 딸려 있어 같은 창을 보는 다른 탭에서도 스크롤 중으로 보일 수 있다(시험에 적음). [새 셸](`respawn-pane -k`)이 복사 모드를 끝내는지는 확인하지 않았다.
- 시험: `tests/test_terminal.py` — scroll 올림/내림/끝내기, 탭 없음 · 잘못된 동작 거절, 그룹 세션만 mouse on(기준 세션은 아님). 33 통과.
- `store.js`: `terminalScroll` 한 메서드만 더했다(맡은 파일 밖 몇 줄, 이 일에 꼭 필요).
- 미리보기(`bridge.preview`)는 `/api`를 원본 브리지로 넘기므로 **`/scroll` 단추는 합친 뒤 브리지를 다시 띄워야 라이브에서 돈다.** 이 확인은 pytest로만 했다(헤드리스 화면 확인 못 함).

## 3. 열셋 — 패널 입력 칸 높이 끌기 (`opanel.js` · `office.html`)

- 입력 칸 위쪽 모서리에 가는 띠(`#pGrip`) — 위로 끌면 커진다. 키보드 ↑ ↓, 더블클릭은 기본 높이로. 오른쪽 아래 모서리 `resize`도 그대로 되고 그것도 기억한다.
- 기억: `localStorage.foremanInputH`(try/catch, 없어도 기본 높이). 처음 보일 때 한 번 복원.
- 상한: 대화 칸이 80px 아래로 줄지 않는 높이(`MIN_CONVO`)와 창 높이의 45% 중 작은 것. 원래 낮아 대화 칸이 80px 미만인 창(1024 × 700 · 150%)은 키울 수 없고 클릭만으로 저장 · 변경도 일어나지 않는다.
- 글씨 배율(`zoom`)이 걸린 패널이라 높이는 CSS px, 마우스는 배율로 나눈다(1366 · 125%에서 끌어 보며 맞춤).
- 확인: 1920 × 1080에서 60px 끌기 → 정확히 +60, 최대 486(창 45%), 새로고침 뒤 유지. 1366 × 768 · 125%는 대화 칸 80px에서 멈춤. 1024 × 700 · 150%는 변화 없음. 패널 너비 두 값은 그대로.

## 4. 작업 중 오라 — 맡은 파일 밖(`400e5cf`)

**맡은 파일 밖 — 관리자 허락 11-11**(세션 276이 drawHeat 둘레만 허락, A · C1과 파일 안 겹침).
- 사용자: 디자이너 캐릭터에만 보라 원이 안 뜬다. 원인 — 그 원은 「활동 중」이 아니라 **사용량 열기**(`drawHeat`)로, 지난 30분 비용 상위 3개(`usage.hot`)에만 붙었다. 디자이너(Sonnet)는 비용이 낮아 빠졌다.
- 사용자 결정: 작업 중이면 모두, 쉬면 끈다. 비용 표시는 필요 없다(맨 윗줄에 있다).
- 고침: `drawHeat` 조건 `hotOf.get()` → `a.s.state === 'ACTIVE'`, 세기 고정 0.8. 세 테마(마법학교 마력 오라 · 오피스 김 · 현장 아지랑이 · 도형 고리) 같은 조건. 서버 `usage.hot` · `hotOf`는 그대로(오라에는 안 쓰고 남아 있다).
- 마법학교 사진: 작업 중인 디자이너 · 코더 · 코더 임시에 오라, 쉬는 관리자 · 코더 상주에는 없다. 한 방에 셋이 동시에 켜질 때 서로 겹치는 곳은 코더 상주와 임시가 같은 구역에 설 때뿐이었고 읽기 어렵지 않았다(작업 책상 · 시약대).

## 6. 되돌리는 법

스위치 없는 화면 변경이라 되돌리기 = revert. 단계별:

| 되돌릴 것 | 커밋 | 브리지 |
|---|---|---|
| 접힌 이름표 따라가기 | `8ead461` revert | 필요 없음(화면만, 새로고침) |
| 스크롤(휠 · 단추 · 스크롤 중 표시) | `014f3de` revert | **다시 띄워야 한다**(`/scroll` · `scrolling`은 브리지 코드). 이미 열린 그룹 세션의 `mouse on`은 탭을 닫았다 열면 사라진다 |
| 입력 칸 높이 끌기 | 마지막 커밋(「패널 입력 칸 높이…」) revert | 필요 없음. 기억된 `foremanInputH`는 무해(안 읽는다) |
| 작업 중 오라 | `400e5cf` revert | 필요 없음(화면만) |

- 스크롤만 급히 끄려면: `foreman-term-view`의 `mouse on` 한 줄을 지우고(휠 끔) 단추는 `terminal.js`에서 숨긴다 — 커밋 revert가 더 안전.
- 이 일은 띄우기 · 끝내기 길을 건드리지 않았다.

## 7. 조용한 고장 점검

- 스크롤: 복사 모드에 들어간 채 두면 친 글이 셸로 안 간다 → 막대에 「입력으로」가 3초 안에 나온다(표시). 스크롤 API가 실패하면 막대 경고(`스크롤하지 못했습니다 — …`)가 뜬다. 텔레그램은 보내지 않는다(사람이 보고 있는 화면 동작이라 알림 대상이 아니다).
- 이름표: 접힌 막대의 이름은 방을 따라가는 표시일 뿐이고, 펼치면 실제 창을 다시 읽어 경고(고른 것과 다른 터미널)가 뜬다.
