# 펫퍼민트 기술문서 멈춘 편 읽기 조사 (11-17, 서기 foreman-5, 관리자 410 일감)

읽기만 한 조사다. 노션에 쓰지 않았고(게시, 덮기, 맞추기, 짝 바꾸기 모두 안 함) 펫퍼민트 저장소와 DB 행도 고치지 않았다. 사람이 결과를 보고 편별로 덮을지 정한다.

## 0. 한 줄 결론

멈춘 7편(09, 11, 12, 13, 14, 15, 16) 모두 **노션에만 있는 글이 없다.** 노션이 git과 다른 곳은 전부 git 역사에 있던 옛 판 글이거나(13블록), 노션에서 글이 빠진 쪽이다. 일곱 편 모두 「바로 덮어도 됨」이다. 옮길 글이 없어 git으로 옮기는 일도 없다.

한계: 노션 쪽지 댓글은 읽지 못했다(통합에 권한이 없어 403). 글자만 비교했고 링크 주소와 글꼴 꾸밈은 보지 않았다(게시기 판정도 보지 않는다). 아래 6절.

## 1. 멈춘 편 목록과 7과 6의 까닭

기준은 `origin/main` 로컬 참조 `ef8042ee`(내가 fetch하지 않았다), 노션을 읽은 날은 11-17이다. 짝은 20편(`doc_publish`, `docs/` 아래 게시됨)이고 그중 13편은 노션 글과 git 글이 같다(00~08, 10, `pipeline.md`, `requirements.md`).

실제 판정 길을 따랐다. 펫퍼민트는 `keep_notion`에 `shape`가 들어 있어서 `Publisher.human_edits`(1303줄)는 이 프로젝트에서 부르지 않는다. 판정은 `_publish_shape`(1413줄)이다. 쪽 전체 글(`compact`, 꾸밈 표시와 공백을 뺀 글)을 견주고, 노션이 지난번 맞춘 git 판(짝의 `commit_sha`)과 다르면 멈춘다(`HumanEdited`). 그리고 맞추기는 `status()`의 새 것과 바뀐 것(지문 `content_hash`가 다른 편)만 시도한다.

| 09_ui_design | 아니오(지문 같음) | 시도하지 않아 멈춤으로 안 센다. 시도했다면 사람 수정으로 멈춤 |

**7과 6의 차이는 09 하나다.** 펫퍼민트 관리자가 센 7개는 09, 11, 12, 13, 14, 15, 16이고 게시기는 `changed` 6편(11~16)만 센다. 09는 짝의 지문이 git 원본과 같아(`_publish_one`의 `content_hash == digest`, 1380줄) 맞추기가 「안 바뀜」으로 건너뛰고 `_publish_shape`에 가지 않는다. 그런데 노션 글은 git과 다르다(2절). 곧 09는 게시기가 한 번도 안 본 채 노션이 갈라진 편이다. 지문 같음이 노션이 안 바뀌었다는 뜻이 아니기 때문이다.

확인: `GET /api/scribe/todo`의 `docs_pub`가 `changed: 6`, `last.held: 6`, `last.failed: 1`(`docs/TODO.md`, 번호 없는 파일이라 새 페이지 제목을 못 정함, 멈춤과 별개)이고 위 표의 11~16이 정확히 그 6편이다. 이름은 내 재현이고 todo 응답에는 편 이름이 없다.

또 하나. 12, 13, 14는 이름은 「사람 수정으로 멈춤」이지만 노션 글이 지난번 맞춘 git 판과 같다(노션∉지난판 0자). 사람이 글을 고친 것이 아니라 git이 바뀐 곳에 표가 있어 자동 패치(`shape_patch`)가 사람 수정 멈춤 글을 내며 멈춘 것이다. 진짜 사람 수정 후보는 09, 11, 15, 16이다.

## 3. 덮기 전에 알 것(권고, 관리자 판단용)

- 덮는 길은 편마다 사람 승인 뒤 force 게시(`sync_children`)다. 펫퍼민트는 `keep_notion`(heading, image, inline_code)이 있어 제목 단계, 그림, 인라인 코드 꾸밈은 노션 모양이 남는다. 이 조사는 글만 봤고 덮은 결과의 모양은 보지 않았다
- 12, 13, 14는 사람이 고친 글이 없으니 force 없이도 풀리게 하는 길이 있다. 자동 패치가 표 때문에 멈추는 것이 문제라서, 표가 든 바뀜은 force로만 덮인다. 이 조사는 코드를 고치지 않았다

## 5. 방법

- 읽기 길: 임시 폴더(`mktemp -d`)에 스크립트를 Write로 만들어 `.venv/bin/python -I`로 돌렸다. 노션 클라이언트는 `NotionClient`를 이어받아 `_call`이 GET 밖을 거부하게 했다(쓰기 함수를 못 부른다). 쓰기를 부르는 `publish`, `sync`, `pair`, `archive`, `update_block`, `append` 등은 한 번도 부르지 않았다. DB는 `SELECT`만. 판정은 `_publish_shape`를 읽어 따라 하되 쓰기 줄은 빼고 계획 단계만 돌렸다
- 비교 글: `shape_text`와 같은 거름(꾸밈, 공백, 하위 페이지, 맨 아래 갱신 줄, 하위 페이지 제목과 같은 목록 줄). 스크립트에서 내 평탄화가 게시기의 `flat_notion`, `shape_text`와 같은 결과인지 단언으로 맞췄다. 같지 않았으면 멈추게 했고 멈추지 않았다
- 글자 단위: 노션 글(`old_t`)과 현재 git 글(`new_t`), 지난 git 글(`prev_t`)을 `difflib.SequenceMatcher`로 맞춰 노션의 안 맞은 글자를 뽑았다. 줄바꿈, 공백, 빈 블록, mermaid, 갱신 줄은 게시기와 같이 이미 빠진다. 안 맞은 글자를 블록에 되돌려 놓고 그 블록 글이 통째로 역사 판(`git log --follow`로 모은 판마다 `md_to_blocks`한 글)에 있는지 봤다. 있으면 옛 판, 없으면 노션에만. 6자 이상일 때만 조각 단위로도 봤다
- 노션 읽기: 7편의 블록 나무 전체(하위 블록까지)를 `children`으로 읽었다. 블록 종류를 세어 그림, 캡션, 수식, 임베드, 콜아웃, 토글, 동기화 블록이 없음을 확인했다(글 칸이 없는 블록에 숨은 글 없음)

## 6. 못 본 것

- 쪽 댓글: `GET /comments`가 `403 Insufficient permissions`다. 통합에 댓글 읽기 권한이 없다. 노션 댓글에만 있는 글이 있는지는 모른다
- 링크 주소(href)와 꾸밈(굵게, 코드)은 글자 비교에 들지 않는다(게시기도 안 본다). 쪽마다 링크가 1~5개 있다
- 쪽 제목과 속성은 보지 않았다
- ref는 로컬 `origin/main`(`ef8042ee`)이다. fetch하지 않았으니 GitHub와 어긋나 있을 수 있다. 게시기도 같은 참조를 쓴다

## 7. 비밀값

- 토큰은 `bridge.notion.load_token`으로 파이썬 메모리에서만 읽었다. 화면, 파일, 로그에 찍지 않았다. 브리지 API 토큰도 같다(todo 읽기 스크립트가 메모리에서만 썼다)
- 스크립트가 찍는 것은 편 경로, 개수, 노션 글(문서 본문)뿐이다. 결과 JSON 둘과 이 기록에서 노션 토큰 값을 개수로 센 검사(`grep -cF`)는 모두 0이었다. 토큰 꼴(`ntn` 시작, `secret` 시작, `Bearer` 뒤 글자) 검사도 JSON 둘은 0이었다. 이 기록에서는 꼴 검사가 1이었는데 7절 이 줄이 패턴 이름을 적은 것이어서 지금 글로 바꿨다

## 8. 규칙 위반

규칙 위반 없음. (`pgrep -f` 안 씀, 파일은 Write로만 만들고 Edit로만 고침, 코드와 브리지를 건드리지 않음, push와 브리지 재시작 안 함, 임시 폴더는 저장소 밖.) 한 가지 적어 둔다: 읽기 스크립트를 돌리려고 `bridge.config.get_settings()`가 DB 비밀번호와 브리지 API 토큰을 같은 프로세스 메모리에 올렸다. 출력하지 않았다.
