## 알아보는 꼴

두 저장소 원고(FOREMAN `notion/`, `portfolio/`, 인프라 `notion/`, `portfolio/`)에서 실제로 쓰는 꼴을 찾아 모두 받게 했다.

| 꼴 | 예 | 받나 |
|---|---|---|
| 줄 안 하나 | `자세한 것은 → 「승인 카드」에서 다룬다.` | 받는다 |
| 줄 안 여럿 | `→ 「겹침 알림」과 → 「계획 한 번」.` | 받는다 |

| 목록 안(중첩 포함) | `- … → 「GPU와 호스트 서비스」에서 다룬다` | 받는다 |
| 굵게 안 | `**… → 「제목」**` | 받는다(링크에 굵게) |

| 번호째 제목(FOREMAN) | `→ 「03 세션 지켜보기와 글 넣기」` | 그대로 맞춤 |
| 번호 없는 제목(인프라) | `→ 「손으로 세운 클러스터」`(H1 `02-01 손으로 …`) | 번호 뗀 색인으로 |

| 머리 주석 안 | `<!-- … → 「x」 -->` | 주석을 먼저 떼어 보지 않는다 |

받지 않는 꼴: 낫표 없이 화살표만 쓴 것(`notion/10_scribe/01_room.md` 49줄 「→ 압축 손실 재기와 → 문서로 옮기기」). 인프라 점검 스크립트 5번 규칙도 낫표 꼴만 보므로 같은 기준으로 두었다. 원고 쪽 몫이라 고치지 않았다.

## 아직 안 올라간 편: 고른 안과 까닭

지금까지는 이미 올라간 편만 링크로 바꿨다(`Ctx.pages`가 게시 기록에서 url이 있는 편만 모은다). 두 안을 합쳤다.

1. **기억(지문 비우기)**: 아직 없는 편을 가리킨 채 올라간 편은 `doc_publish.content_hash`를 NULL로 둔다. 새 표나 칸을 만들지 않았다. 그 편은 docsync 상태와 포트폴리오 목록에서 「바뀜」으로 잡혀 「바뀐 것 없음」으로 건너뛰어지지 않는다. 짝 등록(pair) 행도 지문이 NULL이지만 `commit_sha`도 NULL이라 `commit_sha IS NOT NULL`로 가른다
2. **다시 걸기**
   - 한 쪽 게시(포트폴리오 [게시], API `action: publish`): 한 편이 올라간 직후 `relink`가 그 편을 기다리던 편만 다시 올린다. 다른 편을 기다리는 편은 건드리지 않는다(시험 `test_relink_skips_pages_waiting_for_other_targets`)
   - 한 번 게시(docsync, FOREMAN과 인프라의 [Notion에 올리기]): 편마다 다시 걸면 편 수의 제곱만큼 노션을 부른다. 그래서 다 올린 뒤 `pending`이 있던 편만 한 번 더 돈다(두 번 돌기)

까닭: 두 번 돌기만 하면 포트폴리오처럼 사람이 한 편씩 올리는 길이 풀리지 않는다. 기억만 하면 사람이 다시 눌러야 한다. 지문을 비우는 방식은 새 저장소 없이 「바뀜」 표시와 다음 게시를 그대로 쓰고, 끝내 못 거는 편이 조용히 「그대로」로 보이지 않는다. 포트폴리오 「차례 다시 세우기」(`reorder_portfolio`)는 페이지를 옮기기만 하므로 여기에 다시 걸기를 넣지 않았다.

남는 경우:
- 끝내 없는 제목, 겹치는 제목: 글자로 두고 경고(결과 줄, 로그)
- 가리킨 편이 막혀 끝내 못 올라감: docsync 두 번째 돌기 뒤에도 `pending`이면 「가리킨 편이 아직 Notion에 없어 링크를 못 걸었습니다」 경고, 지문이 비어 있어 다음 맞추기에 다시 시도
- 마크다운 상대 링크(`[…](../notion/x.md)`)가 아직 없는 편을 가리킬 때는 지금처럼 글자만 남고 기억하지 않는다(이번 범위 밖, 포트폴리오에서 노션 원고로 가는 한 줄)
- 가리킨 편의 페이지가 지워져 새로 만들어져 주소가 바뀌어도, 가리키는 편 본문이 같으면 「바뀐 것 없음」이라 옛 주소가 남는다. 드문 경우라 두었다
