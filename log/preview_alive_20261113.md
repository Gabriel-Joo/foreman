# 미리보기가 죽어도 「있음」으로 답하던 조용한 고장 (일감 E, 11-13)

## 한 일
- `bridge/preview.py`: 미리보기 브리지에 확인 주소 `/__foreman_preview`를 넣음(응답 머리 `X-Foreman-Preview: 1` + `{"foreman_preview": true}`). 프록시보다 먼저 등록해 지금 브리지로 넘어가지 않음
- `bridge/previews.py`:
  - `_probe(port)` — 127.0.0.1의 그 포트에 확인 주소를 두드려 **미리보기 브리지로 답할 때만** 참. 포트만 열린 남의 서비스(`model_service` 같은)는 거짓
  - `get()` — 기록이 있어도 tmux가 살아 있고 `_probe`가 참일 때만 「있음」. 아니면 기록을 치우고 남은 tmux도 끄고, 까닭을 `self.dead[경로]`에 남김
  - `start()` — 죽은 기록이면 치우고 다시 띄움(결과에 `restarted`, `was_dead`). 다시 띄우기도 실패하면 「미리보기가 죽어 있습니다 — 까닭. 다시 띄우지 못했습니다: …」로 거부(패널이 보여 주는 서버 거부 사유)
  - `_ready()`도 단순 연결이 아니라 `_probe`로 — 남의 서비스가 그 포트를 잡고 있으면 「떴다」로 치지 않음
- `bridge/handoff.py`: 세션 상태에 `preview_dead`(죽어서 기록을 치운 까닭, 없으면 None) 추가
- 시험(`tests/test_preview.py`): 확인 주소 · 정상 · 죽은 tmux→다시 띄움 · 포트가 남의 서비스 · 다시 띄우기 실패 · 포트 사용 중이면 다른 포트. 전체 pytest 821 통과 · node 132 통과

## 설계와 달랐던 점
- 일감 4번(포트가 남에게 잡혀 있으면 다른 포트): `free_port()`가 이미 127.0.0.1 bind로 빈 포트를 고르고 있어 코드는 그대로 두고 시험만 더함. 8200의 `model_service`는 192.168.122.1에 묶여 있어 127.0.0.1 bind와는 부딪히지 않음 — 이번 고장은 포트 충돌이 아니라 서버가 죽은 기록이 「있음」으로 남은 것
- 텔레그램은 보내지 않음: 미리보기는 사람이 버튼으로 연 것이고, 거부 사유가 그 자리(패널)에 바로 뜸. 알림까지 쏘면 소음이라 판단. 필요하면 관리자가 정함
- 패널 JS는 건드리지 않음(`render.js` · `office.js` 다른 코더 몫). `preview_dead` 칸을 화면에 띄우는 것은 후속

## 판단 근거
- 포트 하나만 보면 `model_service` 같은 다른 서비스에 속으므로 미리보기만 가진 확인 주소 + 응답 머리로 가름
- 기록 위주가 아니라 실제 응답 위주로 「있음」을 정해 기록과 현실이 어긋나도 조용하지 않게 함

## 주의
- 이미 떠 있던(옛 코드로 띄운) 미리보기는 확인 주소가 없어 「죽음」으로 보고 다시 띄워짐 — 한 번만 일어남. 합친 뒤 브리지를 다시 띄워야 서버 쪽이 돈다
