## 실측 — 방법 C (CC 2.1.316, probe CC, Haiku)

보낸 원문과 트랜스크립트 user 줄을 바이트 단위로 비교했다.

| 입력 | 결과 |
|---|---|
| 여러 줄 + `"` `'` `$HOME` 백틱 `\` 한글 들여쓰기 | 그대로. **여러 줄 붙여넣기는 `\n\n<pasted_content id="…">\n…\n</pasted_content id="…">\n`로 감싸여** 모델에 간다 — 이 대화에서 사용자 지시가 같은 모양으로 오는 이유. 한 줄은 감싸이지 않는다 |
| 탭 | **공백 4칸으로 바뀐다** |
| 긴 붙여넣기 60줄 · 3,036자 | 원문 그대로 기록(화면은 접혀도). README 3.1의 미검증 하나가 풀림 |
| 첫 글자 `/` | **슬래시 명령으로 실행**(`Unknown command: /…`), 모델에 안 감, user 줄 없음 |
| 첫 글자 `!` | **bash 모드로 셸 명령이 실행됨**(`<bash-input>echo …</bash-input>` · `<bash-stdout>`) |
| 첫 글자 `@` | 새지 않음. `@토큰`으로 끝나도 자동완성이 Enter를 먹지 않았다(파일이 있는 폴더에서) |
| 보호: 앞에 공백 한 칸 | `/` · `!` 모두 모델에 프롬프트로 갔다(공백 포함 그대로 기록) |
| 보호: 폭 없는 공백(U+200B) | **Enter가 제출되지 않고 입력 칸에 남았고, 다음 주입이 그 뒤에 이어 붙었다** |
| 입력 칸 비우기 | `C-u`는 한 줄만, `Escape`는 안 비운다. 줄 수만큼 `C-u` · `BSpace`를 반복하면 비워진다 |
| 붙여넣기 → Enter 대기 0 · 0.02 · 0.15초 | 모두 정상(tmux가 명령을 차례로 처리). 0.15초 유지 |
| 바쁠 때 입력 | `queue-operation enqueue` → 진행 중인 턴 안에 `attachment/queued_command`로 전달(새 턴 아님). **UserPromptSubmit hook도 불린다** |
| CC가 적는 `sessions/<pid>.json` `status` | `busy` · `idle` · `shell`(셸 명령 실행 중으로 보임 — 런슈즈에서 봄). `tmux`(`세션:@창.%pane`, 소켓 없음) |

| 대상 | 결과 |

| 없는 세션 | 거부: 살아 있는 CC 프로세스 없음 |

## 만든 것

- `bridge/inject.py` — `resolve`(거부 다섯 가지) → `guarded`(첫 글자) → 방법 C(`paste-buffer -p -r -d`, pane마다 잠금) → 제출 확인(트랜스크립트에 프롬프트 · 대기열로 기록됐나, 6초)
- `POST /api/sessions/{id}/input` — 202(확인됨: 새 턴 / 대기열) · 409(거부, 이유) · 504(제출 확인 안 됨). 모든 시도를 `event(source=bridge, type=input)`로, 들어간 턴에 연결
- `GET /api/sessions` — 붙어 있는 세션, 프로세스 상태 · CC status · pane · 주입 가능 여부
- 확인 페이지 — 세션 목록 · 입력 · `/` 명령 체크 · 결과
- API 끝까지 실측(probe): 여러 줄 → 새 턴, `!` → 보호 붙어 새 턴, 턴 시작 17초 뒤 바쁠 때 입력 → 대기열(같은 턴), 런슈즈 · 정지 세션 → 409, 토큰 없음 → 401. 응답 0.5초(제출 확인 포함)

## 시험에서 찾은 것

- **바쁠 때 입력의 UserPromptSubmit이 진행 중인 턴을 닫을 수 있었다.** 2단계는 "트랜스크립트가 15초 안에 연 같은 프롬프트"만 걸렀다 — 15초 넘은 턴에 대기열 입력이 오면 그 턴을 닫고 새 턴을 열었을 것. 열린 턴이 있으면 새 턴을 열지 않고 hook 이벤트를 `queued`로(`2b26867`). 17초 시점 입력으로 다시 확인
- **폭 없는 공백은 보호가 아니라 함정이었다** — 제출이 안 되고 남은 글이 다음 입력과 합쳐졌다. 그래서 제출 확인을 넣었다. 확인이 안 되면 504로 알리되 **입력 칸을 자동으로 비우지 않는다** — 그 pane에 사람이 쓰던 초안을 지울 수 있다

## 설계와 달랐던 점

- **"보낸 텍스트가 그대로 들어간다"** → 여러 줄은 `<pasted_content>` 태그로 감싸여 모델에 "붙여넣은 글"로 간다(사람이 친 글과 신뢰 맥락이 다를 수 있다). 탭은 공백 4칸
- **첫 글자 `/` `!` `@` 모두 위험할 것** → `@`는 안전, `/`는 명령, `!`는 셸 실행. `!`가 가장 위험하다
- **주입하면 끝** → 제출 확인이 필요하다(안 먹힌 Enter가 다음 입력을 오염)
- **ACTIVE 판정 = 열린 턴** → CC가 직접 적는 `status=busy`가 더 정확하다(턴 판정과 무관하게 즉시)

## 판단 근거

- **보호는 공백 한 칸**: 두 후보 중 실제로 제출되는 것. 모델이 보는 글 앞에 공백 하나가 붙는 대가는 작다
- **`!`는 언제나 막는다**: 셸 실행은 터미널 패널(7단계)의 일 — 주입 경로로 셸이 열리면 승인 정책(5단계)을 우회한다
- **`/`는 명시할 때만**(`command: true`): `/compact` 같은 명령을 일부러 보낼 일은 있다
- **pane 확인은 매번 tmux에 묻는다**(목록의 `injectable`은 미리보기): 목록과 주입 사이에 Ctrl+Z가 있을 수 있다

## 아직 안 한 것 · 남은 미검증

- 런슈즈 · 펫퍼민트 실세션에서 hook이 실제로 오는지(설치 뒤 새 턴 없음) — 위 확인 쿼리
- 사용자 중단 시 Stop hook 미발동(문서 기준)
- Ctrl+Z 뒤 `fg` 복귀 때 입력 버퍼 · 진행 중 API 스트림
- 사람이 그 pane에 초안을 쓰고 있을 때 주입하면 초안 뒤에 붙는다 — FOREMAN이 만든 pane(11단계)에서는 문제가 안 되지만 사람과 같이 쓰는 pane은 주의
- 주입 대상이 지금은 tmux 안의 CC뿐이다 — 런슈즈 · 펫퍼민트는 tmux로 옮긴 뒤(로드맵 0단계 보류분)
