## 2. 옮기면 늘 worktree가 되는 까닭 · 인계에 그 사실 덧붙이기

- **원인**: `spawn_new(worktree=None)`은 "그 프로젝트에 살아 있는 세션이 있으면" worktree로 보낸다. 흐름은 ③ 새 세션을 ④ 옛 세션 끝내기보다 먼저 띄운다 → 그 순간 옛 세션이 늘 살아 있다 → **[새 세션으로 옮기기]는 늘 worktree로 뜬다**. 인계를 쓴 세션은 이것을 모르고 「지금 상태」에 "브랜치 main"이라고 쓴다(11-05 · 11-09 두 번)
- **고침**(README 「나중에 할 일」의 그 줄): 넣는 쪽이 받는 세션의 폴더를 알 때 글 맨 앞에 「이 세션이 뜬 자리」 절을 붙인다 — worktree 이름 · 브랜치, push 안 함, 원본 폴더 일(브리지 재시작 · README 표) 안 함, 저장소 CLAUDE.md의 worktree 절을 따름
  - `handoff.wt_block(cwd)`, `injection(summary_id, target_cwd)` — `inject()`(인계 넣기)와 포먼 첫 글 + 인계 경로 둘 다 받는 폴더를 넘긴다
  - ② 확인 미리보기는 띄우기 전이라 이름을 모른다. 대신 `worktree_next`로 "⑂ 새 세션은 따로 작업(worktree)에서 뜹니다 — 넣을 때 그 사실을 글 맨 앞에 덧붙입니다."를 보인다(`will_worktree` — spawn_new와 같은 판단)
- 원인 자체(옮기기인데 worktree로 뜨는 것)는 그대로 두었다 — 아래 「남은 것」

## 3. 화면에서 "디스패처" 빼기 (사용자 지시)

- 감독실 캐릭터 설명: "디스패처의 얼굴입니다. 세션은 없고, …" → 사용자 글 그대로 "뭘 할지 말하면 계획을 세워줍니다. 어느 프로젝트에서, 새 세션으로 할지 기존 세션에 붙일지, 무엇을 읽어야 하는지를 정해서 보여줍니다. 확인하면 세션이 뜹니다."
- 그 밖에 화면 · 텔레그램 · 거부 사유에 나오던 곳: 노트 칸(접힘 · 지난 디스패치 → 지난 계획 · 빈 노트 · 내리기 확인), 말하기 창 이름 기본값 · 방 풀기 툴팁, 감독실 구역 툴팁(디스패처 자리 → 계획 세우는 자리), 시작할 일 툴팁, 사용량 화면 로그인 만료 띠, 계획 실패 사유 셋(시간 초과 · JSON 없음 · 되묻는 계획), 503 "꺼져 있습니다", 자동 기상 텔레그램 셋, 로그인 만료 텔레그램("~된다" → "~됩니다"도 함께), claude PATH 없음 알림
- 기본 테마(도형) 캐릭터 이름 · 이름표 "디스패처" → "감독" · "감독실", 역할 표시 `foreman` → "감독"(머리말 ⌂ 감독실과 맞춤)
- 기록에는 "기능 · 문서 이름은 디스패처, 기본 테마 캐릭터도 디스패처"(`log/stage14_dispatcher_note_wake_result.md`)만 있었고 "화면엔 안 씀"은 없었다 — `docs/style_guide.md` 「4-1.」에 남겼다
