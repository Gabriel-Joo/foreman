## GIF 크기 — 실측

V2(17초, 890×570): 256색 2.72MB · **128색 2.17MB** · 64색 1.76MB · 32색 1.18MB · 16색 0.78MB / 폭 640: 128색 1.25MB · 64색 1.01MB. WebM 0.26MB.
- 화질: 64색 이하에서 작은 소품 색이 빠진다(초록 상자 → 회색, 서버 랙 불빛). 폭을 줄이면 한글 이름표가 깨진다 → **128색 · 원래 크기**
- 카메라가 자리를 잡은 뒤 찍으면 화면 전체가 바뀌는 프레임이 없어 더 작다: 최종 V1 1.45 · V2 1.08 · V3(1.5배 확대) 3.03 · V4 0.74 · V5(전체 화면) 3.57 · V6(패널 1.5배) 0.46 · V7(패널 2배) 0.18MB — **모두 GIF, WebM은 남기지 않았다**
- 마법학교는 촛불 · 불꽃이 매 프레임 바뀌어 무겁다(같은 7초 방 전체 4.38MB)

## 하면서 찾은 고장

1. Notion에 **GIF를 image/jpeg로** 보내고 있었다(PNG가 아니면 jpeg) → 확장자로(`CTYPES`), `.webm`은 동영상 블록, 워크스페이스 한도(`GET /users/me` `bot.workspace_limits.max_file_upload_size_in_bytes` = 5MB)를 넘으면 보내지 않고 거부
2. 사진 설명에 `[대화]`처럼 `]`가 있으면 사진이 **글 문단으로 조용히** 바뀌었다 — 02 UI 편 사진 둘이 Notion에 글로 올라가 있었다 → 설명 안 대괄호를 받게(규칙 `.*`)
3. 시연 화면에 "HTTP 404"(대본에 없는 대화 API) — 실제 화면에 없는 오류가 영상에 남을 뻔 → 대화 · 활동은 빈 목록
4. 다시 게시가 **자리 순서**로 맞대서 글 앞에 사진을 끼우자 뒤 블록이 모두 밀려 새 블록 → 사람이 미리보기로 바꿔 둔 mermaid가 풀렸다 → **내용으로 짝짓기**(difflib, `b6e016b`). 이번 게시는 고치기 전에 나가서 mermaid 미리보기는 사람이 한 번 더 바꿔야 한다
