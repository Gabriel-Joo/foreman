# 패널 입력이 "제출됐는지 확인하지 못했습니다"로만 떨어진 건 — CC가 다른 화면을 띄워 둔 것 (11-08)

## 증상

- 패널에서 보낸 글이 전부 "제출됐는지 확인하지 못했습니다. 터미널에서 입력 칸을 확인해 주세요"로 떨어졌다. 처음엔 슬래시가 든 글만 막히는 것 같았고, 나중엔 슬래시 없는 글도 안 들어갔다.
- 브리지 로그: `주입 제출 확인 안 됨 5a3b93e0 %8(…자) — 입력 칸에 모름` 이 08:44부터 반복, 응답은 504.

## 원인 (실측)

- 대상 pane `%8`(세션 201, tmux `cc-foreman-2`)에 CC의 `/usage` 설정 화면(`Settings · Status · Config · Usage · Stats` 탭)이 떠 있었다. 누가 띄웠는지는 모른다 — 코드 어디에도 `/usage`를 보내는 곳이 없다. 사용자가 그 터미널에서 직접 친 것으로 보인다(확인 못 함).
- 그 화면엔 입력 줄(`❯`)이 없다. 붙여넣은 글은 모달로 들어가 제출되지 않았다.
- `left_in_box()`는 `❯` 줄을 못 찾으면 `None`(판단 불가)을 돌려준다 → 패널은 "확인하지 못했습니다"만 보였다. 실제로는 "입력 줄이 없는 화면이다"가 맞는 말이었다.
- 같은 시각 다른 pane 4개(`%2` `%7` `%66` 등)는 작업 중에도 `❯` 입력 줄이 보였다 → 입력 줄 유무로 "입력 가능한 화면인지"를 가릴 수 있다.

## 고친 것

- `bridge/inject.py` `prompt_showing()`: 화면에 `❯` 줄이 있는지 본다.
- `deliver()`: 붙여넣기 전에 `prompt_showing()`이 거짓이면 보내지 않고 거부한다 — "CC가 입력 줄 대신 다른 화면(설정 · 사용량 등)을 띄워 두고 있습니다. 그 세션 터미널에서 Esc로 닫아 주세요" (409). 글은 어디에도 들어가지 않는다.
- `tests/test_inject.py`: 모달이 떠 있으면 붙여넣기 호출이 0번임을 확인하는 테스트 추가. `.venv` pytest 13건 통과.
- 브리지 재기동(`systemctl --user restart foreman-bridge`, 승인 대기 0건 확인 후). 새 코드 적용 확인: 같은 pane에 글을 보내 409 거부, pane에는 아무것도 들어가지 않음. 이 거부로 세션 201의 이벤트 목록에 오류 한 건이 남았다(실제 거부 기록).

## 하지 않은 것 · 남은 것

- **`%8`의 모달은 닫지 않았다.** 사용자가 그 터미널에서 직접 입력 중이라 Esc를 대신 보내지 않았다. 사용자가 `cc-foreman-2` 터미널에서 **Esc**를 누르면 입력 줄이 돌아오고 패널 입력이 다시 들어간다.
- 슬래시 · 빈 줄 등 입력 형태 문제가 따로 있었는지는 확인하지 못했다. 이번 원인(모달)으로 전부 설명되는 증상이다.
- 기존 "제출됐는지 확인하지 못했습니다" 문구(화면 판단 불가 경우)는 그대로 둔다.
