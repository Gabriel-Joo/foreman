1. **화면 `bridge/static/js/store.js`**
   - `sendInput`이 202에 `verified: false`와 `check`를 받으면 「보냈습니다. 기록을 확인하는 중입니다.」로 띄운다(작업 중이면 「작업이 끝나면 이어서 전달됩니다.」가 앞에 붙는다). 그다음 `followInput`이 `GET /api/sessions/{id}/input/{check}`를 2, 3, 5, 5, 10, 10초 뒤와 15초 간격 일곱 번(모두 140초) 물어 결과로 바꾼다. 들어갔으면 「보냈습니다.」, 끝내 못 찾았으면 「보냈지만 기록에서 찾지 못했습니다. 대화창에서 입력 칸을 확인해 주세요.」(실패색), 확인 번호가 사라졌으면(404) 「기록 확인 결과를 알 수 없습니다」, 140초를 다 써도 끝나지 않았으면 「기록 확인이 끝나지 않았습니다」. 그 사이 사람이 다른 글을 보내 `lastInput`이 바뀌었으면 새 글의 결과를 덮지 않는다
   - `opanel.js`: 확인 중 글은 보이는 시간이 8초가 아니라 150초(`pending`)
   - 입력 이벤트에 `payload.late`가 있으면 활동 줄을 「주입: (늦게 확인) …」 대신 「늦게 확인: 들어갔습니다: … (N초 뒤)」로 그린다. 못 찾았으면 오류색. 서버 쪽 글에서 「(늦게 확인) 」 앞말을 뺐고(`bridge/api/sessions.py`), 이미 DB에 있는 옛 줄은 화면이 앞말을 떼고 그린다
   - `switchModel`: 693 기록대로 504 + `left_in_box === false` 갈래(이제 오지 않는다)를 없앴다. 202만 「바꿨습니다」이고, 504 + 입력 칸에 명령이 남음은 「제출되지 않았습니다. 입력 칸에 명령이 남아 있으니 …」(고른 모델 표시를 하지 않는다), 504 + 알 수 없음은 전과 같다
2. **넣기 길 넷을 `inject.submitted(res)` 한 곳으로**
   - `bridge/mergeprep.py` `_deliver`: `submitted`로 판정. 끝내 못 찾으면 `_late_failed`가 텔레그램을 바로 한 번(글 해시로 중복 막음, 묶음 없이) 보낸다. 합치기 알림은 받는 세션 번호를 이 함수가 몰라 `session_action` 기록은 못 남겼다(텔레그램과 로그만)
   - `bridge/terminal.py` 셸 결과: `submitted`로 판정. 못 넣은 까닭을 `left`면 「입력 칸에 글이 남아 제출되지 않았다」로 가른다. 끝내 못 찾으면 같은 요청의 결과 줄을 실패(`delivered: false`)로 한 번 더 남기고 화면에 「세션에 전달 못 함」을 보낸다
   - `bridge/promote.py` `_send`, `bridge/handoff.py` 인계 요청(`request_live`): `submitted`로 판정하고 left는 「입력 칸에 글이 남아 제출되지 않았다」로 가른다. unconfirmed면 `prompt_id`가 없지만, 기록이 끝내 안 남으면 뒤의 기다림(`WAIT_S` 600초)이 시간 초과로 실패와 알림을 남긴다. 그래서 이 둘에는 따로 `on_late`를 달지 않았다(기다림이 같은 일을 이미 한다). 대신 알림이 오기까지 최대 10분 걸린다
   - `handoff.resend_reads`: `submitted`로 판정하고 `verified`, `outcome`도 돌려준다. 뒤에 기다림이 없어 `on_late`로 인계 알림(`fail=True`)을 보낸다
3. **`tests/data/screen_words.toml`**: 이 파일은 옛 이름과 새 이름 짝(`[[rename]]`), 코드 예외, 문서 예외, 호버 약속 칸뿐이고 **옛 이름 없이 새로 생긴 말을 적을 칸이 없다**. 693의 여섯 말 중 새 말(「아직 대화가 없습니다.」, 「대화를 불러오지 못했습니다(까닭).」, 「입력 칸에 글이 남아 제출되지 않았습니다」, 첫 글 「…그 세션 대화창에서 Enter를 눌러 주세요.」)은 적을 칸이 없어 적지 않았다(칸을 새로 만들지 않았다). 이번에 실제로 옛 말이 된 둘, 「(늦게 확인) 들어갔습니다」와 「(늦게 확인) 기록에서 찾지 못했습니다」는 `[[rename]]`(범위 「화면과 문서 인용」)에 적었다. 적자마자 시험이 이 옛 말을 인용한 원고 두 곳(`notion/03_session.md`, `portfolio/04_session_panel.md`)을 찾았고 고쳤다. 「주입: (늦게 확인)」은 코드에 그 글자가 이어진 곳이 없어(화면이 「주입:」과 서버 글을 이어 붙였다) 적지 않았다
4. **늦게 다시 보기 120초(`LATE_S`)는 그대로**. 잰 값이 아니라는 것을 `bridge/inject.py` 주석과 이 log에 적는다(아래 「120초」). 「(늦게 확인)」 줄에 걸린 시간을 남기는지 확인했더니 **남기지 않았다**(상태 `waited_s`는 `check_state`와 로그에만 있었다). 이제 `on_late`에 넘기는 찾은 것에 `waited_s`를 붙이고, 입력 이벤트 `payload.waited_s`, 활동 줄 「(N초 뒤)」, 관리자 길 `session_action`의 「늦게 확인: 들어감(N초 뒤)」에 남긴다. 끝내 못 찾았을 때는 `waited_s`가 상한(120.0)이다

## 설계와 달랐던 점, 판단

- 일감은 「입력 이벤트 `payload.late`가 있으면 「늦게 확인:」처럼」이었다. 서버가 글 앞에 「(늦게 확인) 」을 붙여 두었는데 화면이 그 앞에 「주입:」을 또 붙이는 것이 문제였으므로, 앞말을 서버가 아니라 화면이 붙이도록 옮겼다(앞말이 한 곳이 되고, 걸린 시간도 화면이 붙인다)
- 문서로 옮기기와 인계 요청에는 `on_late`를 따로 달지 않았다. 둘 다 곧바로 응답 표지를 기다리는 일이 이어지고 그 기다림이 시간 초과로 실패와 알림을 남긴다. 따로 달면 같은 실패를 두 번 알린다. 대신 알림이 기다림 상한(600초)까지 늦을 수 있다
- 합치기 알림의 `session_action` 기록은 못 남겼다(받는 세션 번호를 `_deliver`가 받지 않는다). 텔레그램, 로그만 있다
