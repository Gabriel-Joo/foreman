# 안내 창도 오래 떠 있으면 알림 (11-14, 세션 foreman-2, 관리자 362 일감)

## 한 일
- `bridge/stallwatch.py`: `judge_dialog`가 안내 창(`notice`, `screen_state`의 `dismiss`)을 `notify=True`로 돌려주고, `ALERT_AFTER`에 `notice`를 결정 창과 같은 2분으로 더했다. 알림 열쇠는 `dialog`와 같은 꼴(`stall:notice:<세션>:<처음 본 때>`)이라 한 번만 간다. 머리글도 고쳤다.
- 알림 글은 결정 창과 갈랐다: 「<창 이름> 안내 창이 떠 있어 세션이 입력을 못 받습니다 — 대화창을 확인해 주세요」(사람에게 세션을 보라는 말은 「대화창」 그대로).
- `tests/test_stallwatch.py`: 판정 시험을 `notify` 참으로 고치고, 알림 시험에 안내 창 장면을 더했다(1분 50초에는 안 가고, 2분 뒤 한 번, 같은 창은 다시 안 가고, 창이 닫히면 화면에서 사라짐). `test_stallwatch*.py` 22개 통과.

## 설계와 달랐던 점
- 없음. 화면 쪽(`render.js` `stallChip`)은 `notify === false`일 때만 「텔레그램으로도 알립니다」를 빼므로 고칠 것이 없었다. 안내 창 툴팁에도 이제 그 말이 붙는데 사실과 맞다.
- 이 기능을 설명하는 docs 절은 `stallwatch.py` 머리글 말고 없었다(`docs/10_office_design.md`에는 안내 창 이야기가 없음).

## 헛경보가 걱정되는 경우 (고치지 않고 적기만)
- 사람이 일부러 연 `/config` · `/model` 창을 2분 넘게 두면 알림이 간다. 사용자가 정한 기준이라 그대로 둔다.
- 알림이 한 번 나간 뒤 같은 창이 계속 열려 있어도 다시 안 간다. 창이 닫혔다 다시 열리면 새 시각이라 한 번 더 간다.
- 브리지를 다시 띄우면 떠 있는 창의 「처음 본 때」가 메모리에서 지워져 한 번 더 갈 수 있다(기존 창 알림과 같다).
