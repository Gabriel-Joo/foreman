# 화면 크기 · 글씨 크기 버튼 (2026-11-08)

사용자: 화면이 전체적으로 너무 작다 — 1920 기준으로 픽셀 화면 · 패널 · 터미널을 키우고, 글씨 크기를 그때그때 맞출 버튼.

## 한 것

- **글씨 크기 [가−] 120% [가+]**(머리말, `js/uiscale.js`): 배율 하나가 옆 패널 안쪽 전체(대화 · 탭 · 버튼 · 라벨 · 입력창 — `.oside-main`에 CSS `zoom`)와 터미널 글씨를 함께 바꾼다. 단계 90 · 100 · 110 · **120(처음)** · 130 · 145 · 160%, 이 브라우저에 기억(`foremanUiScale`)
  - 글씨가 px로 곳곳에 박혀 있어 하나하나 키우지 않고 배율로 걸었다
- **터미널**: 글씨 13 → 17px(배율 120%, 14 × 배율). ttyd가 iframe 안 xterm을 `window.term`으로 내놓아 브라우저에서 바로 바꾸고 resize로 행 · 열을 다시 맞춘다 — ttyd(`-t fontSize=13`)를 다시 띄우지 않는다. 높이 45 → **55dvh**(최대 65)
- **입력창**: 3 → 6줄(최소 6.5em, 끌어서 45dvh까지). 높이 860px 아래 창은 3.6em — 1024×700에서 대화가 몇 줄밖에 안 보였다
- **패널 폭(좁게)** 처음 값 360 → 1920에서 420(창의 30%, 360 ~ 420). 이미 끌어서 정한 폭이 있으면 그것을 쓴다
- **픽셀 화면**: 방 위 여백 2.5 → 1.9칸 · 아래 0.5 → 0.4, 좌우 0.5 → 0.4, 맞춤 여유 0.96 → 0.99(감독실도 줄임). 1920에서 방 폭 1275 → 1360px(약 7%). 방은 화면 **높이**에 걸려 있어 더 키우려면 방을 잘라야 한다 — 방 위 카드는 남는 높이만큼 줄을 줄여 그린다(5 → 3줄)

## 확인

- `tools/screen.py` 세 테마 × 세 크기(1920 · 1366 · 1024) × 현장 · 감독실, 세션 214 패널을 연 채: layoutAudit · nameAudit · propAudit · 페이지 오류 **0건**(두 번 — 작은 창 조정 앞뒤). "고정 안 됨"은 고치기 전과 같은 수(오피스 15 · 마법학교 10 · 현장 13)
- 실제 화면에서 [가+] → 패널 zoom 1.2 → 1.3, 터미널 17 → 18px, [가−]로 되돌아옴, 터미널 높이 594px(1080의 55%)
- JS 45 · 전체 473 통과

## 남은 것

- 1024 너비에서는 머리말이 세 줄로 접힌다([토큰]이 셋째 줄) — 글씨 버튼이 더해져서다. 작은 창은 이번 기준(1920)이 아니라 두었다
- 사용량 페이지(`/usage`) · 클래식 화면에는 글씨 버튼이 걸리지 않는다
