## 12c 포트폴리오 — 변환 모드 · 일감 · 다시 게시 보존(11-06)

사용자 결정: 갈래를 둘로 나누지 않고 한 줄로(앞에 「한눈에」, 뒤에 주제 글), 주제 글마다 머리에 "이 글은 뭘 다루는지" 한 줄, 저장소는 비공개라 링크 없이 커밋 해시만 글자로, mermaid는 코드 블록 그대로(사람이 한 번 미리보기로 바꾼다), 사진은 파일 올리기.

한 일
- `bridge/notion.py` 포트폴리오 모드 — `portfolio/` 글은 저장소 링크(커밋 · 파일 · 상대 링크)를 글자로만, 맨 위 "사본" 안내 상자 없이. 바깥 링크는 그대로. 그림 줄 `![설명](img/x.png)`은 저장소 파일을 Notion 파일 올리기(`/file_uploads` → `/send`)로 올려 image 블록에 붙인다. 묶음 페이지 「포트폴리오」
- **다시 게시를 "지우고 새로"에서 "자리 지키며 갈아 끼우기"(`sync_children`)로** — 같은 자리 · 같은 종류 블록은 내용만 PATCH(블록 id 유지), 종류가 바뀐 것만 그 하나를 바꾸고, 남는 것은 지운다. 맨 앞부터 다르면 통째로
- 서기실 「포트폴리오 쓰기」(`bridge/scribe_room.py` `portfolio`) — 주제는 `config/portfolio.toml`(8개, 순서 = Notion 순서), 창에서 주제마다 [쓰기] · [고쳐 쓰기]. 주제가 다르면 다른 파일이라 동시에 열 수 있고(둘까지) 같은 주제만 막는다(`touches`). 서기 프롬프트: 바깥 독자 · 머리 한 줄 · 틀(문제 → 판단 → 구조 → 겪은 문제 → 숫자 → 한계) · `[t:]` 금지 · 내부 주소 금지 · 고칠 곳은 `portfolio/<slug>*`뿐 · 「한눈에」는 `tools/screen.py`로 직접 사진
- `docs/style_guide.md` 「1.」 표 · 「3.」에 포트폴리오 문서

조사 결과
- **mermaid 미리보기를 API로 정할 수 없다** — code 블록 칸은 `caption` · `language` · `rich_text`뿐이고, 다른 칸을 보내면 "body.code.display should be not present"처럼 거부한다. 그래서 대신 다시 게시가 블록을 지우지 않게 바꿨다: 내용 PATCH는 id를 유지한다(실제 Notion에서 "내용 고친 뒤 같은 블록: True")
- 실제 Notion 시험(시험 페이지 둘, 끝나고 휴지통): 사진 파일 올리기 → image 블록(`file_upload`) 선명하게 보임 · mermaid 코드 블록 · 다시 게시 통계 `kept 2 · updated 2 · replaced 1 · added 1`, 첫 줄 · mermaid 블록 id 그대로
- 한계: 사람이 미리보기로 바꾼 mermaid도 **그 블록의 코드가 바뀌면** 내용 PATCH라 표시 모드는 남지만, 블록 앞에 새 블록이 끼거나 종류가 바뀌어 자리가 밀리면(같은 자리 · 같은 종류가 아니면) 새 블록이 되어 다시 바꿔야 한다
