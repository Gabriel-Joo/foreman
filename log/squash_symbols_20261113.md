## 바꾸는 규칙(`plain` 한 곳)

1. 빈칸을 하나로 모은다
2. em dash(—), 가운뎃점(· 와 가타카나 ・), 화살표(→)를 앞뒤 빈칸째 「, 」로 바꾼다
3. 겹친 쉼표(`, ,` `,,`)를 하나로, 쉼표 앞 빈칸을 뺀다
4. 앞뒤 쉼표와 끝 마침표를 뺀다

`plain_title`은 `타입(범위): 설명`이면 범위를 빼고(`!`는 둔다) 설명에 `plain`을, 아니면 전체에 `plain`을 한다.
일부러 두는 것: en dash(–, 「1–3단계」 같은 범위), 숫자 안 쉼표(「1,000건」), 「…」(자를 때 붙이는 것). 자를 때는 끝의 쉼표를 떼고 「…」를 붙인다.

| 넣은 글 | 나온 글 |
|---|---|
| `A — B · C → D` | `A, B, C, D` |
| `챗봇 검색 색인 · 경험·후기` | `챗봇 검색 색인, 경험, 후기` |
| `A, — B` / `A —, B` / `A — · B` | `A, B` |
| `— 앞 기호, 끝 기호 —` | `앞 기호, 끝 기호` |
| `docs(11_worktree): 6-1 — 합치기 · 제목` | `docs: 6-1, 합치기, 제목` |

## 사람이 넘긴 제목

- 기호 · 범위 표시가 있어도 거부하지 않고 바꿔서 쓴다. 결과 `note`에 「제목의 em dash · 가운뎃점 · 화살표를 쉼표로 바꿨습니다.」와 「제목의 범위 표시 (범위)를 뺐습니다.」를 붙인다(일감 문구에 화살표 · 범위 표시를 더했다. 실제로 바꾸는 것을 모두 말하려고). note 글은 화면 글이라 가운뎃점을 그대로 썼다
- 거부 규칙(여러 줄 · 빈 칸 · `타입:` 없음 · 마침표 끝 · 50자)은 그대로다. 50자는 **바꾼 뒤** 길이로 잰다(「A—B」가 「A, B」로 늘어난다). 바꾸고 나니 설명이 비면(`fix: —`) 「설명이 비어 있습니다」로 거부한다

## 판단 근거

- **`check_title`은 바꾸지 않은 글을 돌려준다.** `handoff.worktree_act` · `mergeprep.approve`가 `check_title_for`의 결과를 그대로 `merge`에 넘기는데, 여기서 바꿔 돌려주면 `merge`가 바뀐 줄 몰라 note를 못 단다. 검사는 바꾼 뒤 모양으로, 실제 바꾸기와 note는 `merge` 한 곳에서 한다. 그래서 `handoff.py` · `mergeprep.py`는 고치지 않았다
- 「— 커밋 N개」 꼬리는 제목에서 뺐다(일감대로). 세션 제목이 없을 때의 「첫 제목 외 N건」은 기호가 아니라 두었다. 커밋 수 말고 「다른 커밋이 더 있다」를 제목에서 알리는 유일한 줄이라서다
- 원래 커밋 목록 제목에도 같은 바꾸기를 했다. 그래서 `git log --grep`으로 원래 제목을 찾을 때 기호가 든 원문 그대로는 안 걸린다. 기호 없는 낱말(예: 「합치기 제목」)로 찾으면 걸린다. 해시와 숨은 ref(337)로 원문은 그대로 볼 수 있다

## 이 방식이 잘 안 맞는 곳

- **타입 낱말이 겹친다**: 세션 제목이 「docs 어긋남 맞추기 셋째」처럼 타입과 같은 낱말로 시작하면 `docs: docs 어긋남 …`. 뜻은 깨지지 않고, 그 낱말을 떼면 「어긋남 맞추기」처럼 무엇의 어긋남인지 흐려질 수 있어 두었다
- **가운뎃점이 「와/과」인 짧은 낱말 묶음**: 「경험·후기」 → 「경험, 후기」. 뜻은 같고 쉼표 나열이 된다. 실제 세션 제목에서 쉼표로 바꿔 뜻이 바뀌는 예는 찾지 못했다
- **화살표가 「A를 B로」였을 때**: 「318 → 코더」 → 「318, 코더」. 방향이 사라진다. 일감 규칙(화살표로 문장을 대신하지 않는다)상 세션 제목을 짓는 쪽이 고칠 몫이라 기계는 쉼표로만 바꿨다. 이렇게 된 제목이 싫으면 승인 때 `title`을 넘기면 된다
