## 시험(`tests/test_notion_footer.py`, 22개)

1. 옛 꼴 갱신 줄이 있는 쪽을 새 코드로 다시 맞춘다(쪽 단위 비교 켬, 가짜 노션). git 글이 바뀐 경우와 글은 같고 지문만 다른 경우 둘 다 「사람이 고침」으로 멈추지 않고, 갱신 줄은 같은 블록에서 새 꼴로 바뀌며 두 줄이 되지 않는다
   - 음성 대조: 옛 꼴 알아보기를 끄면(스크래치 스크립트로 정규식만 바꿔 돌림, 파일은 안 고침) 이 두 시험이 `HumanEdited`로 깨진다
2. 새 꼴 줄도 갱신 줄로 알아보고, 새 꼴로 바뀐 쪽을 다시 맞춰도 멈추지 않는다
3. 본문 문단이 「마지막 갱신」으로 시작해도 갱신 줄로 보지 않는다(「마지막 갱신은 매주 월요일에 한다」, 「마지막 갱신 c10a0ab 뒤로 바뀐 것은 없다」, 「마지막 갱신 — 11월에 했다」 등). 그런 문단이 맨 끝에 있는 쪽은 그 문단을 고치지 않고 뒤에 갱신 줄을 붙인다
   - 지킴은 줄 전체 꼴(해시 자리까지)이다. 맨 끝 문단만 보는 지킴은 `_ensure_footer`에만 있고, `shape_text`, `shape_patch`는 쪽 어디에 있든 꼴이 맞는 문단을 뺀다. 본문에 갱신 줄과 똑같은 꼴의 문단이 있으면 그것도 빠진다(비교에서 양쪽 다 빠지므로 멈춤은 생기지 않는다)
   - 전에는 첫머리 `마지막 갱신 — `만 보아 그것으로 시작하는 본문 문단이 비교에서 빠졌다. 이제는 빠지지 않는다. 그런 문단이 실제 노션에 있는지는 보지 않았다
4. 지문(`content_digest`)은 git 본문과 사진만 본다(갱신 줄은 게시할 때 붙인다). 그래서 이 변경만으로 다시 올라가는 쪽은 0이다. 지문이 같은 쪽은 「바뀌지 않음」으로 Notion에 아무것도 쓰지 않으므로, 옛 꼴 줄은 그 편 글이 다음에 바뀌어 올라갈 때 새 꼴로 바뀐다. 그때까지 노션에는 옛 꼴과 새 꼴이 섞여 보인다
